# Jest Basics — Syntax You Need First

Jest runs tests and checks whether actual results match expected results.

## 1. Import Jest Functions

With ES modules, import the functions used by the test:

```js
import { describe, expect, test } from '@jest/globals';
```

- `describe` groups related tests.
- `test` defines one scenario.
- `expect` checks a result.

## 2. `describe()` — Group Tests

```js
describe('GET /users/:id', () => {
  // Tests for this endpoint go here.
});
```

The first argument is the group name. The second argument is a function containing its tests.

`describe()` is optional, but it keeps test output organized.

## 3. `test()` — Define One Scenario

```js
test('returns 404 when the user does not exist', async () => {
  // Arrange, act, and assert.
});
```

The test name should explain the expected behavior.

`it()` is an alias for `test()`:

```js
it('returns 404 when the user does not exist', async () => {
  // Test logic
});
```

Choose one style and use it consistently.

## 4. `expect()` — Make an Assertion

```js
expect(actualValue).toBe(expectedValue);
```

Example:

```js
expect(response.status).toBe(200);
```

The function after `expect()` is called a **matcher**.

## 5. Essential Matchers

### Exact Primitive Value

```js
expect(response.status).toBe(200);
expect(response.body.name).toBe('Asha');
```

Use `toBe()` for numbers, strings, booleans, `null`, and exact references.

### Complete Object or Array

```js
expect(response.body).toEqual({
  id: '123',
  name: 'Asha'
});
```

Use `toEqual()` to compare object and array contents.

### Part of an Object

```js
expect(response.body).toMatchObject({
  name: 'Asha'
});
```

Use this when the response has extra fields such as `id` and `createdAt`.

### Value Exists

```js
expect(response.body.id).toBeDefined();
```

### Value Is Missing

```js
expect(response.body.password).toBeUndefined();
```

### Array Length

```js
expect(response.body.items).toHaveLength(2);
```

### String Pattern

```js
expect(response.headers['content-type']).toMatch(/json/);
```

### Negation

Add `.not` when something must not be true:

```js
expect(response.body).not.toHaveProperty('password');
```

## 7. Setup and Cleanup Hooks

Import the hooks you need:

```js
import {
  afterAll,
  beforeAll,
  beforeEach,
  describe,
  expect,
  test
} from '@jest/globals';
```

### `beforeAll()`

Runs once before all tests in the file or group:

```js
beforeAll(async () => {
  await connectToTestDatabase();
});
```

### `beforeEach()`

Runs before every test:

```js
beforeEach(async () => {
  await clearTestData();
});
```

### `afterAll()`

Runs once after all tests finish:

```js
afterAll(async () => {
  await disconnectFromTestDatabase();
});
```

## 8. Mocks — Learn This After Basic Tests

A mock is a fake function used instead of a real dependency:

```js
import { jest } from '@jest/globals';

const sendEmail = jest.fn();
```

Tell the mock to succeed:

```js
sendEmail.mockResolvedValue({ accepted: true });
```

Check whether it was called:

```js
expect(sendEmail).toHaveBeenCalledTimes(1);
```

Mocks are useful for external services such as email and payment providers. Do not start with module mocking; first become comfortable testing normal responses.

## Quick Revision

```text
describe → groups tests
test     → defines one scenario
expect   → checks the result
matcher  → describes the expected result
hooks    → prepare and clean test state
mock     → replaces a dependency with a fake
```
