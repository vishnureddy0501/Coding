# Start Here — Express API Testing Concepts

Read this file before looking at complete API tests.

## 1. What Are We Testing?

An Express API receives an HTTP request and returns an HTTP response.

```text
Request                         Response
GET /users/123  → Express API → 200 + user data
```

An API test checks whether the response is correct for a particular request.

For example:

```text
Given: user 123 exists
When:  GET /users/123 is requested
Then:  status is 200 and the correct user is returned
```

## 2. Important HTTP Terms

### Endpoint

An endpoint is an HTTP method and path together.

```text
GET /users
POST /users
GET /users/:id
DELETE /users/:id
```

### HTTP Method

| Method | Typical purpose |
| --- | --- |
| `GET` | Read data |
| `POST` | Create data or start an action |
| `PUT` | Replace a complete resource |
| `PATCH` | Update part of a resource |
| `DELETE` | Remove a resource |

### Request Body

Data sent by the client, usually with `POST`, `PUT`, or `PATCH`:

```json
{
  "name": "Asha",
  "email": "asha@example.com"
}
```

### Path Parameter

A value included in the URL path:

```text
GET /users/123
           └─ user ID
```

For an Express route declared as `/users/:id`, the value is available as `req.params.id`.

### Query Parameter

An optional value after `?` in a URL:

```text
GET /users?page=2&role=admin
```

In Express, these values are available through `req.query`.

### Header

Metadata sent with a request or response. Authentication tokens are commonly sent in a header:

```text
Authorization: Bearer token-value
```

### Status Code

A number describing the result:

| Code | Meaning |
| ---: | --- |
| `200` | Request succeeded |
| `201` | Resource was created |
| `204` | Succeeded with no response body |
| `400` | Request input is invalid |
| `401` | User is not authenticated |
| `403` | User is authenticated but not allowed |
| `404` | Resource was not found |
| `409` | Request conflicts with existing data |
| `500` | Unexpected server error |

### Response Body

The data returned by the API, often JSON:

```json
{
  "id": "123",
  "name": "Asha"
}
```

## 3. The Testing Tools

### Jest

Jest is the test runner. It:

- Finds and executes test files.
- Groups related tests.
- Provides assertions such as `expect()`.
- Provides setup, cleanup, and mocking tools.

### Supertest

Supertest sends HTTP-style requests to an Express application during a test.

```text
Jest runs the test
      ↓
Supertest sends a request
      ↓
Express processes it
      ↓
Jest checks the response
```

## 4. Important Testing Terms

### Test Case

One scenario with one expected behavior:

```text
returns 404 when the user does not exist
```

### Assertion

A statement that checks an expected result:

```js
expect(response.status).toBe(200);
```

The test fails if the actual value is not `200`.

### Side Effect

Something the request changes outside its response, such as:

- Creating a database row
- Sending an email
- Charging a payment
- Publishing an event

A strong test may check both the response and an important side effect.

## 5. Arrange, Act, Assert

Most tests follow three steps:

```js
test('returns an existing user', async () => {
  // Arrange: prepare the data needed by the test.
  const user = await createTestUser();

  // Act: perform the operation being tested.
  const response = await request(app).get(`/users/${user.id}`);

  // Assert: check the result.
  expect(response.status).toBe(200);
  expect(response.body.name).toBe(user.name);
});
```

During an interview, following this structure makes your thinking easy to understand.

## 6. What to Test for One Endpoint

Start with only these cases:

1. Successful request
2. Invalid input
3. Resource not found
4. Missing authentication, if required
5. Insufficient permission, if relevant
6. Important database or external side effect
