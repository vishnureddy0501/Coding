# Bulkhead Pattern — Interview Notes

## What Is It?

The Bulkhead pattern isolates resources so failure in one part of a service does not affect everything else.

The name comes from ships, where separate compartments prevent one leak from sinking the entire ship.

```text
Payment calls → Connection Pool A
Search calls  → Connection Pool B
Email calls   → Connection Pool C
```

If Email Service becomes slow and fills Pool C, payment and search requests can continue using their own pools.

## What Can Be Isolated?

- Thread pools
- Connection pools
- Request queues
- Service instances
- Tenants
- Availability zones

## Benefits

- Limits the impact of a failure
- Protects critical operations
- Prevents one customer or dependency from consuming every resource

## Drawbacks

- More pools and limits must be configured and monitored.
- Capacity can be wasted when one pool is idle while another is full.
- Poor limits may reject valid traffic too early.

## Interview Answer

> The Bulkhead pattern separates resources into isolated pools. If one dependency or workload exhausts its pool, unrelated operations keep working. It improves fault isolation at the cost of additional configuration and potentially lower resource utilization.
