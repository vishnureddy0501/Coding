# Service Discovery Pattern — Interview Notes

## What Is It?

Service Discovery allows services to find each other using a logical name instead of a fixed IP address.

```text
Order Service asks for "payment-service"
                   ↓
          Service Registry or DNS
                   ↓
       Returns a healthy instance address
```

## Why Is It Needed?

Service instances frequently start, stop, scale, and receive new addresses. Hardcoded IP addresses quickly become invalid.

## Common Approaches

- **Client-side discovery:** the client gets available instances and selects one.
- **Server-side discovery:** a load balancer or proxy selects an instance.

Platforms such as Kubernetes commonly provide discovery through Services and DNS.

## Important Details

- Instances must register and deregister correctly.
- Health checks should stop traffic from reaching unhealthy instances.
- Discovery information may be cached, so clients must handle stale addresses.
- Load balancing is commonly used with discovery.

## Interview Answer

> Service Discovery lets services locate healthy instances by logical name rather than hardcoded IP address. A registry, DNS system, load balancer, or platform such as Kubernetes tracks changing service locations.
