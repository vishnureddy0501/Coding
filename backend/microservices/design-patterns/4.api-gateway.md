# API Gateway Pattern — Interview Notes

## What Is It?

An API Gateway is a single entry point placed between clients and backend services.

```text
Web / Mobile Client
         ↓
     API Gateway
      ↙   ↓   ↘
   User Order Payment Services
```

Instead of knowing every service address, the client calls the gateway. The gateway sends each request to the correct service.

## Responsibilities

Authentication and authorization
Rate Limiting
Service Discovery
Load Balancing
Logging
Circuit Breaking
Security Enhancements

## Benefits

- Clients use one stable endpoint.
- Common security and traffic rules are centralized.
- Internal services are hidden from external clients.
- The gateway can combine responses from multiple services.

## Drawbacks

- It can become a bottleneck or single point of failure.
- Too much business logic can turn it into a large monolith.
- It adds another network hop.

Run multiple gateway instances and keep service-specific business logic in the services.

## Interview Answer

> An API Gateway provides one entry point for clients and routes requests to the correct microservices. It can centralize concerns such as authentication, rate limiting, logging, and response aggregation, but it must be highly available and should not contain excessive business logic.
