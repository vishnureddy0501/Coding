# Circuit Breaker Pattern — Interview Notes

## What Is It?

A Circuit Breaker temporarily stops calls to a dependency that is repeatedly failing or responding slowly.

It prevents one failure from spreading through the system.

```text
Order Service → Circuit Breaker → Payment Service
                      │
                      └── Fail fast when payment is unhealthy
```

## States

- **Closed:** calls pass through normally.
- **Open:** calls are blocked and fail immediately.
- **Half-open:** a few test calls are allowed to check whether the dependency recovered.

```text
Closed ── too many failures ──→ Open
  ↑                              │
  └──── successful tests ← Half-open
```

## Why Is It Useful?

- Prevents cascading failures
- Avoids wasting threads and connections
- Gives the failing service time to recover
- Returns failure quickly instead of waiting for repeated timeouts

Circuit breakers should be combined with timeouts. Use fallbacks only when stale or reduced data is safe and useful.

## Interview Answer

> A Circuit Breaker monitors calls to a dependency. After failures cross a threshold, it opens and fails new calls immediately. After a cooldown, it allows test calls in the half-open state and closes again if the dependency has recovered.
