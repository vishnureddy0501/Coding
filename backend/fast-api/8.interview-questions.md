# 8. FastAPI interview revision

## 1. Why choose FastAPI?

It provides validation, serialization, dependency injection and OpenAPI documentation from Python type hints. It is ASGI-based and works well for I/O-heavy APIs. Framework choice should still consider team familiarity and ecosystem needs.

## 2. What happens when a request reaches an endpoint?

The ASGI server receives it, middleware runs, routing selects a path operation, dependencies are resolved, inputs are parsed and validated, the endpoint executes, the response model validates/serializes output, and middleware completes the response.

## 3. FastAPI versus Uvicorn?

FastAPI defines the application. Uvicorn is the ASGI server that runs it and handles network connections.

## 4. What are Starlette and Pydantic?

Starlette supplies underlying ASGI/web features. Pydantic parses and validates data. FastAPI integrates them using type hints.

## 5. Why does invalid input return 422?

The HTTP request is understandable, but its values do not satisfy the declared schema. FastAPI returns structured validation errors before calling the endpoint.

## 6. Why use `response_model`?

It documents, validates and serializes the response and filters fields not present in the public schema. It helps prevent fields such as password hashes from leaking.

## 7. `def` or `async def`?

Use `async def` with awaitable non-blocking libraries. Use `def` with blocking libraries. Blocking code inside an async endpoint can block the event loop. Async improves I/O concurrency, not CPU execution speed.

## 8. What is dependency injection?

An endpoint declares what it needs, such as a database session or current user, and FastAPI resolves and injects it. This reduces duplication and makes testing easier through dependency overrides.

## 9. Dependency versus middleware?

Middleware surrounds requests globally and is useful for logging or request IDs. Dependencies are aware of endpoint requirements and can return injected values, making them suitable for authentication and database sessions.

## 10. How do you manage a database session?

Create a dependency that yields one session per request and closes it afterward. Keep transaction boundaries explicit and avoid holding a transaction while waiting on slow external services.

## 11. How do you organize a large project?

Use routers for HTTP endpoints, Pydantic schemas for API contracts, services for business rules and a database/repository layer for persistence. Keep route handlers thin.

## 12. How do you authenticate requests?

Extract the bearer token through a security dependency, validate it, load the user and inject the user. Then perform separate authorization checks for the requested resource.

## 13. How do you test FastAPI?

Use pytest and `TestClient` for endpoint tests. Override dependencies for controlled users or test databases. Test success, validation, authentication, authorization, missing data, conflicts and side effects.

## 14. Are FastAPI background tasks durable?

No. Small in-process tasks are convenient but can be lost during crashes or restarts. Use a durable queue and worker system for important or long-running jobs.

## 15. How do you improve performance?

Measure first. Check blocking calls, database queries, indexes, connection pools and downstream latency. Add caching or scale workers only after identifying the bottleneck.

## 16. How do you handle startup and shutdown?

Use the application's lifespan context manager to initialize shared resources before requests and release them during shutdown.

## 17. How does FastAPI generate documentation?

It builds an OpenAPI schema from routes, parameters, Pydantic models, dependencies and security declarations. Swagger UI and ReDoc render that schema.

## 18. What belongs in a route handler?

HTTP-specific work: accepting validated input, calling business logic, mapping errors and returning a response. Complex business rules should be framework-independent and testable separately.

## Five-minute final checklist

You should be able to explain without notes:

- FastAPI + Starlette + Pydantic + Uvicorn;
- ASGI and when async helps;
- path, query, header and body inputs;
- request models versus response models;
- `Depends`, including dependencies with `yield`;
- `HTTPException` and key status codes;
- route/service/database separation;
- authentication versus authorization;
- `TestClient` and dependency overrides;
- workers, statelessness, health checks and observability.

## Strong closing answer

“FastAPI lets me declare API contracts with Python type hints and Pydantic, generates OpenAPI documentation, and provides dependency injection for concerns such as authentication and database sessions. I keep routes thin, use async only with non-blocking libraries, validate both requests and responses, test through dependency overrides, and deploy it as a stateless ASGI service with timeouts, monitoring and external durable workers.”
