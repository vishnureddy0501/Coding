# 1. FastAPI fundamentals

## What is FastAPI?

FastAPI is a Python framework for building APIs. It uses Python type hints to perform validation, serialization and API documentation.

Its important building blocks are:

- **FastAPI**: the framework and dependency-injection layer;
- **Starlette**: underlying web/ASGI functionality;
- **Pydantic**: data parsing and validation;
- **Uvicorn**: an ASGI server that runs the application.

FastAPI is mainly responsible for connecting these pieces. You declare a route and add Python types; FastAPI reads those declarations, asks Pydantic to validate data, calls your function and converts its result into an HTTP response.

## Set up and run a project

```text
my-api/
├── app/
│   ├── __init__.py
│   └── main.py
└── tests/
```

Install and run it:

```bash
python -m venv .venv
source .venv/bin/activate
pip install "fastapi[standard]"
fastapi dev app/main.py
```

`fastapi dev` enables development conveniences such as automatic reload. Do not use development reload mode as your production server.

The minimal `app/main.py` is:

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/")
def root():
    return {"message": "Hello"}
```

FastAPI converts the returned dictionary to JSON and sets an appropriate content type. You usually return normal Python values rather than constructing a response manually.

Open these after starting the server:

- `/docs`: interactive Swagger UI;
- `/redoc`: alternative documentation;
- `/openapi.json`: the machine-readable API contract.

## WSGI versus ASGI

WSGI was designed mainly for synchronous Python web applications. ASGI supports asynchronous requests, long-lived connections and WebSockets.

Interview answer: FastAPI is an ASGI framework, so it works naturally with `async`/`await` and can handle many I/O-bound requests efficiently.

The request path is roughly:

```text
HTTP client → Uvicorn → middleware → FastAPI router
            → dependencies → validation → endpoint
            → response validation/serialization → client
```

Understanding this order helps diagnose whether an error came from middleware, validation, a dependency or your endpoint.

## Small working API

```python
from fastapi import FastAPI, HTTPException, Query, status
from pydantic import BaseModel

app = FastAPI(title="Task API")


class TaskCreate(BaseModel):
    title: str
    completed: bool = False


tasks: dict[int, dict] = {}


@app.get("/health")
def health_check():
    return {"status": "ok"}


@app.get("/tasks/{task_id}")
def get_task(task_id: int):
    task = tasks.get(task_id)
    if task is None:
        raise HTTPException(status_code=404, detail="Task not found")
    return task


@app.get("/tasks")
def list_tasks(limit: int = Query(default=10, ge=1, le=100)):
    return list(tasks.values())[:limit]


@app.post("/tasks", status_code=status.HTTP_201_CREATED)
def create_task(body: TaskCreate):
    task_id = len(tasks) + 1
    task = {"id": task_id, **body.model_dump()}
    tasks[task_id] = task
    return task
```

FastAPI understands parameters from their location and type:

- `task_id` appears in the route, so it is a path parameter.
- `limit` is a simple value not in the route, so it is a query parameter.
- `body` is a Pydantic model, so it comes from the JSON request body.

It converts and validates values. `/tasks/abc` fails before your function runs because `task_id` must be an integer.

## How FastAPI decides where input comes from

FastAPI normally follows these rules:

1. A parameter matching `{name}` in the URL is a path parameter.
2. A simple typed value such as `str`, `int` or `bool` is a query parameter.
3. A Pydantic model is a JSON request body.
4. `Header`, `Cookie`, `Form`, `File` and similar helpers explicitly select another location.

Example request:

```http
POST /projects/12/tasks?notify=true
Authorization: Bearer token
Content-Type: application/json

{"title": "Prepare release"}
```

The route could receive it as:

```python
from fastapi import Header


@app.post("/projects/{project_id}/tasks")
def create_project_task(
    project_id: int,
    body: TaskCreate,
    notify: bool = False,
    authorization: str | None = Header(default=None),
):
    return {
        "project_id": project_id,
        "notify": notify,
        "title": body.title,
    }
```

FastAPI also converts query text to the declared type. For example, `?notify=true` becomes the Python boolean `True`.

## Common decorators

```python
@app.get("/items")
@app.post("/items")
@app.put("/items/{item_id}")
@app.patch("/items/{item_id}")
@app.delete("/items/{item_id}")
```

- `PUT` generally replaces a complete resource.
- `PATCH` partially updates it.
- `POST` commonly creates a resource.
- A successful delete often returns `204 No Content`.

The route decorator can also define the public API contract:

```python
@app.post(
    "/tasks",
    response_model=TaskResponse,
    status_code=status.HTTP_201_CREATED,
    tags=["tasks"],
    summary="Create a task",
)
def create_task(body: TaskCreate):
    ...
```

- `response_model` defines the public response shape.
- `status_code` documents and returns the normal success status.
- `tags` groups routes in generated documentation.
- `summary` gives API users a useful operation description.

Return codes should describe the result. Creating a resource normally returns `201`; ordinary reads and updates commonly return `200`; an empty successful deletion can return `204`.

## Request values

```python
from fastapi import Cookie, Header, Path, Query


@app.get("/examples/{item_id}")
def example(
    item_id: int = Path(gt=0),
    search: str | None = Query(default=None, max_length=50),
    user_agent: str | None = Header(default=None),
    session_id: str | None = Cookie(default=None),
):
    return {"item_id": item_id, "search": search}
```

The type describes the value received by the function. `Path`, `Query`, `Header`, and `Cookie` provide FastAPI with the request source, validation rules, and defaults.

Common constraints include `gt`, `ge`, `lt`, `le`, `min_length`, `max_length` and `pattern`.

## Accessing the request and controlling the response

Most endpoints do not need the raw request, but it is available when required:

```python
from fastapi import Request, Response


@app.get("/request-info")
def request_info(request: Request, response: Response):
    response.headers["X-App-Version"] = "1"
    return {"client": request.client.host if request.client else None}
```

Prefer declared parameters over manually reading query strings or JSON. Declared values receive validation and appear in OpenAPI.

FastAPI also provides response classes for special cases such as files, redirects, streams and plain text. Use normal return values for ordinary JSON endpoints.

## Routers for larger applications

```python
from fastapi import APIRouter

router = APIRouter(prefix="/users", tags=["users"])


@router.get("/{user_id}")
def get_user(user_id: int):
    return {"id": user_id}


app.include_router(router)
```

Use routers to separate features. Routes should handle HTTP concerns and delegate business logic to services.

A realistic router module looks like this:

```python
# app/api/routes/users.py
from fastapi import APIRouter

router = APIRouter(prefix="/users", tags=["users"])


@router.get("/{user_id}")
def get_user(user_id: int):
    return {"id": user_id}
```

```python
# app/main.py
from fastapi import FastAPI
from app.api.routes import users

app = FastAPI()
app.include_router(users.router)
```

## Common beginner mistakes

- Writing every endpoint in `main.py` instead of using routers.
- Accepting an untyped `dict` when a request schema is known.
- Returning database objects or secret fields without a response model.
- Using `200` for every outcome.
- Putting database queries and all business rules directly in the route.
- Assuming interactive docs replace proper tests.
