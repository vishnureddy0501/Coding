# 3. Dependencies, errors and middleware

Read the syntax section first. Dependency injection becomes much easier after these few Python and FastAPI expressions are clear.

## Syntax you need first

### 1. A dependency is normally a function

```python
def get_message():
    return "Hello"
```

Calling the function normally looks like this:

```python
message = get_message()
```

With dependency injection, FastAPI calls that function for you.

### 2. Understanding `Depends`

```python
from fastapi import Depends


def get_message():
    return "Hello"


@app.get("/message")
def read_message(message: str = Depends(get_message)):
    return {"message": message}
```

just pass the dependency function like above syntax. fast api takes care of rest.

### 3. Understanding `Annotated`

The modern FastAPI syntax is:

```python
from typing import Annotated
from fastapi import Depends


def get_message():
    return "Hello"


@app.get("/message")
def read_message(
    message: Annotated[str, Depends(get_message)],
):
    return {"message": message}
```

`Annotated` combines a Python type with extra information used by a framework:

```python
Annotated[str, Depends(get_message)]
```

Read it as:

> This value is a string, and FastAPI should obtain it from `get_message`.

These two forms mean the same thing:

```python
# Older/default-value style
message: str = Depends(get_message)

# Modern Annotated style
message: Annotated[str, Depends(get_message)]
```

Prefer `Annotated` in new code.

### 4. Understanding a dependency type alias

You may see this syntax:

```python
CurrentUser = Annotated[dict, Depends(get_current_user)]
```

`CurrentUser` is only a reusable name for the complete annotation. It does not contain a user and does not call the dependency.

```python
@app.get("/me")
def read_me(user: CurrentUser):
    return user
```

This is equivalent to:

```python
@app.get("/me")
def read_me(
    user: Annotated[dict, Depends(get_current_user)],
):
    return user
```

Start with the full form. Create an alias only when you understand it or repeat it often.

### 5. Understanding `Header()`

```python
from fastapi import Header


def read_header(
    authorization: Annotated[str | None, Header()] = None,
):
    return authorization
```

- `authorization` is the Python parameter.
- `str | None` means string or `None`.
- `Header()` tells FastAPI to read an HTTP header.
- `= None` makes the header optional.

Make it required by removing `| None` and `= None`:

```python
authorization: Annotated[str, Header()]
```

FastAPI converts underscores in header parameter names to hyphens. For example, `user_agent` reads the `User-Agent` header.

### 6. Understanding `yield`

A normal dependency returns its value and finishes:

```python
def get_value():
    return "value"
```

A dependency using `yield` provides a value and performs cleanup later:

```python
def get_resource():
    resource = open_resource()
    try:
        yield resource
    finally:
        resource.close()
```

Its lifecycle is:

```text
create resource
      ↓
yield it to the endpoint
      ↓
endpoint finishes or fails
      ↓
run the finally block
      ↓
close resource
```

Use this for something that must be cleaned up, such as a database session, file or external client.

## Dependency injection: the simple meaning

Dependency injection means:

> An endpoint declares what it needs. FastAPI obtains that value and passes it into the endpoint.

The endpoint does not create or find the value itself.

## Complete example: injecting the current user

A dependency is a function or callable that provides something an endpoint needs. FastAPI resolves it and injects its returned value.

Your endpoint does not call the dependency directly. `Depends(...)` tells FastAPI to call it, resolve any sub-dependencies, handle errors and inject its result.

Common uses:

- authenticated user;
- database session;
- authorization checks;
- shared query parameters;
- external service clients.

```python
from typing import Annotated
from fastapi import Depends, Header, HTTPException


def get_current_user(
    authorization: Annotated[str | None, Header()] = None,
) -> dict:
    if authorization != "Bearer valid-token":
        raise HTTPException(status_code=401, detail="Invalid token")
    return {"id": 7, "role": "admin"}


CurrentUser = Annotated[dict, Depends(get_current_user)]


@app.get("/me")
def read_me(user: CurrentUser):
    return user
```

## What FastAPI does step by step

Suppose the client sends:

```http
GET /me
Authorization: Bearer valid-token
```

FastAPI performs this sequence:

```text
1. Match the request to read_me
2. Notice that read_me requires CurrentUser
3. Find Depends(get_current_user) inside CurrentUser
4. Notice that get_current_user requires an Authorization header
5. Read the header and pass it into get_current_user
6. Receive the returned user dictionary
7. Pass that dictionary into read_me as user
8. Return the endpoint response
```

If the dependency raises `HTTPException`, FastAPI stops immediately. `read_me` is not called.

This separation is useful because the endpoint only says what it needs:

```python
def read_me(user: CurrentUser):
```

It does not need to know how headers are read, tokens are checked or users are loaded.

## Dependencies can receive request parameters

A dependency can declare query parameters, path parameters, headers and cookies just like an endpoint.

```python
from fastapi import Query


def get_pagination(
    limit: int = Query(default=20, ge=1, le=100),
    offset: int = Query(default=0, ge=0),
) -> dict:
    return {"limit": limit, "offset": offset}


Pagination = Annotated[dict, Depends(get_pagination)]


@app.get("/users")
def list_users(page: Pagination):
    return {
        "limit": page["limit"],
        "offset": page["offset"],
        "items": [],
    }
```

For `/users?limit=10&offset=20`, FastAPI validates the query values, calls `get_pagination(10, 20)` and injects the returned dictionary as `page`.

The dependency's query parameters also appear automatically in `/docs`.

## Why use dependency injection?

Without dependencies, authentication or shared parameter logic gets copied across endpoints. Dependencies provide:

- reuse without copying code;
- one consistent implementation;
- smaller endpoint functions;
- automatic request validation and documentation;
- easy replacement during tests;
- automatic cleanup for dependencies using `yield`.

Use dependencies for request-related requirements such as authentication, permissions, pagination or request-scoped resources. Do not convert every helper into a dependency. A calculation such as `calculate_total(items)` is ordinary business logic and should normally be called directly.

## Nested dependencies

Dependencies may themselves have dependencies. FastAPI builds and resolves this dependency graph for each request. Repeated dependencies are normally cached once per request.

For example:

```text
endpoint
├── database session
└── active user
    └── current user
        └── bearer token
```

FastAPI resolves the lower dependencies first. If token validation raises an exception, the endpoint never runs.

A small nested-dependency example:

```python
def get_current_user(
    authorization: Annotated[str | None, Header()] = None,
) -> dict:
    if authorization != "Bearer valid-token":
        raise HTTPException(status_code=401, detail="Invalid token")
    return {"id": 1, "active": True}


def get_active_user(
    user: Annotated[dict, Depends(get_current_user)],
) -> dict:
    if not user["active"]:
        raise HTTPException(status_code=403, detail="Inactive user")
    return user


ActiveUser = Annotated[dict, Depends(get_active_user)]


@app.get("/dashboard")
def dashboard(user: ActiveUser):
    return {"user_id": user["id"]}
```

FastAPI first calls `get_current_user`, passes its result to `get_active_user`, and passes the final result to `dashboard`.

## Dependencies that return a value versus checks

Use an injected parameter when the endpoint needs the result:

```python
@router.get("/me")
def get_me(user: CurrentUser):
    return user
```

Use the decorator's `dependencies` list when only the check/side effect matters:

```python
@router.delete("/{item_id}", dependencies=[Depends(require_admin)])
def delete_item(item_id: int):
    ...
```

Dependencies can be applied to one endpoint, an entire router or the whole application.

## Dependency caching

Within one request, FastAPI normally calls the same dependency once and reuses its result. This is useful for a current-user lookup or database session. `Depends(dependency, use_cache=False)` requests a fresh call, but most applications should keep the default.

The cache is only for one HTTP request. A new request resolves the dependency again.

## Synchronous and asynchronous dependencies

A dependency may use `def` or `async def`:

```python
async def get_external_data():
    return await async_client.get_data()
```

FastAPI can mix synchronous and asynchronous endpoints and dependencies. Use `async def` when the library being called is asynchronous and requires `await`. Do not place blocking network or file operations directly inside an async dependency.

## Dependencies with cleanup

```python
def get_db():
    session = create_session()
    try:
        yield session
    finally:
        session.close()
```

Code before `yield` creates the resource. Code after `yield` cleans it up even when request handling fails.

Do not commit blindly inside a generic `get_db` cleanup block. Transaction success belongs to the business operation: commit intentionally after successful writes and roll back when the operation fails.

## Replacing dependencies in tests

Suppose production code uses this dependency:

```python
def get_current_user():
    return find_real_user()
```

A test can replace it:

```python
def fake_current_user():
    return {"id": 99, "name": "Test User"}


app.dependency_overrides[get_current_user] = fake_current_user
```

Endpoints now receive the fake user during the test. Clear the replacement afterward:

```python
app.dependency_overrides.clear()
```

The dictionary contains function objects, which is why neither function has parentheses.

## Error handling

Use `HTTPException` for expected HTTP failures:

```python
raise HTTPException(
    status_code=403,
    detail="You cannot access this project",
)
```

Typical status codes:

- `400`: malformed request or invalid operation;
- `401`: missing or invalid authentication;
- `403`: authenticated but not allowed;
- `404`: resource does not exist;
- `409`: conflict, such as duplicate email;
- `422`: request validation failed;
- `500`: unexpected server error.

Keep domain errors independent from HTTP where practical. A service can raise `DuplicateEmailError`; the API layer translates it to `409`.

## Custom exception handlers

When many routes can raise the same domain exception, register one handler:

```python
from fastapi import Request
from fastapi.responses import JSONResponse


class DuplicateEmailError(Exception):
    pass


@app.exception_handler(DuplicateEmailError)
async def duplicate_email_handler(
    request: Request,
    error: DuplicateEmailError,
):
    return JSONResponse(
        status_code=409,
        content={"detail": "Email already exists"},
    )
```

Syntax breakdown:

- `class DuplicateEmailError(Exception)` creates your own exception type.
- `@app.exception_handler(DuplicateEmailError)` registers the function as the handler for that exception.
- `request` is the current HTTP request.
- `error` is the exception object that was raised.
- `JSONResponse` lets you explicitly choose the status code and JSON content.

This keeps error responses consistent. Log unexpected errors internally, but return a safe generic response instead of stack traces.

## Middleware

Middleware surrounds every request and response:

```python
import time
from fastapi import Request


@app.middleware("http")
async def add_process_time(request: Request, call_next):
    started = time.perf_counter()
    response = await call_next(request)
    elapsed = time.perf_counter() - started
    response.headers["X-Process-Time"] = str(elapsed)
    return response
```

Read the middleware in this order:

1. `@app.middleware("http")` registers middleware for HTTP requests.
2. FastAPI calls it with the current `request` and a `call_next` function.
3. Code before `call_next` runs before the endpoint.
4. `await call_next(request)` continues to the endpoint and waits for its response.
5. Code after it runs while the response is returning.
6. The middleware must return the response.

```text
request
   ↓
middleware code before call_next
   ↓
dependencies and endpoint
   ↓
middleware code after call_next
   ↓
response
```

Use middleware for cross-cutting behavior such as request IDs, logging, metrics and CORS. Use dependencies when endpoint-specific values or authorization are needed.

A middleware must call `call_next(request)` to continue the request chain. It may run logic before and after that call. Be careful not to read and consume request streams unnecessarily.

Useful middleware examples:

- attach or propagate a request ID;
- record duration and status code;
- emit access logs or metrics;
- configure CORS;
- add selected security headers.

Authentication can sometimes be implemented in middleware, but FastAPI dependencies are often easier because they integrate with OpenAPI, can vary by endpoint and inject the user directly.

## CORS

CORS is a browser security policy. It does not authenticate requests.

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://app.example.com"],
    allow_credentials=True,
    allow_methods=["GET", "POST"],
    allow_headers=["Authorization", "Content-Type"],
)
```

Avoid `*` in production when credentials are involved. Explicitly allow trusted origins.

CORS is enforced by browsers. A server-to-server caller is not stopped by CORS, so CORS is not an access-control system. Authentication and authorization remain necessary.

## Request state

Middleware can store request-scoped values such as a correlation ID:

```python
request.state.request_id = request_id
```

Later code can read it from the `Request`. Prefer explicit dependency injection for core business dependencies; use request state for genuinely request-wide metadata.

## Interview comparison

| Feature | Best for |
|---|---|
| Dependency | Authentication, DB sessions, reusable endpoint requirements |
| Middleware | Logic applied around most or all requests |
| Exception handler | Converting a known exception type into an HTTP response |
| Service layer | Business rules independent of HTTP |

## Common mistakes

- Calling `get_db()` or `get_current_user()` manually instead of using `Depends`.
- Using middleware for complex endpoint-specific authorization.
- Returning `401` when the user is authenticated but forbidden; that case is `403`.
- Catching `Exception` in every route and returning `400`.
- Forgetting cleanup after yielding a database session or client.
- Treating CORS as protection against non-browser callers.
