# Lesson 4: Configuration and environment variables

## 1. Configuration changes between environments

Database addresses, external service URLs, and credentials should not be hard-coded into route files.

```python
import os


DATABASE_NAME = os.getenv("DATABASE_NAME", "learning_db")
SERVICE_URL = os.getenv("SERVICE_URL")
```

The second argument to `os.getenv` is a default.

## 2. Required configuration

```python
API_USERNAME = os.getenv("API_USERNAME")

if not API_USERNAME:
    raise RuntimeError("API_USERNAME environment variable is required")
```

Failing during startup is useful when the service cannot work correctly without the value.

## 3. Loading a local `.env`

```python
from dotenv import load_dotenv


load_dotenv()
```

This loads local development values into the process environment. Production systems normally inject environment variables or retrieve secrets through a secret manager.

Never commit real secrets into `.env` files.

## 4. Configuration is not a request value

Read process configuration centrally, not repeatedly inside every route:

```python
# app/config.py
PRODUCT_SERVICE_URL = os.getenv(
    "PRODUCT_SERVICE_URL",
    "https://example.internal",
)
```

```python
# service module
from app.config import PRODUCT_SERVICE_URL
```

## 5. Secrets and ordinary configuration differ

- Ordinary configuration: log level, feature URL, timeout.
- Secret: password, private key, API token.

Do not log secret values. If secrets come from an external manager, handle failures explicitly and cache them only according to the application's security requirements.
