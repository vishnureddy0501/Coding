# Lesson 3: Router composition

## 1. Endpoint router

```python
# app/products/api/v1/product.py
from fastapi import APIRouter


router = APIRouter()


@router.get("/{product_id}", response_model=ProductResponse)
async def api_get_product(store: str, product_id: str):
    return await get_product(store, product_id)
```

This file owns individual product operations.

## 2. Feature router

```python
# app/products/api/v1/router.py
from fastapi import APIRouter

from app.products.api.v1 import product


router = APIRouter(prefix="/api/v1", tags=["Products"])
router.include_router(product.router, prefix="/{store}/products")
```

The feature router adds shared versioning, documentation tags, and the feature path.

## 3. Application registration

```python
# app/main.py
from app.products.api.v1.router import router as products_v1_router


app.include_router(products_v1_router)
```

The final URL is the sum of all prefixes and the endpoint path:

```text
/api/v1 + /{store}/products + /{product_id}
= /api/v1/{store}/products/{product_id}
```

## 4. Route order can matter

Static paths should not be accidentally consumed as dynamic identifiers:

```python
@router.get("/summary")
async def summary(): ...


@router.get("/{product_id}")
async def get_one(product_id: str): ...
```

Keeping the static route first makes the intended match clear.

## 5. Keep versioning at the router boundary
 
`/api/v1` belongs in a shared router prefix. This prevents every endpoint from repeating it and allows a future `v2` router to coexist.

## Request trace

For `GET /api/v1/store-a/products/p-10`:

1. the application finds the included products router;
2. the feature router matches `store-a`;
3. the endpoint matches `p-10`;
4. FastAPI calls `api_get_product(store="store-a", product_id="p-10")`.
