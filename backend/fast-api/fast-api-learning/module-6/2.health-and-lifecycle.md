# Lesson 2: Health checks and graceful lifecycle

## 1. A basic status endpoint

```python
import time
from datetime import datetime, timezone

from fastapi import APIRouter


router = APIRouter()
started_at = time.time()


@router.get("/")
def service_status():
    return {
        "status": "ok",
        "uptime_seconds": int(time.time() - started_at),
        "timestamp": datetime.now(timezone.utc).isoformat(),
    }
```

A status endpoint should be quick and predictable.

## 2. Liveness and readiness answer different questions

- Liveness: Is the process running, or should it be restarted?
- Readiness: Is it ready to receive traffic?

A database outage may make a service temporarily unready without meaning the process must be killed immediately.

## 3. Avoid expensive health checks

A frequently called health endpoint should not perform a large query or initialize resources. If readiness checks dependencies, use small bounded operations and timeouts.

## 4. Startup policy affects readiness

If a required client cannot initialize, fail startup or report not-ready. If the dependency is optional and the application can still serve useful requests, log the failure and continue deliberately.

## 5. Shutdown should release owned resources

Use lifespan shutdown for clients, tasks, and resources owned by the process. Background loops should support cancellation or a clear stop condition.

Do not close a shared client merely because one request finishes.
