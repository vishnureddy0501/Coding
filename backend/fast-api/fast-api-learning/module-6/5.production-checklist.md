# Module 6 production checklist

Use this checklist when reading or building a FastAPI service.

## Application

- The Uvicorn import path points to the correct `FastAPI` object.
- The container listens on `0.0.0.0` and the expected port.
- Required environment variables fail clearly during startup.
- Secrets are not committed or logged.

## Lifecycle

- Process-wide clients are initialized or warmed deliberately.
- Optional and required startup failures have different policies.
- Background task references are retained.
- Shutdown releases resources owned by the process.

## HTTP and security

- Public paths are explicitly allow-listed.
- Authentication failures use suitable status codes.
- Tenant scope is included in data access.
- CORS is not treated as authentication.
- Error responses do not expose internal exception details.

## Data and performance

- Page sizes are bounded.
- Search and sort input is escaped or allow-listed.
- Frequent query shapes have deliberate indexes.
- Blocking SDK calls do not freeze the event loop.
- Shared process caches have correct keys, expiry, and locking.

## Resilience and visibility

- External calls have sensible timeouts.
- Retries are bounded and safe for the operation.
- Logs include operation context without sensitive data.
- Exceptions retain tracebacks in server logs.
- Health endpoints are quick and have clear liveness/readiness meaning.
- Trace identifiers allow a request to be followed across components.

## Final exercise

Take the products API from earlier modules and describe its complete production flow:

```text
container starts
→ lifespan initializes resources
→ health endpoint reports readiness
→ middleware verifies a request
→ router validates input
→ service queries tenant-scoped data
→ logs and spans record the operation
→ response model creates the public response
→ shutdown cleans up owned resources
```

For each arrow, name the file or layer responsible for it.
