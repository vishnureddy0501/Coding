# Lesson 1: ASGI, Uvicorn, and containers

## 1. FastAPI is an ASGI application

```python
# app/main.py
from fastapi import FastAPI


app = FastAPI()
```

`app` is the ASGI application object. Uvicorn is the server process that loads it and communicates over HTTP.

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Read `app.main:app` as:

```text
app package → main.py module → app variable
```

## 2. Why bind to `0.0.0.0`?

Inside a container, `127.0.0.1` accepts connections only from that container's loopback interface. `0.0.0.0` lets the container platform route traffic to the server.

## 3. Minimal Dockerfile shape

```dockerfile
FROM python:3.11-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

EXPOSE 8000

CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

- `FROM` selects the runtime base image.
- `WORKDIR` sets the directory for following commands.
- copying requirements first allows dependency layers to be reused when only source code changes;
- `CMD` starts the service.

`EXPOSE` documents the port; the deployment platform still has to publish or route it.

## 4. One process does not share memory with another

In-memory dictionaries, locks, and caches belong to one process. With multiple worker processes, each worker has its own copy.

Do not rely on process memory for durable data or globally consistent coordination.

## 5. Instrumentation may wrap the server command

Production commands sometimes start Uvicorn through an observability tool. The application import path and host/port rules remain the same.
