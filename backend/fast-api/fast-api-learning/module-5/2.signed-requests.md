# Lesson 2: Signed internal requests

A signed request proves that a holder of the private key created a message. The server verifies it using the public key.

## 1. Required headers

```python
service = request.headers.get("X-Service")
timestamp = request.headers.get("X-Timestamp")
signature = request.headers.get("X-Signature")

if not service or not timestamp or not signature:
    raise HTTPException(status_code=401, detail="Missing auth headers")
```

Reject incomplete authentication data before doing expensive work.

## 2. Freshness prevents replay

An attacker might capture a valid signed request and send it again. Include a timestamp and accept only a small time window:

```python
MAX_SKEW = 30

if abs(time.time() - int(timestamp)) > MAX_SKEW:
    raise HTTPException(status_code=401, detail="Request expired")
```

This requires reasonably synchronized clocks. Parse malformed timestamps safely so they become authentication failures rather than accidental server errors.

## 3. Sign a canonical message

```python
raw_body = await request.body()
body_text = raw_body.decode() if raw_body else ""

message = (
    f"{request.method}:{request.url.path}:"
    f"{timestamp}:{body_text}"
)
```

Both sender and verifier must construct exactly the same bytes. Including the method, path, timestamp, and body prevents the signature from being reused for a changed request.

In a larger design, query-string canonicalization must also be specified if query values affect the protected operation.

## 4. Verify with the public key

```python
try:
    public_key.verify(
        base64.b64decode(signature),
        message.encode(),
        padding.PSS(
            mgf=padding.MGF1(hashes.SHA256()),
            salt_length=padding.PSS.MAX_LENGTH,
        ),
        hashes.SHA256(),
    )
except InvalidSignature:
    raise HTTPException(status_code=401, detail="Invalid signature")
```

The server does not decrypt the signature. It verifies that the signature matches the message and public key.

## 5. Private and public keys

- The caller protects the private key and signs requests.
- The receiving service stores or retrieves the public key and verifies requests.
- The private key must never be placed in frontend code or sent with a request.
