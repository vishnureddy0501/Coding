# Lesson 3: Authentication middleware

Middleware is useful when most routes share the same authentication rule.

## 1. Basic structure

```python
class AuthMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request: Request, call_next):
        path = request.url.path

        if path in PUBLIC_PATHS:
            return await call_next(request)

        try:
            await verify_internal_request(request)
        except HTTPException as exc:
            return JSONResponse(
                status_code=exc.status_code,
                content={"detail": exc.detail},
            )

        return await call_next(request)
```

## 2. Why return `JSONResponse` here?

Inside ordinary route and service code, raise `HTTPException`. This middleware catches the verifier's exception and must return an HTTP response to stop the chain.

If verification succeeds, the final `call_next` lets the request reach the route.

## 3. Branch order matters

Cheap, explicit bypass checks should happen before expensive cryptographic or secret-manager work:

```text
public path? → continue
documentation path? → continue
trusted proxy rule? → continue
otherwise → verify signature
```

Every bypass expands the trust boundary. Keep it deliberate and documented.

## 4. Request bodies in middleware

Signature verification may read `await request.body()`. Body handling must be compatible with downstream request processing. Framework request objects commonly cache the body, but middleware behavior should be verified when changing framework versions or middleware styles.

## 5. Middleware authentication is broad

Middleware can establish that a request is trusted. Fine-grained authorization—such as “may this service delete this tenant's product?”—still belongs closer to the operation.
