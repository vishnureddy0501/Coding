# Lesson 4: CORS, secrets, and safe errors

## 1. CORS is not authentication

CORS tells browsers which cross-origin frontend requests may read responses. It does not stop scripts, servers, or command-line clients from sending requests.

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://app.example.com"],
    allow_methods=["GET", "POST", "PATCH", "DELETE"],
    allow_headers=["Content-Type", "Authorization"],
)
```

Use the narrowest origins, methods, and headers that the frontend requires.

## 2. Keep secrets outside source code

```python
token = os.getenv("SERVICE_TOKEN")
```

Production secrets may come from a secret manager. Do not commit them, put them in URLs, or log them.

## 3. Avoid leaking verification details

Clients need a useful status, not cryptographic internals:

```python
raise HTTPException(status_code=401, detail="Invalid signature")
```

Detailed exceptions belong in controlled server logs.

## 4. Validate and limit untrusted input

Security also includes resource protection:

```python
limit: int = Query(20, ge=1, le=100)
```

Bound page sizes, validate enum-like values, escape search expressions, and allow-list sort fields.

## 5. Avoid dynamic query construction from raw input

Use driver parameters where supported. For dynamic field names or sort values, map user choices through a fixed allow-list.

## 6. Log context, not credentials

Useful context includes operation, tenant, safe identifiers, duration, and outcome. Never log passwords, tokens, private keys, full authentication headers, or sensitive request bodies.
