# Lesson 2: HTTP, the first application, and routes

FastAPI connects an HTTP request to a Python callable. Understanding the HTTP pieces prevents route code from feeling magical.

## 1. The HTTP exchange

A simplified request is:

```http
GET /tasks/12?include_notes=true HTTP/1.1
Host: example.com
Accept: application/json
```

It contains:

- method: `GET`;
- path: `/tasks/12`;
- query string: `include_notes=true`;
- headers: metadata such as `Accept`;
- optional body: commonly JSON for create/update requests.

A simplified response is:

```http
HTTP/1.1 200 OK
Content-Type: application/json

{"id":12,"title":"Learn FastAPI"}
```

It contains a status code, headers, and possibly a body. FastAPI converts Python-compatible data into a JSON response, but your route must decide what data and outcome are correct.

## 2. Minimal application

Put this in `app/main.py`:

```python
from fastapi import FastAPI

app = FastAPI(
    title="Task API",
    description="A small API for learning FastAPI fundamentals",
    version="1.0.0",
)


@app.get("/")
def root():
    return {"message": "Hello FastAPI"}
```

Run it from the project root:

```bash
uv run fastapi dev app/main.py
```

`FastAPI()` creates the application object. The development server imports the module, finds `app`, and uses it as the ASGI application. You do not need ASGI internals yet.

Try all four views:

```bash
curl -i http://127.0.0.1:8000/
```

- `/` shows the actual endpoint result;
- `/docs` provides interactive Swagger UI;
- `/redoc` provides reference documentation;
- `/openapi.json` is the machine-readable API contract used by the documentation.

## 3. Route identity

A route is identified by both method and path:

```python
@app.get("/tasks")
def list_tasks():
    return []


@app.post("/tasks")
def create_task():
    return {"id": 1}
```

These do not conflict. `GET /tasks` and `POST /tasks` are different operations.

Common resource-oriented conventions:

| Intent | Method and path | Typical success |
|---|---|---|
| list tasks | `GET /tasks` | `200 OK` |
| get one | `GET /tasks/{task_id}` | `200 OK` |
| create | `POST /tasks` | `201 Created` |
| replace all editable fields | `PUT /tasks/{task_id}` | `200 OK` or `204 No Content` |
| update selected fields | `PATCH /tasks/{task_id}` | `200 OK` |
| delete | `DELETE /tasks/{task_id}` | `204 No Content` |

HTTP does not implement CRUD for you. These conventions communicate intent to clients.

## 4. How route registration works

```python
@app.get("/tasks", tags=["tasks"], summary="List tasks")
def list_tasks():
    return []
```

When the module is imported, the decorator registers:

- method `GET`;
- path `/tasks`;
- function `list_tasks`;
- documentation metadata.

Later, when a matching request arrives, FastAPI calls the function. The Python function name is primarily for your code and generated operation IDs; clients use the method and URL.

## 5. Fixed and dynamic paths

```python
@app.get("/users/me")
def current_user():
    return {"id": "current"}


@app.get("/users/{user_id}")
def get_user(user_id: str):
    return {"id": user_id}
```

Declare `/users/me` before `/users/{user_id}`. Routes are matched in declaration order, and the dynamic route could otherwise treat `me` as an ID.

Two routes with the same method and equivalent dynamic shape are ambiguous and should not be defined:

```python
@app.get("/users/{user_id}")
def by_id(user_id: str): ...

@app.get("/users/{username}")
def by_username(username: str): ...
```

Changing the placeholder name does not change the URL shape.

## 6. JSON-compatible return values

FastAPI can serialize common values:

```python
return {"name": "Vishnu"}       # JSON object
return ["Python", "FastAPI"]    # JSON array
return "hello"                   # JSON string
return 10                        # JSON number
return True                      # JSON boolean
return None                      # JSON null
```

Pydantic models are also supported. Objects such as an arbitrary class instance are not automatically a stable public contract; response models will solve that in Lesson 4.

## 7. Status codes that matter now

```python
from fastapi import status


@app.post("/tasks", status_code=status.HTTP_201_CREATED)
def create_task():
    return {"id": 1, "title": "Learn FastAPI"}
```

`status_code` belongs to the decorator because it describes the normal HTTP response. The named constant equals `201` but is easier to read.

Learn these first:

- `200 OK`: successful read or update with a response body;
- `201 Created`: a resource was created;
- `204 No Content`: success with no response body;
- `400 Bad Request`: request is invalid for a business reason not covered by structural validation;
- `404 Not Found`: requested resource does not exist;
- `409 Conflict`: request conflicts with current state, such as a duplicate unique value;
- `422 Unprocessable Content`: FastAPI understood the request but input validation failed;
- `500 Internal Server Error`: the application failed; do not intentionally use it for normal client mistakes.

Do not memorize every HTTP status code yet.

## 8. Expected errors with `HTTPException`

```python
from fastapi import FastAPI, HTTPException, status

tasks = {1: {"id": 1, "title": "Learn FastAPI"}}


@app.get("/tasks/{task_id}")
def get_task(task_id: int):
    task = tasks.get(task_id)
    if task is None:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail="Task not found",
        )
    return task
```

`raise` matters: execution stops. This produces a response similar to:

```http
HTTP/1.1 404 Not Found
Content-Type: application/json

{"detail":"Task not found"}
```

Use `HTTPException` for expected HTTP failures. Unexpected programming errors should surface as server errors and be fixed, not disguised as `200 OK`.

## 9. A true `204 No Content` response

```python
from fastapi import Response, status


@app.delete("/tasks/{task_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_task(task_id: int) -> Response:
    # delete or raise 404
    return Response(status_code=status.HTTP_204_NO_CONTENT)
```

A `204` response must not contain a body. Do not return a message such as `{"deleted": true}` with `204`; use `200` if you want a response body.

## 10. `def` versus `async def`

Both are valid FastAPI route forms:

```python
@app.get("/sync")
def sync_route():
    return {"mode": "sync"}


@app.get("/async")
async def async_route():
    return {"mode": "async"}
```

Use ordinary `def` throughout this module. Writing `async def` without understanding whether called libraries are blocking does not automatically make an application faster. Async behavior belongs in the concurrency module.

## 11. Development versus production command

```bash
# development: watches files and reloads
uv run fastapi dev app/main.py

# production-style server command, without development reload
uv run fastapi run app/main.py
```

The second command is useful context, not a complete production deployment strategy.

## Common mistakes

- Returning `200` for missing resources instead of raising `404`.
- Sending a body with `204`.
- Declaring dynamic routes before overlapping fixed routes.
- Assuming `async def` is always superior.
- Catching every exception and returning success-shaped error dictionaries.
