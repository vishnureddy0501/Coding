# Lesson 2: First application and routes

## What FastAPI does

FastAPI connects an HTTP request to a Python function.

```text
client request
      ↓
FastAPI finds the matching route
      ↓
FastAPI validates declared inputs
      ↓
your function runs
      ↓
FastAPI converts the result to a response
```

## Minimal application

Create `app/main.py`:

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/")
def root():
    return {"message": "Hello FastAPI"}
```

Run it from the project directory:

```bash
uv run fastapi dev app/main.py
```

Open:

- `http://127.0.0.1:8000/`
- `http://127.0.0.1:8000/docs`
- `http://127.0.0.1:8000/openapi.json`

## Understanding `app = FastAPI()`

```python
app = FastAPI()
```

- `FastAPI` is a class.
- `FastAPI()` creates an application object.
- `app` stores that object.

The server imports this object and uses it to process requests.

You can provide API metadata:

```python
app = FastAPI(
    title="Task API",
    description="API used to learn FastAPI",
    version="1.0.0",
)
```

This information appears in the generated documentation.

## Understanding a route decorator

```python
@app.get("/")
def root():
    return {"message": "Hello FastAPI"}
```

- `get` is the HTTP method.
- `/` is the URL path.
- `root` is the path-operation function.
- The returned dictionary becomes JSON.

FastAPI calls `root`; you do not call it yourself for an HTTP request.

## Common HTTP methods

```python
@app.get("/tasks")
def list_tasks():
    ...


@app.post("/tasks")
def create_task():
    ...


@app.put("/tasks/{task_id}")
def replace_task(task_id: int):
    ...


@app.patch("/tasks/{task_id}")
def update_task(task_id: int):
    ...


@app.delete("/tasks/{task_id}")
def delete_task(task_id: int):
    ...
```

- `GET`: read data;
- `POST`: create something;
- `PUT`: replace a complete resource;
- `PATCH`: update part of a resource;
- `DELETE`: remove a resource.

These are conventions, but following them makes an API predictable.

## Route configuration

```python
from fastapi import status


@app.post(
    "/tasks",
    status_code=status.HTTP_201_CREATED,
    tags=["tasks"],
    summary="Create a task",
)
def create_task():
    return {"id": 1, "title": "Learn FastAPI"}
```

- `status_code` sets and documents the normal success status.
- `tags` groups endpoints in `/docs`.
- `summary` describes the operation.
- `status.HTTP_201_CREATED` is easier to understand than writing `201` directly.

## Returning data

FastAPI can normally serialize these values to JSON:

```python
return {"name": "Vishnu"}       # JSON object
return ["Python", "FastAPI"]    # JSON array
return "hello"                   # JSON string
return 10                        # JSON number
return True                      # JSON boolean
return None                      # JSON null
```

Pydantic models can also be returned and will be serialized.

## Route order can matter

Consider:

```python
@app.get("/users/me")
def current_user():
    return {"id": "current"}


@app.get("/users/{user_id}")
def get_user(user_id: str):
    return {"id": user_id}
```

Declare fixed paths such as `/users/me` before dynamic paths such as `/users/{user_id}`. Otherwise, `me` may be treated as a `user_id`.

## Development versus production command

Development:

```bash
uv run fastapi dev app/main.py
```

It reloads when source code changes.

Basic production-style execution:

```bash
uv run fastapi run app/main.py
```

Do not use auto-reload in production.

## Why documentation is automatic

FastAPI creates an OpenAPI schema from:

- routes and HTTP methods;
- parameters and their types;
- Pydantic models;
- response models;
- status codes;
- security declarations.

Swagger UI at `/docs` reads that schema and creates an interactive interface.

## Common mistakes

- Forgetting to create `app = FastAPI()`.
- Running the command from a directory where `app/main.py` cannot be found.
- Using the wrong HTTP method.
- Calling the endpoint function manually to test HTTP behavior.
- Returning values that cannot be converted to JSON.
- Assuming `/docs` replaces automated tests.
