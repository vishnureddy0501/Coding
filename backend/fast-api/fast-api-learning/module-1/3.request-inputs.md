# Lesson 3: Request inputs

FastAPI decides where a value comes from by looking at your route, parameter type and FastAPI helpers.

## The main rules

1. A name appearing in `{}` in the route is a path parameter.
2. A simple typed value not in the route is normally a query parameter.
3. A Pydantic model is normally read from the JSON request body.
4. `Header`, `Cookie`, `Form` and `File` explicitly choose another source.

## Path parameters

```python
@app.get("/tasks/{task_id}")
def get_task(task_id: int):
    return {"task_id": task_id}
```

Request:

```http
GET /tasks/10
```

FastAPI converts `"10"` from the URL into integer `10`.

This request fails validation:

```http
GET /tasks/abc
```

The function is not called because `abc` cannot become an integer.

## Path validation

```python
from typing import Annotated
from fastapi import Path


@app.get("/tasks/{task_id}")
def get_task(
    task_id: Annotated[int, Path(gt=0)],
):
    return {"task_id": task_id}
```

`gt=0` means greater than zero.

Common numeric constraints:

- `gt`: greater than;
- `ge`: greater than or equal;
- `lt`: less than;
- `le`: less than or equal.

## Query parameters

```python
@app.get("/tasks")
def list_tasks(limit: int = 20, completed: bool | None = None):
    return {"limit": limit, "completed": completed}
```

Request:

```http
GET /tasks?limit=10&completed=true
```

- `limit` becomes integer `10`.
- `completed` becomes boolean `True`.

Both parameters are optional because they have default values.

## Required query parameters

```python
@app.get("/search")
def search(q: str):
    return {"query": q}
```

Because `q` has no default, it is required:

```http
GET /search?q=fastapi
```

## Query validation

```python
from typing import Annotated
from fastapi import Query


@app.get("/search")
def search(
    q: Annotated[str, Query(min_length=2, max_length=50)],
    limit: Annotated[int, Query(ge=1, le=100)] = 20,
):
    return {"query": q, "limit": limit}
```

Read this expression as:

```python
Annotated[int, Query(ge=1, le=100)]
```

> The value is an integer, comes from the query string, and must be between 1 and 100.

## Request body

```python
from pydantic import BaseModel


class TaskCreate(BaseModel):
    title: str
    completed: bool = False


@app.post("/tasks")
def create_task(body: TaskCreate):
    return body
```

Request:

```http
POST /tasks
Content-Type: application/json

{
  "title": "Learn FastAPI"
}
```

FastAPI asks Pydantic to create and validate `TaskCreate`. Inside the function, `body` is a model object:

```python
body.title
body.completed
body.model_dump()
```

It is not a plain dictionary.

## Combining inputs

```python
@app.put("/projects/{project_id}/tasks/{task_id}")
def update_task(
    project_id: int,
    task_id: int,
    body: TaskCreate,
    notify: bool = False,
):
    return {
        "project_id": project_id,
        "task_id": task_id,
        "notify": notify,
        "task": body,
    }
```

Example request:

```http
PUT /projects/2/tasks/10?notify=true
Content-Type: application/json

{"title": "Prepare release"}
```

FastAPI identifies each value automatically:

- `project_id`: path;
- `task_id`: path;
- `body`: JSON body because it is a Pydantic model;
- `notify`: query parameter.

## Headers

```python
from typing import Annotated
from fastapi import Header


@app.get("/request-info")
def request_info(
    user_agent: Annotated[str | None, Header()] = None,
):
    return {"user_agent": user_agent}
```

FastAPI maps `user_agent` to the `User-Agent` HTTP header.

Required header:

```python
x_api_key: Annotated[str, Header()]
```

Do not use the presence of a header alone as authentication; its value must be verified.

## Accessing the complete request

```python
from fastapi import Request


@app.get("/client")
def client_info(request: Request):
    return {
        "url": str(request.url),
        "method": request.method,
    }
```

Use declared parameters when possible because they receive validation and documentation. Use `Request` only when you need lower-level request information.

## Validation failure

FastAPI validates input before calling your function.

```text
request
   ↓
path/query/header/body validation
   ↓ invalid
422 response; endpoint does not run
```

`422` means the request structure was understood, but its values did not satisfy the declared rules.

## Common mistakes

- Assuming all function parameters come from JSON.
- Forgetting that a simple parameter is normally a query parameter.
- Declaring an optional type without providing a default.
- Reading JSON manually when a Pydantic model can describe it.
- Using strings for IDs and numbers when a stronger type is available.
- Treating CORS headers or arbitrary custom headers as authentication.
