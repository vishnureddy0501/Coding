# Lesson 1: Python syntax required for FastAPI

FastAPI uses normal Python syntax. Learn these concepts first so framework code does not look mysterious.

## 1. Variables and basic types

```python
name = "Vishnu"          # str
age = 25                 # int
price = 99.5             # float
is_active = True         # bool
middle_name = None       # no value
```

Common collections:

```python
skills = ["Python", "FastAPI"]
user = {"name": "Vishnu", "age": 25}
coordinates = (10, 20)
unique_roles = {"admin", "editor"}
```

- `list`: ordered and changeable collection;
- `dict`: key-value collection;
- `tuple`: ordered collection usually treated as fixed;
- `set`: collection of unique values.

JSON objects become Python dictionaries. JSON arrays become Python lists.

## 2. Type annotations

```python
name: str = "Vishnu"
age: int = 25
skills: list[str] = ["Python", "FastAPI"]
user: dict[str, str] = {"name": "Vishnu"}
```

The part after `:` describes the expected type.

Python does not normally enforce annotations at runtime:

```python
age: int = "twenty-five"  # Python still allows this
```

Type annotations help editors and type checkers. FastAPI and Pydantic read them to perform runtime validation.

## 3. Optional and union types

```python
nickname: str | None = None
identifier: int | str
```

- `str | None` means a string or no value.
- `int | str` means an integer or a string.

This field is required but may contain `None`:

```python
nickname: str | None
```

This field is optional because it has a default:

```python
nickname: str | None = None
```

Type and default are different ideas.

## 4. Functions

```python
def greet(name: str) -> str:
    return f"Hello, {name}"
```

Breakdown:

- `def` defines a function;
- `greet` is its name;
- `name: str` is a typed parameter;
- `-> str` describes the return type;
- `return` sends a value back to the caller.

Calling it:

```python
message = greet("Vishnu")
```

Function reference versus function call:

```python
greet       # the function itself
greet()     # call it now; this call is missing the required argument
```

This distinction becomes important with FastAPI dependencies.

## 5. Default and keyword arguments

```python
def list_users(limit: int = 20, offset: int = 0):
    return {"limit": limit, "offset": offset}
```

Calls:

```python
list_users()                    # limit=20, offset=0
list_users(10)                  # limit=10, offset=0
list_users(limit=10, offset=5)  # keyword arguments
```

FastAPI uses function parameters to understand endpoint inputs.

## 6. Classes and objects

```python
class User:
    def __init__(self, name: str, age: int):
        self.name = name
        self.age = age


user = User(name="Vishnu", age=25)
print(user.name)
```

- A class is a blueprint.
- An object is an instance of that class.
- `self` refers to the current object.
- `__init__` runs when the object is created.

Pydantic's `BaseModel` handles much of this construction and validation for you.

## 7. Inheritance

```python
class AdminUser(User):
    pass
```

`AdminUser` inherits behavior from `User`.

Pydantic models use inheritance:

```python
from pydantic import BaseModel


class UserCreate(BaseModel):
    name: str
    age: int
```

`UserCreate` receives validation behavior from `BaseModel`.

## 8. Decorators

A decorator adds behavior to a function or registers it somewhere.

```python
@app.get("/users")
def list_users():
    return []
```

Here `@app.get("/users")` tells FastAPI:

> When a GET request arrives for `/users`, call `list_users`.

The decorator does not execute the endpoint immediately. It registers the function during application startup.

## 9. Imports and modules

A Python file is a module.

```python
from fastapi import FastAPI
from pydantic import BaseModel
```

This imports `FastAPI` and `BaseModel` from installed packages.

Importing your own code:

```python
from app.services.users import create_user
```

The dotted path roughly follows folders and files:

```text
app/services/users.py
→ app.services.users
```

An `__init__.py` file marks a directory as a normal Python package and makes imports predictable.

## 10. Unpacking dictionaries

```python
body = {"name": "Vishnu", "age": 25}
user = {"id": 1, **body}
```

Result:

```python
{"id": 1, "name": "Vishnu", "age": 25}
```

`**body` copies key-value pairs into the new dictionary. This syntax is common in simple CRUD examples.

It also passes dictionary values as keyword arguments:

```python
user = UserCreate(**body)
```

This is similar to:

```python
user = UserCreate(name="Vishnu", age=25)
```

## 11. List slicing

```python
users = ["A", "B", "C", "D"]
page = users[1:3]
```

`page` becomes:

```python
["B", "C"]
```

A pagination expression often looks like:

```python
items[offset : offset + limit]
```

## 12. Exceptions

```python
def divide(a: int, b: int) -> float:
    if b == 0:
        raise ValueError("b cannot be zero")
    return a / b
```

`raise` immediately stops normal execution and reports an error. FastAPI uses the same concept with `HTTPException`.

## 13. Async syntax—only the meaning for now

```python
async def fetch_user():
    user = await database.get_user()
    return user
```

- `async def` defines an asynchronous function.
- `await` pauses this function while waiting without blocking the event loop.
- `await` can be used only inside `async def`.

You do not need async for every endpoint. It will be covered in depth later.

## Lesson summary

Be able to explain:

- annotation versus runtime validation;
- required versus optional values;
- function reference versus function call;
- decorator registration;
- class inheritance from `BaseModel`;
- dictionary unpacking;
- the basic meaning of `async` and `await`.
