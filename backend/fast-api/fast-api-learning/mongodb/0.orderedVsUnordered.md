# Ordered vs unordered bulk inserts

## Ordered insert

```python
await collection.insert_many(documents, ordered=True)
```

- This is the default behavior.
- Documents are processed in order.
- MongoDB stops when one document fails.
- Documents after the failure are not attempted.

```text
Document A -> inserted
Document B -> failed
Document C -> not attempted
```

Use it when processing should stop after the first failure.

## Unordered insert

```python
await collection.insert_many(documents, ordered=False)
```

- MongoDB attempts every document.
- One failure does not stop the remaining inserts.
- Execution order is not guaranteed.
- It can be faster than an ordered insert.

```text
Document A -> inserted
Document B -> failed
Document C -> inserted
```

Use it when documents are independent and you want to insert as many as possible.

## Quick comparison

| Behavior | Ordered | Unordered |
|---|---|---|
| Stops after an error | Yes | No |
| Attempts every document | Not always | Yes |
| Execution order guaranteed | Yes | No |
| Best for | Stop-on-error processing | Independent documents |

## Important

An ordered insert is not a transaction. If document B fails, document A remains inserted.

Use a MongoDB transaction when the requirement is: either every operation succeeds or none of them is saved.
