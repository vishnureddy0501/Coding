# Lesson 1: Coroutines, `async def`, and `await`

## 1. An async function creates a coroutine

```python
async def fetch_product(product_id: str):
    return {"product_id": product_id}
```

Calling it does not immediately produce the dictionary:

```python
result = fetch_product("p-1")  # coroutine object
result = await fetch_product("p-1")  # dictionary
```

`await` runs the coroutine and waits for its result.

## 2. Why async helps web servers

Database and network operations spend time waiting for external systems. While one request waits, the event loop can progress other requests.

```python
@router.get("/{product_id}")
async def get_product(product_id: str):
    return await product_client.fetch(product_id)
```

Async improves concurrency for waiting-heavy work. It does not make CPU calculation inherently faster.

## 3. Await only awaitable work

```python
document = collection.find_one({"product_id": product_id})
```

If this library method is synchronous, do not write `await collection.find_one(...)`. Whether `await` is needed depends on the library's API, not merely on being inside `async def`.

## 4. Sequential versus concurrent awaits

```python
product = await fetch_product(product_id)
reviews = await fetch_reviews(product_id)
```

This is sequential. Use concurrency only when operations are independent:

```python
product, reviews = await asyncio.gather(
    fetch_product(product_id),
    fetch_reviews(product_id),
)
```

If the second call needs the first result, sequential execution is correct.

## 5. Error behavior

An exception raised inside an awaited coroutine appears at the `await` expression and follows normal `try/except` rules.

## Important rule

Choose async because the called libraries support asynchronous I/O. Avoid converting every function to `async def` without a reason.
