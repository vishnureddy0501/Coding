# Lesson 2: Blocking work in an async application

## 1. What blocks the event loop?

A synchronous operation that takes a long time prevents the event-loop thread from progressing other async tasks.

Examples include:

- a slow synchronous SDK call;
- `time.sleep(...)`;
- large CPU calculations;
- synchronous file or network operations.

Never use `time.sleep` inside async request code:

```python
await asyncio.sleep(2)
```

`asyncio.sleep` yields control while waiting.

## 2. Run unavoidable synchronous work in a thread

```python
def load_from_legacy_sdk(product_id: str):
    return legacy_sdk.fetch(product_id)


async def get_product(product_id: str):
    return await asyncio.to_thread(
        load_from_legacy_sdk,
        product_id,
    )
```

`asyncio.to_thread` moves the blocking call to a worker thread so it does not freeze the event loop.

This does not make the operation faster. It protects the responsiveness of the async server.

## 3. Timeouts prevent endless waiting

```python
result = await asyncio.wait_for(
    remote_client.fetch(product_id),
    timeout=5,
)
```

A timeout limits how long your code waits. Decide how timeout errors should be logged and represented to callers.

## 4. Retries need limits

Retries are suitable for transient failures, not validation errors.

```text
attempt 1 → wait 1 second
attempt 2 → wait 2 seconds
attempt 3 → fail
```

Use a maximum attempt count and backoff. Unbounded retries can keep requests alive indefinitely and amplify an outage.

## 5. Background tasks are not request results

```python
app.state.refresh_task = asyncio.create_task(refresh_periodically())
```

This schedules independent process-level work. Do not use it when the request must know whether the operation succeeded.
