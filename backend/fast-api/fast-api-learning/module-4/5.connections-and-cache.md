# Lesson 5: Connections, caching, and concurrency safety

## 1. Reuse database clients

Creating a new database client for every request wastes connections and setup time. Applications commonly create or cache clients at process level and reuse them.

```python
clients = {}


def get_client(database_name: str):
    client = clients.get(database_name)
    if client:
        return client

    client = create_client(database_name)
    clients[database_name] = client
    return client
```

## 2. TTL caches expire entries

```python
cache[key] = (value, time.time() + ttl_seconds)
```

When reading:

```python
value, expires_at = cache[key]
if time.time() >= expires_at:
    del cache[key]
```

A TTL prevents stale resources or data from living forever.

## 3. Shared dictionaries need protection

Several threads may read and write a process-level cache. A lock protects multi-step operations:

```python
lock = threading.Lock()


with lock:
    cached = cache.get(key)
    if not cached:
        cache[key] = build_value()
```

Without a lock, two threads may both observe a miss and create conflicting entries.

Do not keep a blocking lock held while awaiting slow asynchronous I/O. Plan the locked section carefully.

## 4. Cache the right things

Good candidates are costly values that can safely be reused, such as connection handlers or slowly changing configuration.

Do not cache request-specific authorization decisions globally. Include every important dimension—such as tenant and database—in the cache key.

## 5. Cleanup policy matters

Evicting a cache entry and closing a shared client are separate decisions. Closing a client still used by an in-flight operation can break that operation. Define ownership and shutdown behavior before adding automatic cleanup.
