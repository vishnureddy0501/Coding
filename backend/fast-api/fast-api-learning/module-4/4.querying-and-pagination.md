# Lesson 4: Filtering, sorting, and pagination

## 1. Build a query incrementally

```python
query = {
    "store": store,
    "is_deleted": False,
}

if status:
    query["status"] = status

if search:
    query["name"] = {
        "$regex": re.escape(search),
        "$options": "i",
    }
```

Begin with mandatory scope constraints, then add optional filters.

`re.escape` prevents search text from unexpectedly becoming a regular-expression instruction.

## 2. Allow-list sort fields

Never send an arbitrary user string directly into database sorting:

```python
allowed_sort_fields = {
    "name": "name",
    "price": "price",
    "updated": "updated_at",
}

sort_field = allowed_sort_fields.get(sort_by, "updated_at")
sort_direction = 1 if sort_order == "asc" else -1
```

An allow-list makes supported behavior explicit.

## 3. Offset pagination

```python
cursor = (
    collection.find(query)
    .sort(sort_field, sort_direction)
    .skip(offset)
    .limit(limit + 1)
)

documents = list(cursor)
has_more = len(documents) > limit
items = documents[:limit]
```

Fetching `limit + 1` items cheaply answers whether another page exists.

The next page uses:

```text
next offset = current offset + limit
```

## 4. Count before slicing when total is required

```python
total = collection.count_documents(query)
```

The count must use the same filters as the list query. Otherwise `total` describes different data.

## 5. Validate pagination at the HTTP boundary

```python
limit: int = Query(20, ge=1, le=100)
offset: int = Query(0, ge=0)
```

The maximum protects the database and response size from an unbounded request.

## 6. Indexes support frequent query shapes

An index helps MongoDB locate and sort documents without scanning everything. Design indexes from real query patterns, especially tenant scope, soft-delete flags, identifiers, and common sort fields.

Indexes improve reads but consume storage and add write cost. Do not index every field automatically.
