# Lesson 3: MongoDB documents and CRUD

MongoDB stores dictionary-like documents in collections.

## 1. Example document

```python
document = {
    "product_id": "p-1",
    "store": "store-a",
    "name": "Keyboard",
    "price": 70,
    "is_deleted": False,
}
```

Application-facing string IDs are often easier to expose than MongoDB's internal `_id`.

## 2. Insert

```python
result = collection.insert_one(document)

if not result.inserted_id:
    raise HTTPException(status_code=500, detail="Failed to create product")
```

Build and validate the document before inserting it.

## 3. Find one

Always include tenant or ownership boundaries in the query:

```python
document = collection.find_one(
    {
        "store": store,
        "product_id": product_id,
        "is_deleted": False,
    }
)

if not document:
    raise HTTPException(status_code=404, detail="Product not found")
```

Looking up only by `product_id` could accidentally cross tenant boundaries.

## 4. Update

```python
result = collection.update_one(
    {"store": store, "product_id": product_id},
    {"$set": {"price": new_price}},
)

if result.matched_count == 0:
    raise HTTPException(status_code=404, detail="Product not found")
```

`matched_count` says whether a document matched. `modified_count` can be zero even when the document exists—for example, when the new value equals the old value.

## 5. Soft delete

```python
collection.update_one(
    {"store": store, "product_id": product_id},
    {"$set": {"is_deleted": True}},
)
```

Soft deletion keeps the document but hides it from normal reads. Every relevant read query must consistently include `is_deleted: False`.

## 6. Convert database data at the boundary

Database documents can contain fields not intended for clients. Build a response model rather than returning raw documents blindly.
