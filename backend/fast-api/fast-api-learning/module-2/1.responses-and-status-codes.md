# Lesson 1: Responses and status codes

## 1. The response pipeline

For a normal returned value:

```text
route returns Python data
        ↓
FastAPI applies the response model
        ↓
output is validated, filtered, and serialized
        ↓
an HTTP response is created
```

```python
class UserPublic(BaseModel):
    id: int
    username: str


@app.get("/users/{user_id}", response_model=UserPublic)
def get_user(user_id: int):
    return {
        "id": user_id,
        "username": "vishnu",
        "password_hash": "must-not-leak",
    }
```

The response contains only `id` and `username`. A response model is simultaneously validation, serialization, filtering, documentation, and a security boundary.

Do not rely on filtering as your only secret-handling strategy. Prefer not to put secrets in returned structures at all.

## 2. Return annotation versus `response_model`

When the function truly returns the declared model, use a return annotation:

```python
@app.get("/tasks/{task_id}")
def get_task(task_id: int) -> TaskResponse:  # in customer success code base also. we don't have this syntax. It has response_model syntax at all places.
    return TaskResponse(id=task_id, title="Learn", completed=False)
```

When your implementation returns a different internal type, use the decorator:

```python
from typing import Any


@app.get("/tasks/{task_id}", response_model=TaskResponse)
def get_task(task_id: int) -> Any:
    return {"id": task_id, "title": "Learn", "completed": False}
```

If both are declared, `response_model` controls FastAPI's response processing. Do not specify both without a reason.

Collections and envelopes are contracts too:

```python
class TaskList(BaseModel):
    items: list[TaskResponse]
    total: int


@app.get("/tasks", response_model=TaskList)
def list_tasks():
    return {"items": [], "total": 0}
```

An envelope can carry pagination metadata; a bare `list[TaskResponse]` is simpler when metadata is unnecessary.

## 4. Default success status

The decorator's `status_code` describes the normal successful outcome:

```python
@app.post(
    "/tasks",
    response_model=TaskResponse,
    status_code=status.HTTP_201_CREATED,
)
def create_task(body: TaskCreate): ...
```

## 5. Adding response headers or changing status dynamically

FastAPI can inject a temporary `Response` object:

```python
from fastapi import Response, status


@app.put("/tasks/{task_id}", response_model=TaskResponse)
def upsert_task(task_id: int, body: TaskCreate, response: Response):
    created = task_id not in tasks
    task = save_task(task_id, body)

    response.headers["X-Resource-ID"] = str(task_id)
    if created:
        response.status_code = status.HTTP_201_CREATED
    return task
```

You still return normal data, so response-model processing remains active. FastAPI copies the status and headers from the injected `Response` into the final response.

If many branches need different outcomes, separate endpoints or explicit response types may be clearer than extensive dynamic status changes.

## 6. Returning a `Response` directly

```python
from fastapi.responses import JSONResponse


@app.get("/raw")
def raw_response() -> JSONResponse:
    return JSONResponse(
        status_code=200,
        content={"message": "already prepared"},
        headers={"X-Source": "manual"},
    )
```

When you return a `Response` subclass directly, FastAPI passes it through. You become responsible for its body, status, content type, and serialization. A declared response model does not filter a directly returned response.

Use direct responses when you actually need control: empty responses, redirects, files, streaming, non-JSON formats, or custom error handlers. Use normal returned data for ordinary JSON APIs.


## 9. Response validation failure

If a route promises `TaskResponse` but omits a required field, that is an application bug, not a client mistake. FastAPI produces a server error rather than sending invalid data.

Do not catch this and turn it into `422`. The request may be perfectly valid; your output violated your own contract.

## Common mistakes

- Assuming a return annotation is merely documentation when FastAPI can use it as a response field.
- Returning internal or secret fields without an output model.
- Returning `JSONResponse` unnecessarily and bypassing response-model processing.
- Sending a body with `204`.
- Documenting errors in `responses` but returning a different runtime shape.
- Treating response validation failure as a client validation error.
- Using `202` as a generic successful response.

## 3. Response-model include and exclude options [No need, not present in Aviso]

FastAPI supports options such as `response_model_exclude_none=True`, but use them carefully:

```python
@app.get(
    "/tasks/{task_id}",
    response_model=TaskResponse,
    response_model_exclude_none=True,
)
def get_task(task_id: int): ...
```

This can make actual output differ from the model's apparent full shape. Prefer a response model that accurately expresses the public contract. Use exclude options only when omission is genuinely part of that contract.

## 7. Correct empty responses [We don't use 204. Hence not needed]

```python
@app.delete(
    "/tasks/{task_id}",
    status_code=status.HTTP_204_NO_CONTENT,
    response_class=Response,
)
def delete_task(task_id: int) -> Response:
    delete_existing_task(task_id)
    return Response(status_code=status.HTTP_204_NO_CONTENT)
```

A `204` must have no body. If you want to return `{"deleted": true}`, use `200` instead.


## 8. Documenting additional responses

The success model alone does not document every possible error:

```python
class ErrorDetail(BaseModel):
    code: str
    message: str


class ErrorResponse(BaseModel):
    error: ErrorDetail


@app.get(
    "/tasks/{task_id}",
    response_model=TaskResponse,
    responses={404: {"model": ErrorResponse, "description": "Task not found"}},
)
def get_task(task_id: int): ...
```

`responses` enriches OpenAPI documentation; it does not automatically make your runtime errors match that model. Your exception handling must return the documented shape.
