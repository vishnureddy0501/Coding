# Pairs and Custom Comparators

## Priority Queue of Pairs

This is a max heap of pairs:

```cpp
priority_queue<pair<int, int>> maxHeap;
```

Pairs are compared lexicographically:

1. Compare `.first`.
2. If `.first` is equal, compare `.second`.

```cpp
maxHeap.push({5, 2});
maxHeap.push({3, 10});
maxHeap.push({5, 7});

auto [first, second] = maxHeap.top();
// {5, 7}
```

`{5, 7}` comes before `{5, 2}` because their first values are equal and `7` is larger than `2`.

## Min Heap of Pairs

```cpp
priority_queue<
    pair<int, int>,
    vector<pair<int, int>>,
    greater<pair<int, int>>
> minHeap;
```

This is common in Dijkstra:

```cpp
// {distance, node}
minHeap.push({0, source});
```

Because distance is stored first, the pair with the smallest distance reaches the top.

## Pair Containing a Vector

The following type stores a score and a list of values:

```cpp
using Item = pair<double, vector<int>>;
```

With the default pair comparison, both the score and vector participate in ordering:

```cpp
priority_queue<Item, vector<Item>, greater<Item>> minHeap;

minHeap.push({3.5, {1, 2, 3}});
minHeap.push({1.2, {4, 5}});
minHeap.push({2.8, {6, 7}});
```

If only the score should determine priority, use a custom comparator.

## Comparator Rule

The comparator answers:

> Should `a` have lower priority than `b`?

For a min heap, return `true` when `a` should come after `b`, usually when `a` is larger:

```cpp
struct MinComparator {
    bool operator()(int a, int b) const {
        return a > b;
    }
};
```

For a max heap, return `true` when `a` should come after `b`, usually when `a` is smaller:

```cpp
struct MaxComparator {
    bool operator()(int a, int b) const {
        return a < b;
    }
};
```

This feels reversed because the element considered lower priority moves away from the top.

## Custom Comparator for Objects

Suppose each item is `{score, studentId}` and the smallest score should come first:

```cpp
struct CompareScore {
    bool operator()(
        const pair<int, int>& a,
        const pair<int, int>& b
    ) const {
        if (a.first != b.first) {
            return a.first > b.first;
        }

        return a.second > b.second;
    }
};

priority_queue<
    pair<int, int>,
    vector<pair<int, int>>,
    CompareScore
> minHeap;
```

This sorts by:

1. Smaller score first
2. Smaller student ID when scores are equal

## Custom Comparator for Vectors

Largest first value at the top:

```cpp
struct CompareFirstValue {
    bool operator()(
        const vector<int>& a,
        const vector<int>& b
    ) const {
        return a[0] < b[0];
    }
};

priority_queue<
    vector<int>,
    vector<vector<int>>,
    CompareFirstValue
> heap;

heap.push({10, 20});
heap.push({30, 40});

// {30, 40} is at the top.
```

## Comparator Based on the Last Digit

Smallest last digit at the top:

```cpp
struct CompareLastDigit {
    bool operator()(int a, int b) const {
        return a % 10 > b % 10;
    }
};

priority_queue<
    int,
    vector<int>,
    CompareLastDigit
> heap;

heap.push(34);
heap.push(45);
heap.push(12);
```

Pop order:

```text
12 34 45
```

Their last digits are `2`, `4`, and `5`.

## Lambda Comparator

A lambda can be useful when the ordering is local to one function:

```cpp
auto compare = [](const pair<int, int>& a, const pair<int, int>& b) {
    return a.second > b.second;
};

priority_queue<
    pair<int, int>,
    vector<pair<int, int>>,
    decltype(compare)
> minHeap(compare);
```

This creates a min heap based on `.second`.

## Negative-Value Min-Heap Trick

A max heap can simulate a min heap by storing negative values:

```cpp
priority_queue<int> heap;

heap.push(-10);
heap.push(-5);

int smallest = -heap.top(); // 5
```

For a pair:

```cpp
priority_queue<pair<int, int>> heap;

// Store {-value, -index}.
heap.push({-value, -index});

auto [negativeValue, negativeIndex] = heap.top();
int value = -negativeValue;
int index = -negativeIndex;
```

This trick works, but `greater<T>` is usually clearer and less error-prone.
