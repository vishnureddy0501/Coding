In a recent interview, I was asked, "Can you implement asynchronous communication without Kafka or any message broker?" My immediate thought was that this sounded like a trick question, as many engineers typically associate asynchronous communication with tools like Kafka, RabbitMQ, or other message brokers.

However, the answer is surprisingly straightforward: Yes, we absolutely can.

Consider an e-commerce application where a payment succeeds. After that, we need to:
1. Send an Order Confirmation email.
2. Generate an invoice.

Instead of publishing an event to Kafka, the Payment Service can simply:
- Store these tasks in a database table.
- Return the success response to the user immediately.
- Let a background worker periodically poll the database table and process pending jobs asynchronously.

This pattern is often referred to as the Transactional Outbox Pattern or Database-backed Job Queue—no Kafka, no RabbitMQ, yet still asynchronous.

Message brokers become valuable when you need:
1. High throughput.
2. Multiple consumers.
3. Event replay.
4. Independent scaling.

For simple workflows and low-traffic systems, a database-backed job queue can be the simpler and more practical solution.
