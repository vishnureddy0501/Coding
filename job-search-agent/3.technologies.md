# 3. Technologies

## Recommended stack

| Area | Technology | Why |
|---|---|---|
| Web UI | Next.js + TypeScript + Tailwind CSS | Fast job-list UI and good SEO if pages become public |
| API | FastAPI + Pydantic | Async APIs and clear validation |
| API/feed collection | `httpx` | Simple async HTTP requests |
| HTML crawling | Scrapy | Scheduling, retries, throttling, parsing pipelines |
| JavaScript pages | Playwright, only when permitted | Renders pages that require a browser |
| Database | PostgreSQL | Filtering, relations, uniqueness, and full-text search |
| ORM/migrations | SQLAlchemy + Alembic | Database models and controlled schema changes |
| Background jobs | Celery + Redis | Scheduled collection and retries outside the API |
| Cache/queue | Redis | Task broker and short-lived query cache |
| Deployment | Docker Compose initially | Repeatable local and server setup |
| Monitoring | Structured logs + Sentry initially | Failures and broken adapters |

## What not to add initially

- Kafka
- Kubernetes
- Elasticsearch/OpenSearch
- Multiple microservices
- LLM-based extraction for every page

Begin as a **modular monolith** with separate API, worker, frontend, PostgreSQL, and Redis containers. Split services only after real scaling problems appear.

## Where AI fits later

After collection works reliably, AI can:

- extract missing skills from descriptions;
- match a resume to jobs;
- explain why a job matches;
- summarize long descriptions;
- generate search queries.

Do not use an LLM for fields already available in structured APIs.
