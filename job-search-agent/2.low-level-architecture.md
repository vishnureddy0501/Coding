# 2. Low-level architecture

## Complete collection flow

```mermaid
sequenceDiagram
    autonumber
    participant S as Scheduler
    participant Q as Redis queue
    participant W as Celery worker
    participant A as Source adapter
    participant P as Processing pipeline
    participant DB as PostgreSQL

    S->>Q: Enqueue collect_source(source_id)
    Q->>W: Deliver task
    W->>DB: Create crawl_run = running
    W->>A: fetch(cursor / page)
    A->>A: Call API or permitted page
    A-->>W: RawJob records
    W->>P: Normalize each RawJob
    P->>P: Validate required fields
    P->>P: Build deduplication key
    P->>DB: Upsert company and job
    P->>DB: Mark unseen old jobs inactive
    W->>DB: Save counts and crawl status
```

## Adapter contract

Every portal has different field names. Each adapter must return the same `RawJob` shape:

```python
class RawJob:
    source: str
    external_id: str | None
    title: str
    company_name: str
    location_text: str | None
    description_html: str
    apply_url: str
    posted_at: datetime | None
    employment_type: str | None
    remote_type: str | None
```

Example mappings:

```text
Greenhouse departments  -> categories
Lever workplaceType     -> remote_type
Career-page jobLocation -> location_text
```

The rest of the application never needs to understand portal-specific names.

## Search request flow

```mermaid
sequenceDiagram
    autonumber
    participant U as User
    participant UI as Next.js
    participant API as FastAPI
    participant R as Redis cache
    participant DB as PostgreSQL

    U->>UI: Search "React Bengaluru remote"
    UI->>API: GET /jobs?q=React&location=Bengaluru&remote=true
    API->>R: Check cached result
    alt Cache hit
        R-->>API: Job IDs/result
    else Cache miss
        API->>DB: Filter, search, sort, paginate
        DB-->>API: Jobs
        API->>R: Cache briefly
    end
    API-->>UI: Paginated JSON
    UI-->>U: Render job cards
```

## Failure handling

```text
Temporary timeout -> retry with delay
Invalid record    -> skip it and log the reason
Parser broken     -> fail only that source
Database error    -> retry task; do not lose crawl status
Repeated failure  -> alert and disable that source temporarily
```

Never let one broken adapter stop the other sources.
