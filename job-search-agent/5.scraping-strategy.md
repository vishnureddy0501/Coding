# 5. Scraping strategy

## Use sources in this order

```text
1. Official/public API
2. Public ATS JSON feed
3. RSS or approved feed
4. Permitted static HTML page
5. Permitted JavaScript page with Playwright
```

APIs are more stable and cheaper than browser scraping. Greenhouse provides a Job Board API, and Lever provides a public Postings API.

## One adapter per source type

```text
collectors/
├── base.py
├── greenhouse.py
├── lever.py
├── rss.py
└── career_page/
    └── example_company.py
```

Several companies using Greenhouse can share one Greenhouse adapter; only their board token changes.

## Responsible collection rules

- Read the site's terms and `robots.txt` before collecting.
- Identify your crawler when appropriate.
- Use low concurrency and delays.
- Cache responses and avoid downloading unchanged pages.
- Never bypass logins, CAPTCHAs, access controls, or rate limits.
- Store only fields required for job search.
- Remove expired jobs and honor deletion requests.
- Do not automate applications without explicit permission and user confirmation.

## Freshness

For every successful crawl:

1. Set `last_seen_at` for jobs found now.
2. Do not immediately delete missing jobs—a temporary page failure may occur.
3. Mark a job inactive only after it is absent from multiple successful crawls or its source says it is closed.

## Detecting broken parsers

Alert when:

- a normally large source suddenly returns zero jobs;
- required fields are missing for many records;
- HTTP errors repeat;
- the HTML structure no longer matches selectors.

Keep a few saved HTML/JSON fixtures and test every adapter against them.
