# 6. MVP implementation plan

## Phase 1 — One source end to end

Use Greenhouse or Lever:

1. Create PostgreSQL tables.
2. Build one API adapter using `httpx`.
3. Normalize and upsert jobs.
4. Create `GET /api/v1/jobs` in FastAPI.
5. Display job cards in Next.js.

At this point, run collection manually. Do not add Celery yet.

## Phase 2 — Multiple sources

1. Add the second ATS adapter.
2. Add deduplication.
3. Track crawl runs and errors.
4. Add filters and pagination.
5. Mark expired jobs inactive.

## Phase 3 — Automation

1. Add Redis and Celery workers.
2. Schedule each enabled source.
3. Add retry rules and timeouts.
4. Add monitoring and alerts.

## Phase 4 — User features

- Authentication
- Saved jobs
- Search alerts
- Application tracking
- Resume-based matching

## Suggested project structure

```text
job-search-agent/
├── frontend/                 # Next.js
├── backend/
│   ├── app/
│   │   ├── api/              # FastAPI routes
│   │   ├── collectors/       # Source adapters
│   │   ├── processing/       # Normalize and deduplicate
│   │   ├── models/           # SQLAlchemy models
│   │   ├── schemas/          # Pydantic schemas
│   │   ├── repositories/     # Database access
│   │   └── tasks/            # Celery tasks
│   ├── migrations/           # Alembic
│   └── tests/
├── docker-compose.yml
└── .env.example
```

## First success condition

```text
Collect 100+ jobs from one permitted source
-> rerun without duplicates
-> search/filter them in the browser
-> correctly mark removed jobs inactive
```

Only after this works should you add more portals or AI features.
