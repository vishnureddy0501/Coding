# 2. Create and test the ALB

In **EC2 → Load Balancers → Create Application Load Balancer**:

| Setting | Value |
|---|---|
| Name | `fastapi-prod-alb` |
| Scheme | Internet-facing |
| IP type | IPv4 |
| VPC | Same VPC as production EC2 |
| Subnets | Public subnets from at least two Availability Zones |
| Security group | `fastapi-alb-sg` |
| Listener | HTTP `80` |
| Default action | Forward to `fastapi-prod-tg` |

The ALB needs two Availability Zone subnets even though the target group currently contains one EC2 instance.

## Verify

1. Open `fastapi-prod-tg → Targets`.
2. Wait for the production target to become **Healthy**.
3. Open the ALB and copy its **DNS name**.
4. Test:

```text
http://<alb-dns-name>/health
http://<alb-dns-name>/docs
```

If unhealthy, check Nginx, `/health`, port `80`, and both security groups.

Delete the ALB after practice if you do not want it running continuously; ALB charges continue while it exists.

Reference: [AWS: create an Application Load Balancer](https://docs.aws.amazon.com/elasticloadbalancing/latest/application/create-application-load-balancer.html)
