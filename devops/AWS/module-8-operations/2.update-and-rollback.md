# 2. Deploy updates and roll back

Never overwrite the previous image tag. Build a new tag such as `v2`.

```text
Build v2 -> deploy to dev -> verify -> deploy to prod
```

## On development EC2

Replace `<account-id>`, then run:

```bash
sudo docker pull <account-id>.dkr.ecr.ap-south-1.amazonaws.com/fastapi-app:v2
sudo docker rm -f fastapi-app
sudo docker run -d \
  --name fastapi-app \
  --restart unless-stopped \
  --env-file /opt/fastapi/app.env \
  -p 127.0.0.1:8000:8000 \
  <account-id>.dkr.ecr.ap-south-1.amazonaws.com/fastapi-app:v2

curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/ready
```

Only then repeat the same steps on production.

## Rollback

If `v2` fails:

```bash
sudo docker rm -f fastapi-app
sudo docker run -d \
  --name fastapi-app \
  --restart unless-stopped \
  --env-file /opt/fastapi/app.env \
  -p 127.0.0.1:8000:8000 \
  <account-id>.dkr.ecr.ap-south-1.amazonaws.com/fastapi-app:v1

curl http://127.0.0.1:8000/health
```

Keep at least the current and previous working ECR tags. This single-server process causes brief downtime; zero-downtime deployment comes later with multiple instances.

Automate this with GitHub Actions only after the manual process is comfortable. Use GitHub OIDC later instead of saving permanent AWS keys in GitHub.
