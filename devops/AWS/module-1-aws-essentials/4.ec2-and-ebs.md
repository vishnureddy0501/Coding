# Lesson 4: EC2 servers and EBS disks

## 1. What is EC2?

EC2 is an AWS service for renting virtual computers.

One rented virtual computer is called an **EC2 instance**.

It behaves like a normal computer:

- it has CPU and memory;
- it runs an operating system;
- it has a disk;
- it connects to a network;
- you can install software on it.

Our EC2 instance will run:

```text
Ubuntu
├── Docker
│   └── FastAPI application
└── Nginx
```

## 2. What do we choose when creating EC2?

When launching an instance, AWS asks for several choices:

| Choice | Meaning |
|---|---|
| Region | Geographic location of the server |
| AMI | Starting operating-system image |
| Instance type | CPU and memory size |
| Subnet | Network and Availability Zone |
| Security group | Allowed network traffic |
| IAM role | AWS permissions given to the server |
| EBS volume | Server disk |

We will configure these later through the AWS Console.

## 3. What is an AMI?

AMI means Amazon Machine Image. It is a template used to create an EC2 server.

For example:

```text
Ubuntu AMI
   -> Launch instance
   -> New virtual server running Ubuntu
```

An AMI is not a running server. It is the starting template for one.

## 4. What is an instance type?

The instance type decides how much CPU and memory the server has.

```text
Smaller instance -> lower cost, less capacity
Larger instance  -> higher cost, more capacity
```

Examples include `t3.micro` and `t3.small`. We will select a small instance after checking the current price and FastAPI's memory needs.

Do not choose a large instance just because it is available. Start small, observe usage, and increase it only when necessary.

## 5. What is EBS?

EBS means Elastic Block Store. It is a virtual disk attached to EC2.

It stores:

- Ubuntu system files;
- installed programs;
- Docker images;
- Nginx configuration;
- local logs.

```text
EC2 = virtual computer
EBS = disk connected to that computer
```

## 6. What should not be stored only on EBS?

Do not store important user uploads only on the server disk:

```text
/home/ubuntu/uploads/profile-photo.jpg
```

If the instance is deleted or replaced, the file may be lost or unavailable.

Use the correct storage:

```text
Application records -> MongoDB Atlas
Uploaded files      -> S3
Server files        -> EBS
```

## 7. EC2 private and public IPs

EC2 receives a private IP inside the VPC. It may also receive a public IP for internet communication.

```text
Private IP -> communication inside the VPC
Public IP  -> communication through the internet
```

An automatically assigned public IP can change after an instance is stopped and started.

Production users will access the Application Load Balancer rather than depending on the EC2 public IP.

## 8. Instance states

| State | Meaning |
|---|---|
| Running | Server is powered on |
| Stopped | Server is powered off but can be started again |
| Terminated | Server is deleted and cannot be restarted |

Stopping an instance usually stops compute charges, but its EBS disk and some other attached resources can still cost money.

## 9. Development and production instances

We will use two independent servers:

```text
fastapi-dev-ec2
└── Development configuration and data access

fastapi-prod-ec2
└── Production configuration and data access
```

A development failure should not affect production.

## 10. What are we responsible for?

AWS maintains the physical hardware. We are responsible for what runs inside the instance:

- operating-system updates;
- Docker and Nginx installation;
- application deployment;
- security-group configuration;
- secrets and permissions;
- logs and monitoring.

EC2 gives control, but that control includes maintenance responsibility.

## Common mistakes

- Choosing the wrong AWS Region
- Opening every network port to the internet
- Giving the EC2 role administrator permission
- Storing uploads only on EBS
- Assuming a stopped instance has no remaining cost
- Terminating an instance before checking important data
