# Lesson 1: Cloud, Regions, and Availability Zones

## 1. What does “cloud” mean?

Without a cloud provider, you would need to:

1. buy a physical computer;
2. keep it powered on;
3. connect it to the internet;
4. replace failed hardware;
5. secure and maintain it.

AWS owns large data centers and lets you rent computing resources. You create and remove resources when needed and pay for what you use.

AWS is not one machine. It is a collection of services for computing, storage, networking, security, monitoring, and many other tasks.

## 2. What is a server?

A server is a computer that waits for requests and responds to them.

Your laptop can temporarily act as a server:

```bash
uvicorn app.main:app --port 8000
```

But when the laptop sleeps or disconnects, users cannot reach the application. For deployment, FastAPI runs on a computer that remains available. In our architecture, that computer is an EC2 instance.

## 3. What is an AWS Region?

A Region is a geographical AWS location.

Examples:

| Region code | Location |
|---|---|
| `ap-south-1` | Mumbai |
| `ap-south-2` | Hyderabad |
| `us-east-1` | North Virginia |
| `eu-west-1` | Ireland |

Resources created in one Region usually stay in that Region. If you create an EC2 instance while the console is set to Mumbai and later switch to Ireland, the instance will not appear there.

### How to select a Region

Consider:

- location of most users;
- location of the MongoDB Atlas cluster;
- service availability;
- legal or data-residency requirements;
- price differences.

For this course, use Mumbai (`ap-south-1`) unless your Atlas cluster or users are closer to another Region.

Keep EC2 and Atlas close to reduce network travel time.

## 4. What is an Availability Zone?

A Region contains multiple isolated Availability Zones, normally written as:

```text
ap-south-1a
ap-south-1b
ap-south-1c
```

Think of a Region as a city and Availability Zones as separate groups of data centers within that city.

Availability Zones have independent infrastructure, but they are connected using fast private networking.

If one Availability Zone has a serious failure, resources in another zone may continue operating.

## 5. Region versus Availability Zone

```text
AWS
└── Region: ap-south-1
    ├── Availability Zone: ap-south-1a
    ├── Availability Zone: ap-south-1b
    └── Availability Zone: ap-south-1c
```

| Region | Availability Zone |
|---|---|
| A geographic AWS location | An isolated location inside a Region |
| Contains multiple AZs | Belongs to exactly one Region |
| Example: Mumbai | Example: `ap-south-1a` |

## 6. What will our application use?

- Dev EC2: one Availability Zone
- Prod EC2: one Availability Zone initially
- Application Load Balancer: subnets in at least two Availability Zones
- S3: a regional service; you do not place a bucket in a particular AZ

One production EC2 instance is not highly available. If its instance or Availability Zone fails, the API becomes unavailable. We accept that simplification now and will learn redundancy later.
