# Lesson 5: Docker, ECR, Nginx, and FastAPI

This lesson explains how the application runs inside EC2.

## 1. The software stack

```text
EC2 virtual server
└── Ubuntu operating system
    ├── Docker
    │   └── FastAPI container on port 8000
    └── Nginx on port 80
```

Each layer has one job.

## 2. FastAPI and Uvicorn

FastAPI defines routes and business logic. It does not listen for network requests by itself.

Uvicorn is an ASGI server that runs the FastAPI application:

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Meaning:

- `app.main` refers to `app/main.py`;
- `:app` is the FastAPI object;
- `0.0.0.0` accepts connections from outside the container;
- `8000` is the application port.

## 3. What problem does Docker solve?

Without Docker, we manually install the correct Python version and every dependency on each server.

Docker packages the application and its runtime requirements into an image:

```text
Docker image
├── Python
├── Dependencies
├── Application code
└── Startup command
```

The same image can run on a laptop, dev EC2, and prod EC2.

## 4. Image versus container

An image is a packaged template. A container is a running copy of that image.

```text
Docker image --docker run--> Running container
```

One image can be used to start multiple containers.

## 5. What is a Dockerfile?

A Dockerfile contains instructions for building an image.

Simplified example:

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY . .
RUN pip install -r requirements.txt
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

We will create a proper project-specific Dockerfile in Module 2.

## 6. What is ECR?

ECR means Elastic Container Registry. It stores Docker images in AWS.

The deployment flow is:

```text
Source code
   -> Build Docker image
   -> Push image to ECR
   -> EC2 pulls image from ECR
   -> EC2 starts a container
```

ECR stores images; it does not run them. EC2 runs the container.

## 7. Why do we need Nginx?

Nginx is a web server and reverse proxy.

It receives HTTP traffic on port `80` and forwards it to FastAPI on port `8000`:

```text
Request -> Nginx :80 -> FastAPI :8000
```

Nginx also provides:

- access and error logs;
- request-size limits;
- timeout settings;
- one stable entry point for the application.

## 8. What is a reverse proxy?

A reverse proxy receives a request for another server and forwards it.

The client does not call FastAPI directly:

```text
Client knows Nginx
Nginx knows FastAPI
```

Conceptual Nginx configuration:

```nginx
server {
    listen 80;

    location / {
        proxy_pass http://127.0.0.1:8000;
    }
}
```

`127.0.0.1` means the same EC2 server.

## 9. Docker port mapping

Think of the container as a small separate computer inside EC2.

FastAPI listens on port `8000` **inside the container**. Nginx runs on the EC2 host, so Docker must provide a path from EC2 to that container port.

```text
EC2 port 8000  -------->  Container port 8000
     host                       FastAPI
```

We create that path using `-p`:

```bash
docker run -p 127.0.0.1:8000:8000 your-image
```

Read it like this:

```text
127.0.0.1 : 8000 : 8000
    |         |       |
    |         |       └── port inside the container
    |         └────────── port on the EC2 host
    └──────────────────── only this EC2 machine can use it
```

The complete request flow is:

```text
User
  |
  v
Nginx on EC2 :80
  |
  v
EC2 localhost :8000
  |  Docker port mapping
  v
FastAPI inside container :8000
```

The two port numbers do not have to match. For example:

```bash
docker run -p 127.0.0.1:9000:8000 your-image
```

This means EC2 port `9000` forwards to FastAPI's container port `8000`. Nginx would then use `http://127.0.0.1:9000`.

For this project, we use `127.0.0.1:8000:8000`. Nginx can reach FastAPI, but users cannot bypass Nginx and directly access port `8000`.

## 10. Configuration is not baked into the image

Dev and prod should use the same image with different environment values:

```text
Same image + dev MONGO_URL  + dev S3 bucket  = dev app
Same image + prod MONGO_URL + prod S3 bucket = prod app
```

Never bake passwords or production configuration into a Docker image.

## 11. Restarting the application

The container should start again after a server reboot or process failure. For the first deployment, Docker's restart policy is enough:

```bash
docker run --restart unless-stopped ...
```

We will test restart behavior during deployment.

## Common mistakes

- Confusing an ECR image with a running container
- Exposing port `8000` publicly
- Putting secrets inside the image
- Using different manually built application setups in dev and prod
- Forgetting a restart policy
- Running Nginx while the FastAPI container is stopped
