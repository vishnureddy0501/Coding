# Lesson 7: S3, MongoDB Atlas, and configuration

## 1. Why do we need different storage systems?

Different data has different storage needs:

| Data | Storage |
|---|---|
| Users, tasks, orders, metadata | MongoDB Atlas |
| Images, PDFs, exports, attachments | Amazon S3 |
| Ubuntu, Docker, Nginx files | EC2's EBS disk |

MongoDB is a database. S3 is file/object storage. EBS is the server's disk.

## 2. What is S3?

S3 means Simple Storage Service. It stores files as objects inside buckets.

```text
Bucket: fastapi-prod-files
└── Object
    ├── Key: users/123/profile.jpg
    └── Content: image bytes
```

- A bucket is the top-level container.
- A key is the object's unique name inside the bucket.
- The object is the stored file and its metadata.

Keys look like folder paths, but S3 is not a normal disk filesystem.

## 3. Why separate dev and prod buckets?

```text
fastapi-dev-files
fastapi-prod-files
```

This prevents development testing from deleting or replacing production files. It also allows separate IAM permissions.

## 4. Private buckets

Our buckets should not be public. S3 Block Public Access remains enabled.

FastAPI accesses S3 using its EC2 IAM role:

```text
FastAPI -> EC2 role -> S3 permission check -> bucket
```

## 5. Presigned URLs

Sometimes a browser should upload or download directly from S3.

FastAPI can create a temporary presigned URL:

```text
1. Browser asks FastAPI for permission.
2. FastAPI verifies the user.
3. FastAPI creates a short-lived S3 URL.
4. Browser uses that URL for one allowed operation.
```

The bucket remains private. The URL carries temporary, limited permission.

## 6. What goes into MongoDB?

Store file information and the S3 key:

```json
{
  "user_id": "123",
  "file_name": "profile.jpg",
  "s3_key": "users/123/profile.jpg"
}
```

Store the actual file in S3.

## 7. What is MongoDB Atlas?

Atlas is a managed MongoDB service. Atlas operates the database servers, while our FastAPI application connects to them.

FastAPI needs a connection string:

```text
mongodb+srv://USERNAME:PASSWORD@CLUSTER/DATABASE
```

This value is secret because it contains database credentials.

## 8. Atlas performs two checks

For a connection to work:

1. the connection source must be allowed by Atlas network access;
2. the database username and password must be valid.

```text
Network access check
        +
Database authentication
        =
Successful connection
```

Avoid permanently allowing `0.0.0.0/0`, because that permits connection attempts from anywhere.

## 9. Separate Atlas environments

Use separate databases and users:

```text
Dev FastAPI  -> dev Atlas user  -> dev database
Prod FastAPI -> prod Atlas user -> prod database
```

Development code should not be able to modify production records.

## 10. Application configuration

The application needs values such as:

```text
APP_ENV
MONGO_URL
MONGO_DATABASE
S3_BUCKET
AWS_REGION
```

These values change between environments, but the application image remains the same.

## 11. Parameter Store

AWS Systems Manager Parameter Store keeps configuration outside Git and the Docker image.

Suggested names:

```text
/fastapi/dev/mongo-url
/fastapi/dev/s3-bucket
/fastapi/prod/mongo-url
/fastapi/prod/s3-bucket
```

Use `SecureString` for secret values. The EC2 IAM role receives permission to read only its environment's path.

## 12. Secret versus non-secret

| Configuration | Secret? |
|---|---|
| MongoDB URL containing a password | Yes |
| JWT signing key | Yes |
| S3 bucket name | Usually no |
| AWS Region | No |
| Environment name | No |

Even non-secret values belong outside the image when they vary between dev and prod.

## Common mistakes

- Making the entire S3 bucket public
- Storing permanent AWS keys in application settings
- Putting the MongoDB password in Git
- Sharing the same database and bucket between dev and prod
- Storing large files directly in MongoDB without a reason
- Saving uploads only on the EC2 disk

4. Why does Atlas need network permission and credentials?
5. Where should `MONGO_URL` be stored?

### Answers

1. S3.

3. No. It grants temporary permission for a specific operation.
4. The network rule controls where connections originate; credentials identify and authorize the database user.
5. In secure configuration such as Parameter Store `SecureString`.
