# Lesson 6: Load balancer, domain, and HTTPS

## 1. The problem we are solving

We want users to call:

```text
https://api.example.com
```

instead of remembering an EC2 IP address such as:

```text
http://203.0.113.10
```

We also want HTTPS and automatic health checks.

Our flow is:

```text
Domain -> Application Load Balancer -> EC2 -> Nginx -> FastAPI
```

## 2. What is DNS?

DNS translates a human-readable name into a network destination.

```text
api.example.com -> Application Load Balancer
```

It works like a contacts list: you remember a name instead of a number.

## 3. What is Route 53?

Route 53 is AWS's DNS service.

We create a DNS record that points the production API name to the load balancer:

```text
api.example.com -> fastapi-prod-alb
```

Route 53 does not run FastAPI and does not forward application code. It helps clients locate the ALB.

## 4. What is an Application Load Balancer?

An ALB receives HTTP/HTTPS requests and forwards them to application servers.

```text
Users
  |
  v
ALB
  |
  v
Production EC2
```

We initially have only one EC2 target. The ALB still gives us:

- a stable endpoint;
- HTTPS certificate handling;
- health checks;
- an easy path to add more servers later.

An ALB costs money even with only one target.

## 5. Listener

A listener is an ALB rule that waits on a port.

We will use:

```text
Port 80  -> redirect to HTTPS
Port 443 -> forward to the FastAPI target group
```

The listener answers: “What should the ALB do when traffic arrives on this port?”

## 6. Target group

A target group contains the servers that can receive forwarded requests.

```text
fastapi-prod-target-group
└── production EC2 on port 80
```

The ALB does not forward directly to FastAPI port `8000`. It sends traffic to Nginx on EC2 port `80`.

## 7. Health check

The target group regularly requests:

```http
GET /health
```

FastAPI returns a small success response:

```python
@app.get("/health")
async def health():
    return {"status": "ok"}
```

If checks fail repeatedly, the target becomes unhealthy and stops receiving normal ALB traffic.

With only one target, the API becomes unavailable when it is unhealthy. The ALB detects failure but cannot repair the server.

## 8. HTTP versus HTTPS

HTTP sends traffic without TLS encryption. HTTPS encrypts the connection using TLS.

```text
HTTP  -> port 80
HTTPS -> port 443
```

Production APIs should use HTTPS, especially when requests contain login tokens or private data.

## 9. What is ACM?

ACM means AWS Certificate Manager. It creates and manages a TLS certificate for a domain you control.

```text
Certificate for api.example.com
             |
             v
Attached to ALB listener on port 443
```

The browser verifies the certificate and creates an encrypted HTTPS connection with the ALB.

## 10. Where does HTTPS end?

In our simple architecture:

```text
User --HTTPS--> ALB --HTTP--> Nginx --HTTP--> FastAPI
```

The ALB terminates HTTPS. Traffic after the ALB remains inside our VPC.

## 11. Complete request flow

```text
1. User requests https://api.example.com/items.
2. DNS resolves api.example.com to the ALB.
3. The ALB accepts HTTPS using the ACM certificate.
4. The port 443 listener forwards to the target group.
5. The target group selects the healthy production EC2 instance.
6. The ALB sends HTTP to Nginx on EC2 port 80.
7. Nginx proxies the request to FastAPI on port 8000.
8. The response returns through Nginx and the ALB.
```

## Common mistakes

- Pointing the domain directly to a changing EC2 public IP
- Creating a certificate for the wrong domain name
- Creating the certificate in a different Region from the ALB
- Using the wrong target port
- Using a health path that does not return `200`
- Forgetting to allow the ALB security group to reach EC2 port `80`
- Assuming one target provides high availability
