# Lesson 9: Complete architecture and revision

This lesson connects everything from Module 1.

## 1. Development architecture

```text
Your computer
    |
    | HTTP :80, allowed only from your IP
    v
Dev EC2
    |
    v
Nginx :80
    |
    v
FastAPI container :8000
    |                         |
    v                         v
MongoDB Atlas dev DB      Private dev S3 bucket
```

Development uses one EC2 instance and no load balancer initially.

## 2. Production architecture

```text
User
  |
  | https://api.example.com
  v
Route 53 DNS
  |
  v
Application Load Balancer :443
  |  ACM certificate
  |  /health target check
  v
Production EC2 :80
  |
  v
Nginx
  |
  v
FastAPI container :8000
  |                          |
  v                          v
MongoDB Atlas prod DB    Private prod S3 bucket
```

Production has one EC2 target. It is intentionally simple, not highly available.

## 3. What every component does

| Component | Simple responsibility |
|---|---|
| Region | Geographic home of resources |
| Availability Zone | Isolated location inside a Region |
| VPC | Private AWS network |
| Subnet | Smaller network in one AZ |
| Route table | Chooses where network traffic goes |
| Internet gateway | Connects a VPC with the internet |
| Security group | Allows selected network connections |
| IAM role | Gives temporary AWS permissions to EC2 |
| EC2 | Runs our server software |
| EBS | Provides the EC2 disk |
| Docker | Packages and runs FastAPI |
| ECR | Stores Docker images |
| Nginx | Forwards HTTP requests to FastAPI |
| ALB | Public HTTPS endpoint and health checker |
| Route 53 | Maps the domain to the ALB |
| ACM | Supplies the HTTPS certificate |
| S3 | Stores uploaded/generated files |
| MongoDB Atlas | Stores application records |
| Parameter Store | Stores environment configuration |
| CloudWatch | Provides metrics, logs, and alarms |
| Session Manager | Provides controlled EC2 terminal access |

## 4. Complete API request

Suppose a user requests `GET /items`:

```text
1. Route 53 resolves api.example.com to the ALB.
2. The ALB accepts HTTPS using its ACM certificate.
3. The ALB checks that the EC2 target is healthy.
4. The ALB sends HTTP to Nginx on EC2 port 80.
5. Nginx forwards the request to FastAPI on port 8000.
6. FastAPI reads data from MongoDB Atlas.
7. FastAPI creates the response.
8. The response returns through Nginx and the ALB.
```

## 5. Complete file-upload request

```text
1. User asks FastAPI for permission to upload.
2. FastAPI authenticates and authorizes the user.
3. FastAPI uses the EC2 IAM role to create a presigned S3 URL.
4. User uploads the file directly to private S3.
5. FastAPI stores the S3 object key and metadata in MongoDB.
```

No permanent AWS access key is given to the user.

## 6. Dev and prod separation

```text
Development                 Production
-----------                 ----------
Dev EC2                     Prod EC2
Dev IAM role                Prod IAM role
Dev S3 bucket               Prod S3 bucket
Dev Atlas user/database     Prod Atlas user/database
/fastapi/dev/* settings     /fastapi/prod/* settings
```

The Docker image can be the same. Permissions, settings, and data are separate.

## 7. What is public?

```text
Public:
- production ALB ports 80 and 443;
- dev EC2 port 80 only from your IP while learning.

Not directly public:
- production EC2 port 80;
- FastAPI port 8000;
- MongoDB port 27017;
- S3 objects;
- Parameter Store secrets.
```

## 8. What happens when something fails?

### FastAPI container stops

Nginx cannot reach FastAPI, `/health` fails, and the ALB marks the target unhealthy.

### Nginx stops

The ALB cannot reach EC2 port `80`, so the target becomes unhealthy.

### Production EC2 stops

The API becomes unavailable because there is only one production server.

### Atlas connection fails

Routes that need database access fail. Logs should show the connection error.

### IAM role lacks S3 permission

The network call reaches S3, but S3 returns access denied.

## 9. Security rules to remember

1. Do not use the root user for daily work.
2. Enable MFA.
3. Never commit AWS or Atlas credentials.
4. Use IAM roles instead of permanent AWS keys on EC2.
5. Keep S3 Block Public Access enabled.
6. Do not expose FastAPI port `8000`.
7. Do not open SSH port `22` to everyone.
8. Keep dev and prod data separate.
9. Check the selected Region before creating resources.
10. Remove unused billable resources.

## 11. Short answers

1. DNS → ALB → EC2/Nginx → FastAPI.
2. ALB handles public HTTPS and target health; Nginx proxies locally to FastAPI.
3. To obtain limited temporary permissions for S3, ECR, parameters, and logs.
4. Records in MongoDB, files in S3, and server/system files on EBS.
5. An AMI templates an EC2 server; a Docker image packages the application.
6. Its security group allows port `80` only from the ALB security group.
7. In secure external configuration such as Parameter Store `SecureString`.
8. A metric is a number over time, a log is an event record, and an alarm watches a metric condition.
9. With AWS Systems Manager Session Manager.
10. It has only one production EC2 instance.
