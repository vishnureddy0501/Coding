# 2. MongoDB and health checks

## Startup and shutdown

When the container starts:

1. Required environment variables are checked.
2. FastAPI connects to MongoDB Atlas and sends `ping`.
3. The API starts accepting requests.

If MongoDB cannot be reached, startup fails and Docker logs show the reason. During shutdown, the MongoDB client is closed cleanly.

## Two health endpoints

| Endpoint | Checks | Use |
|---|---|---|
| `/health` | FastAPI process is running | Docker and ALB health checks |
| `/ready` | MongoDB is accessible | Deployment verification and diagnosis |

`/health` stays fast and does not ping Atlas every time the load balancer checks the server. `/ready` returns `503` when MongoDB is unavailable.
