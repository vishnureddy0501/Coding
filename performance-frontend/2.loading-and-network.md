# Improving Loading and Network Performance

## 1. Build and inspect the production application

Always test the optimized production build.

For a Vite application:

```bash
npm run build
npm run preview
```

Check the build output for unexpectedly large JavaScript chunks.

## 2. Route-level code splitting

Do not put every page in the initial JavaScript bundle. Load a page when the user visits it.

Vue Router example:

```js
const routes = [
  {
    path: "/reports",
    component: () => import("./views/ReportsPage.vue")
  }
];
```

This creates a separate chunk for `ReportsPage`.

Use it for:

- Pages and routes
- Large modals
- Editors and charts
- Admin-only features
- Features rarely opened

Do not split every tiny component. Too many tiny chunks create extra requests and complexity.

## 3. Lazy-load a heavy component

```js
import { defineAsyncComponent } from "vue";

const AnalyticsChart = defineAsyncComponent(
  () => import("./AnalyticsChart.vue")
);
```

This is useful when a component is below the fold or appears only after user action.

## 4. Run independent API calls in parallel

Slow sequential version:

```js
const account = await getAccount();
const usage = await getUsage();
const tickets = await getTickets();
```

Faster parallel version:

```js
const [account, usage, tickets] = await Promise.all([
  getAccount(),
  getUsage(),
  getTickets()
]);
```

Only use `Promise.all` when the requests do not depend on one another.

## 5. Prevent duplicate requests

In the Network panel, filter by the API name and check whether it fires more than expected.

Typical causes:

- API call exists in more than one lifecycle hook.
- Multiple components request the same shared data.
- A watcher runs immediately and the mounted hook makes the same call.
- A watcher observes a large object and fires for unrelated changes.
- A button can be clicked repeatedly while the request is running.

Possible fixes:

- Keep shared data in one store.
- Cache the loaded result.
- Watch only the required value.
- Disable the submit button while saving.
- Cancel an old search request when a new search starts.

## 6. Debounce search requests

Do not call the API after every keypress.

```js
let timer;

function onSearch(value) {
  clearTimeout(timer);

  timer = setTimeout(() => {
    fetchSearchResults(value);
  }, 300);
}
```

The request runs after the user stops typing for 300 ms.

## 7. Cancel outdated requests

If a user searches for `a`, then quickly searches for `apple`, the first response may arrive last and replace the correct result.

```js
let controller;

async function search(query) {
  controller?.abort();
  controller = new AbortController();

  const response = await fetch(`/api/search?q=${query}`, {
    signal: controller.signal
  });

  return response.json();
}
```

This saves work and prevents stale responses from updating the UI.

## 8. Reduce API response size

Avoid downloading thousands of records when the screen shows only 20.

Use:

- Server-side pagination
- Server-side search, filtering, and sorting
- Only the fields needed by the screen
- Summary endpoints for dashboards
- Compression for text responses

Example:

```text
Bad:  GET /deals → returns 50,000 complete deals
Good: GET /deals?page=1&limit=25&fields=id,name,amount,status
```

## 9. Lazy loading and preloading

### Lazy load

Use when a resource is not needed immediately:

```html
<img src="report.webp" loading="lazy" alt="Report preview">
```

Do not lazy-load the main image visible at the top of the page because that can delay LCP.

### Preload

Use for an important resource that the current page certainly needs early:

```html
<link rel="preload" href="/fonts/app.woff2" as="font" type="font/woff2" crossorigin>
```

Preload only a few critical resources. Incorrect preloading competes with more important downloads.

### Prefetch

Use for a resource likely to be needed on a future page:

```html
<link rel="prefetch" href="/assets/reports-page.js">
```

## 10. Understand the request waterfall

A waterfall like this is slow:

```text
Load user
   ↓
Load account
   ↓
Load dashboard
   ↓
Load chart
```

Remove unnecessary dependencies and start independent work earlier.

## Practical verification

After making a change, compare:

- Initial JavaScript transferred
- Number of requests
- LCP
- API response sizes
- Request waterfall
- Time until the page becomes interactive
