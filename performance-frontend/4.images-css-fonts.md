# Images, CSS, and Font Performance

## 1. Images

Images are often the largest resources on a page.

### Send the correct dimensions

Do not send a 3000-pixel image to display it at 300 pixels. Resize the actual file or let an image CDN generate the correct size.

### Use modern formats

- Use **AVIF** or **WebP** for photos and rich images.
- Use **SVG** for simple icons and logos when appropriate.
- Use PNG only when its lossless quality or transparency is needed.

### Serve responsive images

```html
<img
  src="product-800.webp"
  srcset="product-400.webp 400w, product-800.webp 800w"
  sizes="(max-width: 600px) 400px, 800px"
  width="800"
  height="500"
  alt="Product dashboard"
>
```

The browser selects a suitable file for the screen.

### Prevent layout shift

Always provide image dimensions or an aspect ratio:

```css
.preview {
  aspect-ratio: 16 / 9;
  width: 100%;
}
```

The browser reserves space before the image arrives.

### Handle the LCP image correctly

For the main above-the-fold image:

- Do not use `loading="lazy"`.
- Keep it compressed and correctly sized.
- Make sure it is discoverable in the initial HTML when possible.
- Consider high fetch priority only when it is truly the main image.

For below-the-fold images:

```html
<img src="chart.webp" loading="lazy" alt="Sales chart">
```

## 2. CSS

### Remove unused CSS

Use DevTools Coverage to find large amounts of unused CSS. Then:

- Remove old styles.
- Load feature-specific CSS with that feature.
- Ensure the production build removes unused framework styles safely.

### Avoid overly complex selectors

Prefer simple component classes:

```css
.account-card__title { }
```

Avoid long selectors that tightly depend on page structure:

```css
.dashboard .content .panel ul li div span.title { }
```

### Keep above-the-fold CSS available early

The browser needs CSS before it can correctly render the page. Large blocking stylesheets delay the first display.

Practical fixes:

- Remove unused global CSS.
- Split CSS by route or feature through the build system.
- Avoid loading styles for a large unused component library.

## 3. Fonts

### Use WOFF2

WOFF2 is a compressed web-font format suitable for modern browsers.

### Load only required weights

Do not download every font weight if the application uses only regular and bold.

### Configure font display

```css
@font-face {
  font-family: "AppFont";
  src: url("/fonts/app-regular.woff2") format("woff2");
  font-display: swap;
}
```

`font-display: swap` allows fallback text to appear while the custom font loads.

### Prevent visible movement

Choose a fallback font with similar dimensions to the custom font. A very different fallback can cause text and nearby elements to move when the final font appears.

### Preload only critical fonts

```html
<link
  rel="preload"
  href="/fonts/app-regular.woff2"
  as="font"
  type="font/woff2"
  crossorigin
>
```

Do not preload every font file.

## 4. Third-party scripts

Analytics, chat, advertisements, and support widgets can add network and JavaScript cost.

Use the Network and Performance panels to check their cost.

Possible fixes:

- Remove unused third-party scripts.
- Load non-critical scripts after the main content.
- Load a widget only when the user opens it.
- Use `async` or `defer` correctly for external scripts.
- Review whether the business value justifies the performance cost.

## Practical image investigation

```text
Network → filter Img
  ↓
Sort by Size
  ↓
Open the largest file
  ↓
Compare natural dimensions with displayed dimensions
  ↓
Resize + compress + use a modern format
  ↓
Reload and compare transferred bytes and LCP
```
