# Practical Vue Performance

## 1. Inspect components with Vue Devtools

Use Vue Devtools to inspect:

- Component hierarchy
- Props and state
- Pinia or Vuex changes
- Components created more often than expected

Use Chrome's Performance panel for exact browser timing. Vue Devtools helps identify the Vue component involved.

## 2. Use stable keys in lists

```vue
<AccountRow
  v-for="account in accounts"
  :key="account.id"
  :account="account"
/>
```

Do not use the array index as the key when rows can be inserted, deleted, sorted, or reordered. A stable ID helps Vue correctly reuse components.

## 3. Use computed values for derived state

```js
const activeAccounts = computed(() =>
  accounts.value.filter((account) => account.active)
);
```

A computed value is cached until its dependencies change.

Do not use a computed property for side effects or API requests. Use it to calculate a value.

## 4. Avoid unnecessary deep watchers

This may react to every nested change in a large object:

```js
watch(filters, loadData, { deep: true });
```

Watch only the values that affect the request:

```js
watch(
  () => [filters.status, filters.ownerId],
  loadData
);
```

If the watcher triggers an API call, consider debouncing it.

## 5. Keep props stable

If a parent creates a new object during every render, a child may receive a new reference even when the meaningful values did not change.

Store stable objects in state or derive them with a computed value when appropriate.

Do not blindly add memoization everywhere. First use Vue Devtools and the browser Performance panel to find repeated expensive updates.

## 6. Lazy-load routes and large components

```js
const ReportsPage = () => import("./ReportsPage.vue");
```

Use async components for large optional sections:

```js
const ForecastChart = defineAsyncComponent(
  () => import("./ForecastChart.vue")
);
```

## 7. Virtualize large lists

If a table has thousands of rows, rendering all rows is expensive even if fetching the data is fast.

Use pagination or a Vue-compatible virtual list. Confirm the improvement by checking:

- DOM node count
- Scripting and rendering time
- Scrolling performance

## 8. Keep global state focused

Do not put every temporary UI value into a global store.

- Keep local component state local.
- Store genuinely shared data globally.
- Avoid duplicating the same data in multiple stores.
- Normalize large collections when frequent item lookup is needed.

## 9. Clean up when a component unmounts

```js
onMounted(() => {
  window.addEventListener("resize", handleResize);
});

onUnmounted(() => {
  window.removeEventListener("resize", handleResize);
});
```

Also close timers, observers, subscriptions, and sockets.

## 10. Avoid making everything reactive

Large third-party objects or static configuration may not need Vue's deep reactivity.

Depending on the case, consider:

- Keeping constants outside the component
- `shallowRef` for a large value whose nested fields do not need tracking
- `markRaw` for an object that Vue should not make reactive

Use these only when profiling shows meaningful reactive overhead or when an external object should not be proxied.

## 11. Diagnose a slow Vue screen

```text
Network
  → Is data fetching slow or duplicated?

Chrome Performance
  → Is JavaScript, layout, or paint slow?

Vue Devtools
  → Which component/state change is involved?

Elements/Performance Monitor
  → Are too many DOM nodes being rendered?

Fix one cause
  → Record the same interaction again
```
