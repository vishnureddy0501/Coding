# Fixing Slow JavaScript and Rendering

## Understand the browser's work

The browser roughly performs:

```text
JavaScript
   ↓
Style calculation
   ↓
Layout — calculate sizes and positions
   ↓
Paint — draw pixels
   ↓
Composite — combine visual layers
```

A slow page may have a problem in any of these steps.

## 1. Remove expensive repeated work

Bad example: searching the entire list for every item.

```js
const result = users.map((user) => ({
  ...user,
  team: teams.find((team) => team.id === user.teamId)
}));
```

Create a lookup once:

```js
const teamsById = new Map(
  teams.map((team) => [team.id, team])
);

const result = users.map((user) => ({
  ...user,
  team: teamsById.get(user.teamId)
}));
```

Use DevTools Performance before changing code so you know this work is actually expensive.

## 2. Render fewer DOM elements

Rendering 10,000 rows creates expensive JavaScript, layout, paint, and memory work.

Use:

- Pagination when users work page by page.
- Virtualization when users must scroll through one large list.
- Expand details only when requested.

Virtualization renders only the visible rows plus a small buffer.

```text
Data contains 10,000 rows
Screen shows about 20 rows
DOM contains about 20–40 rows, not 10,000
```

## 3. Avoid layout thrashing

This pattern repeatedly reads layout and changes it:

```js
items.forEach((item) => {
  const width = item.offsetWidth;
  item.style.width = `${width + 10}px`;
});
```

The browser may recalculate layout many times.

Read measurements together, then perform writes together:

```js
const widths = items.map((item) => item.offsetWidth);

items.forEach((item, index) => {
  item.style.width = `${widths[index] + 10}px`;
});
```

Confirm this issue by looking for repeated **Layout** events in the Performance panel.

## 4. Use efficient animations

Prefer:

```css
.card {
  transform: translateX(20px);
  opacity: 0.8;
}
```

Avoid frequently animating layout-related properties such as:

- `width`
- `height`
- `top`
- `left`
- `margin`

`transform` and `opacity` usually require less layout and paint work.

## 5. Debounce and throttle

Use **debounce** when an action should run after events stop.

Example: Wait until the user stops typing before searching.

Use **throttle** when an action may run repeatedly but must be limited.

Example: Process a scroll event at most once every 100 ms.

Do not automatically debounce every interaction. Buttons and important immediate feedback should still respond immediately.

## 6. Break up long tasks

If JavaScript blocks the main thread for a long time, clicks and typing feel delayed.

Possible fixes:

- Process smaller batches.
- Defer non-critical work until after the important UI update.
- Avoid parsing or transforming large datasets in the browser.
- Ask the backend for prepared summaries.
- Move CPU-heavy work to a Web Worker.

## 7. Use a Web Worker for CPU-heavy work

A Web Worker runs JavaScript away from the main UI thread.

Good cases:

- Large calculations
- Parsing very large files
- Heavy data transformations

Not useful for:

- Direct DOM updates
- Small calculations
- Network requests that are already asynchronous

Workers add communication and serialization cost, so measure before using one.

## 8. Prevent memory leaks

Clean up resources created by a component:

```js
const timer = setInterval(refreshData, 5000);

window.addEventListener("resize", handleResize);

onUnmounted(() => {
  clearInterval(timer);
  window.removeEventListener("resize", handleResize);
});
```

Also clean up:

- Subscriptions
- Observers
- WebSocket connections
- Third-party widgets
- Pending requests when appropriate

## 9. Avoid unnecessary work on scroll

Instead of continuously checking element positions during scroll, use `IntersectionObserver` to know when an element enters the viewport.

Useful for:

- Lazy loading
- Infinite scrolling
- Starting animations
- Recording whether content became visible

## How to verify a rendering fix

Record the same interaction before and after. Compare:

- Long-task duration
- Scripting time
- Layout and paint time
- Number of DOM nodes
- Frames per second
- Interaction delay
