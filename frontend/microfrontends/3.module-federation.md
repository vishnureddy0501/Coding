# 3. Webpack Module Federation

Module Federation allows independently built applications to expose and consume modules at runtime.

## Mental model

```text
Host application
   │
   ├── local modules
   └── imports Catalog/ProductList
                  ↑
          catalog remote build
```

Important terms:

- **host**: consumes remote modules;
- **remote**: exposes modules;
- **container**: runtime wrapper around a federated build;
- **remote entry**: manifest-like JavaScript entry for the container;
- **exposes**: modules made available by a remote;
- **remotes**: remote containers known by the host;
- **shared**: dependencies coordinated through a shared scope.

## Remote configuration

Conceptual webpack configuration:

```javascript
import webpack from "webpack";

const { ModuleFederationPlugin } = webpack.container;

export default {
  output: {
    publicPath: "auto",
    uniqueName: "catalog",
  },
  plugins: [
    new ModuleFederationPlugin({
      name: "catalog",
      filename: "remoteEntry.js",
      exposes: {
        "./ProductList": "./src/components/ProductList.vue",
      },
      shared: {
        vue: {
          singleton: true,
          requiredVersion: "^3.5.0",
        },
      },
    }),
  ],
};
```

- `name` identifies the remote container.
- `filename` is the container entry emitted by the build.
- `exposes` maps public module names to internal files.
- `publicPath: "auto"` lets webpack infer where remote chunks are hosted.
- `uniqueName` prevents webpack runtime collisions between builds.

## Host configuration

```javascript
new ModuleFederationPlugin({
  name: "shell",
  remotes: {
    catalog: "catalog@https://catalog.example.com/remoteEntry.js",
  },
  shared: {
    vue: {
      singleton: true,
      requiredVersion: "^3.5.0",
    },
  },
});
```

The host can dynamically import the exposed module:

```javascript
const ProductList = () => import("catalog/ProductList");
```

Remote loading is asynchronous because the browser may need to download both `remoteEntry.js` and an additional exposed-module chunk.

## Vue lazy component

```javascript
import { defineAsyncComponent } from "vue";

export const ProductList = defineAsyncComponent({
  loader: () => import("catalog/ProductList"),
  loadingComponent: LoadingView,
  errorComponent: RemoteUnavailable,
  timeout: 10_000,
});
```

This makes loading and failure states explicit.

## Shared dependencies

Without sharing, the host and each remote may download their own Vue copy.

With `shared`, builds register available dependency versions into a runtime share scope. Consumers select a compatible version.

Important options:

- `singleton: true`: only one active version should be used;
- `requiredVersion`: compatible semantic-version range;
- `eager: true`: include synchronously instead of a separate async chunk—use cautiously because it can increase initial bundles.

Share Vue as a singleton when Vue objects cross application boundaries. Do not blindly make every library a singleton.

## Runtime loading flow

```text
1. Browser loads the host
2. Host loads the remote container entry
3. Host and remote initialize the shared dependency scope
4. Host asks the container for an exposed module
5. Webpack downloads the necessary remote chunk
6. Vue evaluates and renders the component
```

Module Federation shares code, not application ownership rules. Teams still need stable contracts, version compatibility, monitoring and deployment coordination.

## Common errors

### Remote entry cannot be loaded

Check URL, deployment, CORS, HTTPS and Content Security Policy.

### Module does not exist in container

The import name must exactly match the key under `exposes`:

```text
exposes: "./ProductList"
import:  "catalog/ProductList"
```

### Shared module is unavailable for eager consumption

Federated initialization often needs an asynchronous boundary. A common structure is:

```javascript
// index.js
import("./bootstrap");
```

The application starts inside `bootstrap.js`. This gives webpack time to initialize remote and shared modules.

### Duplicate Vue instances

Verify that Vue is configured as a compatible singleton in host and remotes. Also inspect lockfiles for incompatible versions.

### Old page requests deleted chunks

A browser running an older host may request old remote chunks after a new deployment. Use content hashes and retain older assets for a safe period.

## What to say in an interview

> Module Federation lets separate webpack builds expose and consume modules at runtime. A remote publishes a container entry and exposed modules; the host loads that container and imports those modules asynchronously. Shared scopes can prevent duplicate framework copies, but version compatibility and singleton usage must be managed carefully. It enables independent deployment but introduces runtime network, contract and observability concerns.
