# DOM — Interview Notes

## 1. What is the DOM?

DOM stands for **Document Object Model**.

When a browser receives HTML, it converts it into a tree of objects. This tree is the DOM.

JavaScript uses the DOM to read and change the page. It can change content and styles and add or remove elements.

### Important interview point

The DOM is **not part of JavaScript**. It is a Web API provided by the browser.

## 2. Real DOM

The **real DOM** is the actual document tree maintained by the browser. It represents the page currently being displayed.

After a DOM change, the browser may need to:

1. Update the DOM tree.
2. Recalculate affected CSS styles.
3. Recalculate element sizes and positions.
4. Paint the changed pixels.
5. Combine visual layers on the screen.

Real DOM updates are not automatically slow. A few small changes are normally inexpensive. Problems occur when an application makes many unnecessary changes or repeatedly forces layout calculation.

## 3. Virtual DOM

The **virtual DOM** is a lightweight JavaScript representation of the UI. Frameworks such as Vue use it to determine how the real DOM should change.

The general process is:

1. Application state changes.
2. The framework creates a new virtual DOM representation.
3. It compares the new representation with the previous one.
4. It finds what changed.
5. It updates the required parts of the real DOM.

Comparing the representations is called **diffing**. Applying the changes is called **patching** or **reconciliation**.

| Real DOM | Virtual DOM |
|---|---|
| Maintained by the browser | Maintained by a framework |
| Represents the actual webpage | Represents the desired UI in memory |
| Directly affects the screen | Helps decide which real DOM updates are needed |
| Used by normal webpages | Used by frameworks that implement it |

The virtual DOM does not replace the real DOM. Only the real DOM can be displayed by the browser.

### Is the virtual DOM always faster?

No. A small direct DOM update may be faster. The virtual DOM is useful because it makes complex interfaces easier to manage and helps frameworks group updates efficiently.

## 4. Browser rendering terms

### Style calculation

The browser determines which CSS rules apply to each element.

### Layout or reflow

The browser calculates element sizes and positions.

### Paint

The browser draws visual details such as text, colors, borders, and shadows.

### Composite

The browser combines visual layers to produce the final screen.

Repeatedly changing the DOM and forcing layout calculations between changes is called **layout thrashing**. It can create performance problems.

## 5. Shadow DOM

The **Shadow DOM** creates an isolated DOM tree inside an element. Web Components commonly use it.

Its purpose is encapsulation:

- Internal markup is separated from the main document.
- Component styles can be isolated.
- Page styles are less likely to affect the component accidentally.

For most interviews, understanding component and style isolation is sufficient.

## 6. DOM collections

DOM APIs sometimes return collections:

- **NodeList:** a collection of nodes
- **HTMLCollection:** a collection containing only elements

Some collections are **live**, meaning they update automatically when the DOM changes. Others are **static**, meaning they remain a snapshot of the original result.

This matters when elements are added or removed while a collection is being used.

## 7. DOM security and XSS

DOM-based XSS can happen when an application places untrusted data into the page and the browser treats it as executable HTML or JavaScript.

The main rule is:

> Treat user-provided content as text, not HTML.

If the application genuinely needs to accept HTML, sanitize it with a trusted sanitizer. Client-side validation alone cannot enforce security or authorization.

## 8. DOM and Vue.js

Vue normally manages DOM updates:

~~~text
Reactive state changes
        ↓
Vue updates its virtual DOM
        ↓
Vue patches the real DOM
~~~

Normally change reactive state instead of directly changing DOM content controlled by Vue. A manual DOM update could make the real DOM disagree with Vue's expected state.

Direct DOM access is still useful for:

- Focusing an input
- Measuring an element
- Integrating a third-party DOM library
- Working with canvas, audio, or video

Vue provides template references for controlled access in these situations.

## Important comparison

| Real DOM | Virtual DOM |
|---|---|
| Browser's actual document tree | Framework's in-memory representation |
| Produces the displayed page | Helps calculate required updates |
| Must eventually be updated | Cannot display anything by itself |

## Common interview questions

### What is the DOM?

It is the browser's tree of objects representing the current HTML document. It allows scripts to read and modify the page.

### Is the DOM the same as HTML?

No. HTML is the source markup. The DOM is the current object tree created from it. JavaScript and browser corrections can make the DOM different from the original HTML.

### Why can frequent DOM manipulation be slow?

Changes may cause style calculation, layout, paint, and compositing. Unnecessary changes can make the browser repeat this work.

### Why does Vue use a virtual DOM?

It gives Vue a declarative way to compare UI states and apply required changes to the real DOM.

### Is the virtual DOM always faster?

No. Direct updates may be faster for simple cases. The virtual DOM mainly improves maintainability and provides efficient general-purpose UI updates.
