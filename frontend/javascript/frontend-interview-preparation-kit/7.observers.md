# Browser Observers — Simple Interview Notes

## What is an observer?

An observer lets us tell the browser:

> Watch this element. Notify me when something important changes.

> clean up the observers in beforeDestroy.

Without an observer, our JavaScript might need to check an element repeatedly:

```text
Is it visible now?
Is it visible now?
Did its size change?
Was a child added?
```

Repeated checking is difficult and can waste browser resources. An observer allows the browser to notify us only when the relevant change happens.

The three important observers are:

| Observer | Watches for |
|---|---|
| Intersection Observer | An element entering or leaving a visible area |
| Mutation Observer | The DOM structure or attributes changing |
| Resize Observer | An element's size changing |

## 1. Intersection Observer

### What does it observe?

Intersection Observer checks whether an element is entering or leaving.

### Why do we need it?

Before Intersection Observer, developers often listened to every scroll event and repeatedly calculated element positions.

```text
User scrolls
    ↓
Run JavaScript repeatedly
    ↓
Calculate the element's position repeatedly
```

This can be inefficient because scrolling may produce many events in a short time.

Intersection Observer allows the browser to track visibility efficiently and notify the application when a chosen visibility point is crossed.

### Common use cases

- **Lazy loading:** load an image shortly before it reaches the screen.
- **Infinite scrolling:** load more products when the last item becomes visible.
- **Animations:** begin an animation when a section enters the screen.
- **Pause work:** stop a video or animation when it leaves the screen.

### Important concepts


#### Threshold

The **threshold** controls how much of the target must be visible before we are notified.

```text
0% threshold   → notify when any part starts appearing
50% threshold  → notify when half is visible
100% threshold → notify when the whole element is visible
```

#### Root margin

The **root margin** makes the observed area larger or smaller.

For lazy loading, we may make it larger so an image starts downloading shortly **before** the user reaches it.

### Important limitation

Intersection Observer tells us whether element rectangles overlap. It does not always prove that the user can genuinely see the element. Another element might cover it, or CSS may make it transparent.

## 2. Mutation Observer

### What does it observe?

Mutation Observer watches for changes to the DOM.

It can notify us when:

- An element is added
- An element is removed
- An attribute changes
- Text changes
- Something changes inside an observed subtree

In simple words, it answers:

> Did the page's DOM structure or content change?

### Why do we need it?

Sometimes our code does not control the part of the page that changes.

For example:

- A third-party chat tool adds an element.
- A browser extension changes the page.
- An older library inserts content.
- An external widget changes an attribute.

Instead of checking the DOM repeatedly, Mutation Observer notifies us when the selected change happens.

### Common use cases

- Detecting content added by a third-party widget
- Watching an external library modify the DOM
- Responding when an attribute or class changes outside our code
- Building developer tools or browser extensions
- Connecting to dynamically inserted elements that we do not control

### What is a mutation?

A mutation simply means a change to the DOM. It does not mean that something is harmful.

Common mutation types are:

- **Child-list mutation:** child nodes were added or removed.
- **Attribute mutation:** an attribute such as `class` changed.
- **Character-data mutation:** text inside a text node changed.


### Interview answer

> Mutation Observer notifies us when the DOM structure, attributes, or text changes. 

## 3. Resize Observer

### What does it observe?

Resize Observer notifies us when a particular element's dimensions change.

In simple words, it answers:

> Did this element become wider, narrower, taller, or shorter?

### Why do we need it?

The window resize event tells us when the browser window changes size. It does not tell us whenever an individual element changes size.

An element can resize even when the window does not:

- A sidebar opens.
- New text is added.
- A parent layout changes.
- A panel is dragged.
- Data loads into a chart.
- Another element disappears and frees space.

Resize Observer watches the actual element, regardless of what caused its size to change.

### Common use cases

- Resize a chart when its container changes.
- Adjust a canvas to match its displayed size.
- Change a component layout based on available space.
- Recalculate a virtualized list.
- Reposition content when a panel changes size.
- Adapt a reusable component placed in different containers.

### Resize Observer versus media queries

| Media query | Resize Observer |
|---|---|
| Responds mainly to viewport characteristics | Responds to one element's size |
| Best for page-level responsive CSS | Useful when JavaScript needs the element's dimensions |
| Uses CSS | Uses JavaScript notification |

CSS container queries can handle many component-layout cases without JavaScript. Prefer CSS when the requirement is purely visual. Use Resize Observer when JavaScript genuinely needs to react to the new dimensions.

### Performance warning

Changing the observed element's size while responding to its size change can create a loop:

```text
Size changes
    ↓
Observer responds and changes size again
    ↓
Observer responds again
```

Avoid unnecessary size changes inside the response. Keep the work small because it can delay rendering.

### Interview answer

> Resize Observer tells us when an individual element changes size. It is useful for charts, canvases, resizable panels, and components whose layout depends on their container rather than the browser window.


## Common confusion

### Intersection Observer versus scroll event

Use Intersection Observer when you care about whether an element has entered or left an area. Use a scroll event when you genuinely need the exact scroll position or must react continuously to scrolling.

### Mutation Observer versus event listener

An event listener watches for events such as clicks and input. Mutation Observer watches for changes to the DOM tree. Adding an element to the page is a mutation, not a user event.

### Resize Observer versus window resize

The window resize event watches the browser window. Resize Observer watches a chosen element, even if the browser window did not change.


## Interview scenarios

### Load the next page in an infinite product list

Observe a small marker at the bottom of the list with Intersection Observer. When it becomes visible, request the next page.

### Update a chart when its card becomes narrower

Use Resize Observer because the card can resize without the browser window resizing.

### Detect when a third-party library adds a popup

Use Mutation Observer because external code is changing the DOM structure.


## Final revision

```text
Observer             → browser notifies us when something changes

IntersectionObserver → visibility or intersection changed
                       Lazy loading, infinite scroll, analytics

MutationObserver     → DOM structure, attribute, or text changed
                       Third-party and external DOM changes

ResizeObserver       → an element's size changed
                       Charts, containers, resizable components

Cleanup              → unobserve or disconnect when finished
```
