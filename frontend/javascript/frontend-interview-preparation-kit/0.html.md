## 1. Semantic HTML
choosing html tags based on its **meaning** 

| Element | Meaning |
|---|---|
| `<header>` | Introduction for a page or section |
| `<nav>` | Major navigation links |
| `<main>` | Main page content; normally one per page |
| `<section>` | Related content, usually with a heading |
| `<article>` | Independent content such as a post |
| `<aside>` | Secondary related content |
| `<footer>` | Footer for a page or section |

Semantic HTML helps screen readers, search engines, browsers, and developers understand the page. Use `<div>` and `<span>` only when no meaningful element fits.


A `<button>` already works with the mouse, keyboard, and screen readers. Users can reach it with the Tab key and activate it with Enter or Space.

A `<div>` is only a container. Making it clickable with JavaScript does not automatically give it these button behaviors. You would have to implement them yourself, so use a real `<button>` whenever the user is performing an action.


## 4. What is an iframe?

An `<iframe>` displays another webpage inside your webpage. Think of it as a small browser window inside the page.

Common examples are:

- YouTube players
- Maps
- Payment pages
- Support widgets
- Separately hosted applications

The iframe has its own HTML, CSS, JavaScript, and browsing context.

## 5. Why are iframes often not preferred?

Iframes are not always bad, but they have costs:

- **Performance:** they may load another complete application with more scripts and requests.
- **Styling:** the parent usually cannot style a cross-origin iframe's content.
- **Communication:** the iframe does not share Vue state; controlled messaging is required.
- **Security:** third-party content runs inside the embedded page and needs restrictions.
- **SEO:** important iframe content belongs to a separate document.

## 6. When is an iframe appropriate?

Use it when you intentionally need an **isolated external webpage**, such as:

- A trusted payment flow
- A map or video player
- A third-party widget without a suitable API
- An independently deployed application that requires isolation

Avoid it for content that belongs to your normal Vue application.


## 8. Making an iframe safer

When an iframe is required:

- Embed only trusted sources.
- Give it a descriptive `title`.
- Use `sandbox` to limit its capabilities.
- Grant only required permissions through `allow`.
- Lazy-load it if it is below the visible screen.
- Define its dimensions to prevent layout shifts.
- When messaging between windows, verify the sender and origin.


## Interview answers


### Why can an iframe be problematic?

It loads a separate document and adds performance, styling, communication, security, accessibility, and responsive-design concerns.

### When should we use an iframe?

When an isolated external webpage must be embedded, such as a payment page, map, video player, or third-party application.

### What should we use for our own application content?

A framework component. For external data, use the service's API and render it through the application when possible.
