# JavaScript Prototypes

## What is a prototype?

A **prototype** is an object from which another JavaScript object can access properties and methods.

Consider an array:

```js
const numbers = [1, 2, 3];

numbers.map((number) => number * 2);
```

We did not create a `map` function inside `numbers`. JavaScript gets it from:

```js
Array.prototype
```

In simple words:

> Every array can use methods stored in `Array.prototype`.

## Why do we need prototypes?

Suppose we create several arrays:

```js
const first = [1, 2];
const second = [3, 4];
```

JavaScript does not need to create a separate `map` function for each array. Both arrays share the same function from `Array.prototype`.

This saves memory and allows all objects of the same type to share methods.

## Prototype chain

When we request a property or method, JavaScript searches for it in this order:

```text
The object itself
       ↓ not found
Its prototype
       ↓ not found
The prototype's prototype
       ↓
null — stop searching
```

For an array, the chain looks like this:

```text
numbers
   ↓
Array.prototype
   ↓
Object.prototype
   ↓
null
```

Example:

```js
numbers.map(...);
```

JavaScript checks:

1. Is `map` directly available on `numbers`? No.
2. Is `map` available on `Array.prototype`? Yes.
3. Use that method.

This search is called the **prototype chain**.

## Simple custom method

We can add a shared method to `Array.prototype`:

```js
Array.prototype.firstItem = function () {
  return this[0];
};
```

Now every array can access it:

```js
const names = ["Ram", "Sam"];

console.log(names.firstItem()); // "Ram"
```

Here, `this` means the array that called the method:

```text
names.firstItem()
  ↓
this is names
```

Normally, avoid changing built-in prototypes in application code because your method could conflict with existing or future JavaScript methods. It is mainly useful here for understanding prototypes and polyfills.

## How this relates to a polyfill

A polyfill provides a feature when an older environment does not support it.

For example, a simplified `map` polyfill can be added to `Array.prototype`:

```js
if (!Array.prototype.myMap) {
  Array.prototype.myMap = function (callback) {
    const result = [];

    for (let i = 0; i < this.length; i++) {
      result.push(callback(this[i], i, this));
    }

    return result;
  };
}
```

It can then be used by any array:

```js
const result = [1, 2, 3].myMap((number) => number * 2);

console.log(result); // [2, 4, 6]
```

## Objects also have prototypes

```js
const user = {
  name: "Vishnu"
};

user.toString();
```

We did not create `toString` inside `user`. JavaScript finds it in `Object.prototype`.

```text
user
  ↓
Object.prototype
  ↓
null
```

## Classes use prototypes internally

```js
class User {
  constructor(name) {
    this.name = name;
  }

  sayHello() {
    return `Hello, ${this.name}`;
  }
}
```

The `sayHello` method is stored in `User.prototype`. All `User` objects share the same method.

You do not need to manually use prototypes when writing a class, but JavaScript uses prototypes internally.

## Important terms

### Own property

A property that exists directly on the object:

```js
const user = { name: "Vishnu" };
```

`name` is an own property of `user`.

### Inherited property or method

A property or method found through the prototype chain.

For an array, `map` is inherited from `Array.prototype`.

### Prototype chain

The sequence of objects JavaScript searches when a property is not found directly on an object.

## Interview answer

> A prototype is an object from which another JavaScript object can access properties and methods. When a method is not found directly on an object, JavaScript searches for it through the prototype chain. For example, arrays get methods such as `map` from `Array.prototype`. These shared methods do not have to be recreated for every array, which saves memory.

## Easiest way to remember

```text
Object does not have the method
              ↓
JavaScript checks its prototype
              ↓
If it is found, JavaScript uses it
```
