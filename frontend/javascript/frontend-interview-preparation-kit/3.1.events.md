# JavaScript Events — Interview Notes

## 1. Events and event listeners

An **event** is a notification that something happened in the browser.

Common examples include:

- A click
- Keyboard input
- A form submission
- Mouse movement
- Page loading
- Window resizing

An **event listener** waits for a particular event on an element. When the event occurs, its handler runs.

## 2. Event propagation

When an event occurs on a nested element, it travels through the DOM tree. This is called **event propagation**.

Propagation has three phases:

~~~text
1. Capturing phase: ancestors → target
2. Target phase: event reaches the target
3. Bubbling phase: target → ancestors
~~~

Imagine a button inside a card:

~~~text
Body
└── Card
    └── Button
~~~

When the button is clicked:

~~~text
Capturing: Body → Card → Button
Target:    Button
Bubbling:  Button → Card → Body
~~~

## 3. Event capturing

During **capturing**, the event travels from the top of the DOM tree toward the target.

Capturing is useful when a parent must observe an event before the target handles it. Most application event handling uses bubbling, so capturing is less commonly used directly.

Capturing is also called the **trickling phase**.

### Vue capturing example

Vue's .capture modifier registers the parent's listener for the capturing phase.

~~~vue
<script setup>
function handleCardCapture() {
  console.log("1. Card capture")
}

function handleButtonClick() {
  console.log("2. Button click")
}
</script>

<template>
  <div class="card" @click.capture="handleCardCapture">
    <button @click="handleButtonClick">
      Buy
    </button>
  </div>
</template>
~~~

Clicking the button prints:

~~~text
1. Card capture
2. Button click
~~~

The card runs first because its listener is handling the event while it travels toward the button.

## 4. Event bubbling

During **bubbling**, the event travels from the target upward through its ancestors.

For example, clicking a button inside a card can first run the button's listener and then the card's listener.

Many common events bubble, including click and keyboard events. Some events do not bubble.

### Vue bubbling example

Vue uses bubbling by default when we use @click without the .capture modifier.

~~~vue
<script setup>
function handleButtonClick() {
  console.log("1. Button click")
}

function handleCardClick() {
  console.log("2. Card click")
}
</script>

<template>
  <div class="card" @click="handleCardClick">
    <button @click="handleButtonClick">
      Buy
    </button>
  </div>
</template>
~~~

Clicking the button prints:

~~~text
1. Button click
2. Card click
~~~

The event starts on the button and then bubbles to the card.

If the button uses @click.stop, Vue calls stopPropagation(), so the card's listener does not run.

## 5. Event delegation

**Event delegation** means placing one listener on a parent instead of separate listeners on every child.

When a child produces an event, it bubbles to the parent. The parent identifies which child caused it and performs the correct action.

~~~text
Product list — one listener
├── Product 1 button
├── Product 2 button
└── Product 3 button
~~~

### Benefits

- Uses fewer listeners
- Works well for large lists
- Handles children added later
- Keeps related behavior in one place

The original target may be an icon inside a button. The parent should therefore find the intended matching element instead of assuming the exact clicked node is the button.

Event delegation requires an event that bubbles.

### Vue delegation example

The parent has one click listener. The three buttons have no individual listeners.

~~~vue
<script setup>
function handleClick(event) {
  if (event.target.tagName === "BUTTON") {
    console.log("Clicked:", event.target.textContent)
  }
}
</script>

<template>
  <div @click="handleClick">
    <button>Phone</button>
    <button>Laptop</button>
    <button>Headphones</button>
  </div>
</template>
~~~

The flow is:

~~~text
User clicks the Laptop button
              ↓
Click bubbles to the parent div
              ↓
The parent's handleClick function runs
              ↓
It prints "Laptop"
~~~

event.target is the button that was clicked. The parent div handles the event because the click bubbles upward.

In a normal Vue list, putting @click on each button is usually clear and perfectly acceptable. Event delegation is most useful for very large lists, DOM created outside Vue, or places where one parent handler is intentionally preferred.

## 6. Target versus current target

- **target:** the element where the event originally happened
- **currentTarget:** the element whose listener is currently running

With event delegation, target may be a child button while currentTarget is the parent list containing the listener.

## 7. Preventing default versus stopping propagation

Some events have normal browser behavior:

- A link navigates to another page.
- A form submission may reload the page.

**preventDefault** stops the browser's normal action.

**stopPropagation** stops the event from continuing through the DOM tree.

| preventDefault | stopPropagation |
|---|---|
| Stops normal browser behavior | Stops event movement |
| Does not stop bubbling | Does not stop the default action |

Use stopPropagation carefully because another part of the application may depend on bubbling.

## 8. Events and Shadow DOM

Events can cross a Shadow DOM boundary only when configured to do so.

When an event crosses that boundary, the visible target may be changed to the custom element instead of exposing an internal element. This is called **event retargeting**.

## Common interview questions


### What is the difference between preventDefault and stopPropagation?

preventDefault stops the browser's normal action. stopPropagation stops the event from moving through the DOM tree.

## Quick revision

~~~text
Event listener   → reacts to a browser event
Propagation      → event travels through the DOM tree
Capturing        → ancestors to target
Target phase     → event reaches the target
Bubbling         → target to ancestors
Event delegation → parent handles child events
preventDefault   → stops normal browser behavior
stopPropagation  → stops event movement
~~~
