# JavaScript — Important Interview Topics

## 1. How JavaScript works

The JavaScript engine reads, prepares, and executes JavaScript code.

JavaScript runs one piece of JavaScript at a time on the main thread. The browser provides extra features such as timers, Fetch, and DOM events.

~~~text
JavaScript engine → executes JavaScript code
Browser Web APIs  → handle timers, network, and DOM events
Event loop        → schedules asynchronous callbacks
~~~

Long-running JavaScript can block clicks and rendering because the main thread is busy.

## 2. Execution Context

An **execution context** is the environment created to run JavaScript code.

It contains:

- Variables and functions
- The scope chain
- The value of this
- Information about the currently executing code

JavaScript creates:

- One global execution context
- A new function execution context for every function call

Execution happens in two simple phases:

### Creation phase

JavaScript prepares variables, functions, scope, and this.

### Execution phase

JavaScript runs statements and assigns values.

Active execution contexts are stored in the call stack.

## 3. Illegal shadowing

**Shadowing** means an inner variable uses the same name as an outer variable.

~~~js
let value = 10

function show() {
  let value = 20
  console.log(value) // 20
}
~~~

This is valid. The inner value temporarily hides the outer value.

**Illegal shadowing** happens when declarations with the same name conflict.

~~~js
let value = 10

{
  var value = 20 // SyntaxError
}
~~~

var is function-scoped, so it tries to enter the same wider scope where value was already declared with let.

Remember:

~~~text
Inner let can shadow outer var → valid
Inner var cannot cross and redeclare outer let/const → illegal
~~~

## 4. Mutable and immutable data types

### Immutable

Primitive values cannot be changed internally:

- String
- Number
- Boolean
- BigInt
- Symbol
- undefined
- null

~~~js
let name = "Vishnu"
name.toUpperCase()

console.log(name) // "Vishnu"
~~~

The method creates a new string; it does not change the original string.

### Mutable

Objects and arrays can be changed after creation.

~~~js
const user = { name: "Vishnu" }
user.name = "Shivam"
~~~

const prevents variable reassignment. It does not make the object immutable.

## 5. Critical Rendering Path

The Critical Rendering Path means:

~~~text
The steps a browser follows to turn HTML and CSS
into the webpage visible on the screen.
~~~

### Simple flow

~~~text
1. Read HTML → DOM
2. Read CSS  → understand how elements should look
3. Layout    → calculate their size and position
4. Paint     → draw them on the screen
~~~


The browser internally calls the HTML structure the **DOM** and the CSS information the **CSSOM**. You only need to remember:

~~~text
HTML structure + CSS styles → layout → visible pixels
~~~

## 6. this keyword

this refers to the object connected to the current function call.

For a normal function, this depends mainly on **how the function is called**.

~~~js
const user = {
  name: "Vishnu",
  showName() {
    console.log(this.name)
  }
}

user.showName() // this is user
~~~

Common rules:

~~~text
object.method()  → this is the object
fn.call(object)  → this is the supplied object
new Fn()         → this is the new object
plain fn()       → undefined in strict mode
~~~

## 7. Arrow functions and this

An arrow function does not create its own this.

It takes this from the surrounding scope. This is called **lexical this**.

~~~js
const user = {
  name: "Vishnu",

  showLater() {
    setTimeout(() => {
      console.log(this.name)
    }, 1000)
  }
}
~~~

The arrow function uses this from showLater(), so it can access user.name.

Do not use an arrow function as an object method when the method needs its own dynamic this:

~~~js
const user = {
  name: "Vishnu",
  showName: () => console.log(this.name) // Not user
}
~~~

call, apply, and bind cannot change an arrow function's this.

## 8. call, apply, and bind

These methods control this for normal functions.

~~~js
function introduce(city, country) {
  console.log(this.name, city, country)
}

const user = { name: "Vishnu" }
~~~

### call

Runs the function immediately. Arguments are passed separately.

~~~js
introduce.call(user, "Delhi", "India")
~~~

### apply

Runs the function immediately. Arguments are passed as an array.

~~~js
introduce.apply(user, ["Delhi", "India"])
~~~

### bind

Returns a new function that can run later.

~~~js
const boundFunction = introduce.bind(user, "Delhi")
boundFunction("India")
~~~

~~~text
call  → run now, separate arguments
apply → run now, argument array
bind  → return a function for later
~~~

## 9. Callbacks and Callback Hell

### What is a callback?

A callback is a function passed to another function so it can be called when needed.

~~~js
function greet(name, callback) {
  console.log("Hello", name)
  callback()
}

function sayGoodbye() {
  console.log("Goodbye")
}

greet("Vishnu", sayGoodbye)
~~~

### Passing versus calling a callback

~~~js
greet("Vishnu", sayGoodbye)   // Pass the function
greet("Vishnu", sayGoodbye()) // Call it immediately and pass its result
~~~

Normally, a callback should be passed without parentheses.

### Synchronous callback

A synchronous callback runs during the current JavaScript execution.

~~~js
const numbers = [1, 2, 3]

numbers.forEach((number) => {
  console.log(number)
})

console.log("Finished")
~~~

Output:

~~~text
1
2
3
Finished
~~~

The forEach callback runs immediately for every item.

### Asynchronous callback

An asynchronous callback runs later, after an operation or event completes.

~~~js
console.log("Start")

setTimeout(() => {
  console.log("Timer finished")
}, 1000)

console.log("End")
~~~

Output:

~~~text
Start
End
Timer finished
~~~

The browser handles the timer and schedules its callback for later.

Important:

> A callback is not automatically asynchronous. forEach uses synchronous callbacks, while timers and events use asynchronous callbacks.

### Callback with a result

The callback can receive data:

~~~js
function add(a, b, callback) {
  const result = a + b
  callback(result)
}

add(10, 20, (result) => {
  console.log(result) // 30
})
~~~

### What is callback hell?

Callback hell happens when several dependent asynchronous operations are nested inside each other.

~~~js
getUser((user) => {
  getOrders(user.id, (orders) => {
    getPayment(orders[0].id, (payment) => {
      console.log(payment)
    })
  })
})
~~~

The order is:

~~~text
Get user
   ↓
Get that user's orders
   ↓
Get the first order's payment
~~~

Each operation depends on the previous result, so every callback is placed inside the previous callback.

### Why is callback hell a problem?

- The code becomes deeply nested.
- The execution order is difficult to follow.
- Every level may need separate error handling.
- Adding more steps makes maintenance difficult.
- The code keeps moving toward the right.

This shape is sometimes called the **Pyramid of Doom**.

### The same flow with Promise chaining

~~~js
getUser()
  .then((user) => getOrders(user.id))
  .then((orders) => getPayment(orders[0].id))
  .then((payment) => console.log(payment))
  .catch((error) => console.log(error))
~~~

The steps remain in one readable chain, and one catch can handle errors from the chain.

### The same flow with async/await

~~~js
async function showPayment() {
  try {
    const user = await getUser()
    const orders = await getOrders(user.id)
    const payment = await getPayment(orders[0].id)

    console.log(payment)
  } catch (error) {
    console.log(error)
  }
}
~~~

async/await is built on Promises. It makes asynchronous code look similar to normal sequential code.

### Callback interview answer

> A callback is a function passed to another function to be called later or when needed. Callbacks can be synchronous or asynchronous. Deeply nesting dependent asynchronous callbacks creates callback hell, which Promises and async/await make easier to read and handle.

## 10. Prototype and prototypal inheritance

Every normal JavaScript object can have another object as its prototype.

If a property is not found on the object, JavaScript looks in its prototype.

~~~text
Current object
    ↓ not found
Its prototype
    ↓ not found
Prototype's prototype
    ↓
null
~~~

This lookup path is the **prototype chain**.

~~~js
const animal = {
  eat() {
    console.log("Eating")
  }
}

const dog = Object.create(animal)
dog.bark = () => console.log("Barking")

dog.eat() // Found in animal
~~~

JavaScript class syntax also uses prototypes internally.

## 11. Memoisation

Memoisation means saving a function result and reusing it when the same input appears again.

eg: fibanacci in DP.

## 12. Generator functions

A generator function can pause and later continue from the same place.

It uses function* and yield.

~~~js
function* numbers() {
  yield 1
  yield 2
  yield 3
}

const generator = numbers()

console.log(generator.next()) // { value: 1, done: false }
console.log(generator.next()) // { value: 2, done: false }
console.log(generator.next()) // { value: 3, done: false }
console.log(generator.next()) // { value: undefined, done: true }
~~~

Calling a generator does not run its body immediately. next() runs it until the next yield.

Generators are useful for custom iterators, lazy values, and step-by-step processing.

## 13. async and defer

A normal external script can stop HTML parsing while it downloads and runs.

Both async and defer allow downloading while HTML parsing continues.

| defer | async |
|---|---|
| Runs after HTML parsing | Runs as soon as downloaded |
| Preserves script order | Order is not guaranteed |
| Good for application scripts | Good for independent scripts |

~~~html
<script src="app.js" defer></script>
<script src="analytics.js" async></script>
~~~

Module scripts are deferred by default.

## 14. Polyfills

A **polyfill** is our own implementation of a feature that the environment does not support.

For example, imagine an old browser does not have Array.prototype.forEach. We can create myForEach and use it in a similar way.

~~~text
Native method missing
        ↓
We write a similar method
        ↓
Old environment can use that behavior
~~~

In interviews, polyfills are mainly used to test whether you understand how a method works internally.

The examples below are intentionally simple learning versions. Native methods handle more edge cases.

### One important idea: what does this mean?

When we write a method on Function.prototype:

~~~js
Function.prototype.myCall = function () {
  console.log(this)
}

function greet() {}
greet.myCall()
~~~

Inside myCall, this is greet—the function on which myCall was called.

Similarly, inside an Array prototype method, this is the array:

~~~js
const numbers = [10, 20, 30]
numbers.myForEach(...)

// Inside myForEach:
// this means numbers
~~~

Understanding this makes the polyfills much easier.

### 1. call polyfill

Normal usage:

~~~js
function introduce(city) {
  console.log(this.name, city)
}

const user = { name: "Vishnu" }

introduce.call(user, "Delhi")
~~~

call makes introduce behave temporarily like a method of user:

~~~js
user.temporaryFunction = introduce
user.temporaryFunction("Delhi")
delete user.temporaryFunction
~~~

Our simplified polyfill does the same:

~~~js
Function.prototype.myCall = function (context, ...args) {
  const temporaryKey = Symbol()

  context[temporaryKey] = this
  const result = context[temporaryKey](...args)
  delete context[temporaryKey]

  return result
}
~~~

Usage:

~~~js
introduce.myCall(user, "Delhi")
~~~

Step by step:

~~~text
this                   → introduce function
context                → user object
context[temporaryKey]  → temporarily stores introduce
context[temporaryKey]()→ runs introduce with this = user
delete                 → removes the temporary property
~~~

Symbol creates a unique property name so an existing property is not overwritten.

### 2. apply polyfill

apply works like call. The only difference is how arguments are received:

~~~text
call  → separate arguments
apply → one array of arguments
~~~

~~~js
Function.prototype.myApply = function (context, args) {
  const temporaryKey = Symbol()

  context[temporaryKey] = this
  const result = context[temporaryKey](...args)
  delete context[temporaryKey]

  return result
}
~~~

Usage:

~~~js
introduce.myApply(user, ["Delhi"])
~~~

The spread operator changes ["Delhi"] into a normal argument.

### 3. bind polyfill

bind does not run the function immediately. It returns a new function for later.

~~~js
Function.prototype.myBind = function (context, ...firstArgs) {
  const originalFunction = this

  return function (...laterArgs) {
    return originalFunction.call(
      context,
      ...firstArgs,
      ...laterArgs
    )
  }
}
~~~

Usage:

~~~js
function introduce(city, country) {
  console.log(this.name, city, country)
}

const boundFunction = introduce.myBind(user, "Delhi")
boundFunction("India")
~~~

Step by step:

~~~text
introduce.myBind(...) → this is introduce
Save introduce        → originalFunction
Return a new function → nothing runs yet
boundFunction(...)    → call introduce with this = user
~~~

This learning version does not cover the special native behavior of using a bound function with new.

### 4. reduce polyfill

reduce visits every item and keeps one accumulated result.

~~~js
const total = [10, 20, 30].reduce((sum, number) => {
  return sum + number
}, 0)

console.log(total) // 60
~~~

Simplified polyfill:

~~~js
Array.prototype.myReduce = function (callback, initialValue) {
  let accumulator = initialValue

  for (let index = 0; index < this.length; index++) {
    accumulator = callback(
      accumulator,
      this[index],
      index,
      this
    )
  }

  return accumulator
}
~~~

Usage:

~~~js
const total = [10, 20, 30].myReduce((sum, number) => {
  return sum + number
}, 0)
~~~

Flow:

~~~text
Start accumulator = 0
0 + 10  → 10
10 + 20 → 30
30 + 30 → 60
Return 60
~~~

This simple version expects an initial value. The native reduce can also work without one by using the first available array item.

### 5. forEach polyfill

forEach simply runs a callback once for each item.

~~~js
Array.prototype.myForEach = function (callback) {
  for (let index = 0; index < this.length; index++) {
    callback(this[index], index, this)
  }
}
~~~

Usage:

~~~js
const numbers = [10, 20, 30]

numbers.myForEach((number, index) => {
  console.log(index, number)
})
~~~

Inside myForEach:

~~~text
this[0] → 10
this[1] → 20
this[2] → 30
~~~

Like native forEach, the learning method does not return a transformed array.

### 6. flat polyfill

flat removes levels of nested arrays.

~~~js
const values = [1, [2, [3]]]

values.flat(1) // [1, 2, [3]]
values.flat(2) // [1, 2, 3]
~~~

Simplified polyfill:

~~~js
Array.prototype.myFlat = function (depth = 1) {
  const result = []

  function openArray(array, remainingDepth) {
    array.forEach((item) => {
      const shouldOpen =
        Array.isArray(item) && remainingDepth > 0

      if (shouldOpen) {
        openArray(item, remainingDepth - 1)
      } else {
        result.push(item)
      }
    })
  }

  openArray(this, depth)
  return result
}
~~~

Usage:

~~~js
const values = [1, [2, [3]]]
console.log(values.myFlat(2)) // [1, 2, 3]
~~~

The helper checks each item:

~~~text
Normal value                     → add to result
Array and depth is still allowed → open it recursively
~~~

### Polyfill revision

~~~text
Polyfill → our implementation of a missing feature

myCall   → run now with chosen this and separate arguments
myApply  → run now with chosen this and an argument array
myBind   → return a function that runs later
myReduce → keep updating one accumulator
myForEach→ run a callback for every item
myFlat   → recursively open nested arrays
~~~
