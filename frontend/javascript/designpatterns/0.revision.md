# Important Design Patterns — Simple Interview Revision

Design patterns are reusable ways to solve common software-design problems.

| Category | Patterns |
|---|---|
| Creational | Singleton, Factory, Builder |
| Structural | Adapter, Decorator, Facade, Proxy |
| Behavioral | Command, Mediator, Observer, State, Strategy |

---

# 1. Singleton Pattern

## Definition

The Singleton pattern ensures that a class has only one shared instance throughout the application.

## Easy example: Logger

We want every part of the application to use the same logger.

```js
class Logger {
  constructor() {
    if (Logger.instance) {
      return Logger.instance;
    }

    Logger.instance = this;
  }

  log(message) {
    console.log(message);
  }
}

const logger1 = new Logger();
const logger2 = new Logger();

logger1.log("Application started");

console.log(logger1 === logger2); // true
```

Both variables contain the same logger instance.

## Interview answer

> Singleton ensures that only one instance of a class exists. A logger is a good example because the entire application can use the same logger instead of creating a new one in every module.

> **Remember:** One class, one shared object.

# 4. Adapter Pattern

## Definition

The Adapter pattern converts data or an interface into the format expected by the application.

## Easy example: API response adapter

The API returns `first_name`, but our application expects `firstName`.

```js
const apiUser = {
  first_name: "Vishnu",
  email_address: "vishnu@example.com"
};

function adaptUser(user) {
  return {
    firstName: user.first_name,
    email: user.email_address
  };
}

const user = adaptUser(apiUser);

console.log(user.firstName); // Vishnu
```

## Interview answer

> Adapter makes incompatible formats work together. For example, it can convert a third-party API response into the data structure used by our frontend.

> **Remember:** Convert one format into another.

# 9. Mediator Pattern

## Definition

The Mediator pattern allows components to communicate through a central object instead of communicating directly.

## Easy example: Vuex store

Suppose `LoginComponent` updates the logged-in user and `HeaderComponent` displays that user. The components do not communicate directly; both communicate through Vuex.

### Vuex store
### LoginComponent.vue
### HeaderComponent.vue


The communication flow is:

```text
LoginComponent
      ↓ dispatches login action
Vuex action
      ↓ commits setUser mutation
Vuex mutation
      ↓ updates state
Vuex state
      ↓ getter returns current user
Vuex getter
      ↓ component reactively receives the value
HeaderComponent
```

`LoginComponent` does not import or call `HeaderComponent`. Vuex coordinates the communication, so it acts as the mediator. When the mutation updates the state, Vue's reactivity causes `HeaderComponent` to rerender; that part also demonstrates Observer-style behavior.

## Interview answer

> Mediator reduces direct dependencies between components. In this example, `LoginComponent` dispatches an action, the action commits a mutation, the mutation updates the state, and `HeaderComponent` reads the result through a getter. Vuex acts as the central coordinator, while Vue reactivity updates the component when the state changes.

> **Remember:** Components communicate through a middleman.

# 10. Observer Pattern

## Definition

The Observer pattern notifies dependent subscribers when observed data changes.

## Vuex observer flow

```text
Vuex mutation updates state
          ↓
Vue reactivity detects the state change
          ↓
Dependent getter is marked for reevaluation
          ↓
Component using the getter receives the new value
          ↓
Component rerenders automatically
```

The getter is not the subscription mechanism. Vue's reactivity system tracks which components depend on the getter's underlying state.

## Interview answer

> Observer creates a one-to-many relationship. In Vuex, when a mutation changes reactive state, every component that depends on that state or its getters updates automatically.

> **Remember:** One change notifies many subscribers.

# 6. Facade Pattern

## Definition

The Facade pattern provides one simple method for performing several complex operations.

## Easy example: Place an order

```js
function makePayment() {
  console.log("Payment completed");
}

function updateStock() {
  console.log("Stock updated");
}

function sendEmail() {
  console.log("Confirmation email sent");
}

function placeOrder() {
  makePayment();
  updateStock();
  sendEmail();
}

placeOrder();
```

The caller uses only `placeOrder()` and does not need to understand all the internal steps.

## Interview answer

> **Remember:** One simple method hides many operations.


# 2. Factory Pattern

## Definition

The Factory pattern creates different objects based on the given input.

```javascript
function createUser(type) {
    switch (type) {
        case "admin":
            return {
                role: "admin",
                permissions: ["ALL"]
            };

        case "user":
            return {
                role: "user",
                permissions: ["READ"]
            };

        default:
            throw new Error("Invalid user type");
    }
}
```

Now, everywhere else in your application, you simply call the factory.

```javascript
const admin = createUser("admin");

const user = createUser("user");
```

## Interview answer

> Factory centralizes object creation. The caller provides a type, and the factory returns the correct object without exposing the creation details.

> **Remember:** Give a type and receive the correct object.

# 3. Builder Pattern

## Definition

The Builder pattern creates a complex object one step at a time.

## Easy example: Build a user

```js
class UserBuilder {
  constructor(name) {
    this.user = { name };
  }

  setAge(age) {
    this.user.age = age;
    return this;
  }

  setCity(city) {
    this.user.city = city;
    return this;
  }

  build() {
    return this.user;
  }
}

const user = new UserBuilder("Vishnu")
  .setAge(25)
  .setCity("Hyderabad")
  .build();

console.log(user);
```

## Interview answer

Builder Pattern = build a complex object step-by-step.

Instead of passing many arguments to a constructor:
  class User {
      constructor() {
          this.name = '';
          this.age = 0;
          this.country = '';
          this.isAdmin = false;
      }
  }
  new User("Vishnu", 25, "India", true, "admin");

we can build the object gradually.

# 7. Proxy Pattern

## Definition

The Proxy pattern places another object in front of the real object to control access to it.


Proxy = an object that stands in front of another object and controls access to it.

A very simple Vue example is checking authentication before making an API call.

Without Proxy
api.getUser();
With Proxy
Component
    ↓
   Proxy
    ↓
Check authentication
    ↓
Real API
Simple JavaScript example
class RealAPI {
    getUser() {
        console.log("Calling API...");
        return {
            name: "Vishnu"
        };
    }
}

class APIProxy {
    constructor(api) {
        this.api = api;
    }

    getUser(isLoggedIn) {
        if (!isLoggedIn) {
            console.log("Access denied");
            return;
        }

        return this.api.getUser();
    }
}

Usage:

const api = new RealAPI();

const proxy = new APIProxy(api);

proxy.getUser(false);
// Access denied

proxy.getUser(true);
// Calling API...

The component doesn't directly access RealAPI.

Component
    ↓
APIProxy
    ↓
RealAPI

The Proxy controls access to the real object.

> **Remember:** Control access to the real object.

# 8. Command Pattern

## Definition

The Command pattern represents an action as an object. The action can then be executed, stored in history, queued, or undone.

## Easy example: Counter with undo and redo

```js
let count = 0;
const undoStack = [];
const redoStack = [];

function createCounterCommand(value) {
  return {
    execute() {
      count += value;
    },

    undo() {
      count -= value;
    }
  };
}

function executeCommand(command) {
  command.execute();
  undoStack.push(command);
  redoStack.length = 0;
}

function undo() {
  const command = undoStack.pop();

  if (command) {
    command.undo();
    redoStack.push(command);
  }
}

function redo() {
  const command = redoStack.pop();

  if (command) {
    command.execute();
    undoStack.push(command);
  }
}

const increment = createCounterCommand(1);
const decrement = createCounterCommand(-1);

executeCommand(increment);
console.log(count); // 1

executeCommand(increment);
console.log(count); // 2

executeCommand(decrement);
console.log(count); // 1

undo();
console.log(count); // 2

redo();
console.log(count); // 1
```

The increment and decrement operations are commands. The undo stack stores executed commands, while the redo stack stores commands that were undone.

## Interview answer

> Command wraps an action inside an object. The caller executes the command without needing to know its internal logic. Because commands can be stored, the pattern is useful for action history, queues, and undo/redo functionality.

> **Remember:** Turn an action into an object so it can be executed, stored, or undone.

# 12. Strategy Pattern

## Definition

The Strategy pattern provides multiple ways to perform the same operation and allows one to be selected at runtime.

## Easy example: Payment strategies

```js
function payByCard(amount) {
  console.log(`Paid ₹${amount} using card`);
}

function payByUpi(amount) {
  console.log(`Paid ₹${amount} using UPI`);
}

function checkout(amount, paymentStrategy) {
  paymentStrategy(amount);
}

checkout(1000, payByUpi);
```

`payByCard` and `payByUpi` are interchangeable strategies.


example 2:
----------
const payment = {
    upiPayment () {
        console.log("upi payment");
    },
    cardPayment () {
        console.log("card payment");
    }
}

payment["upiPayment"]();

## Interview answer

> Strategy defines multiple algorithms for the same operation and allows the application to choose one at runtime. Examples include payment methods, validation rules, sorting, and authentication providers.

> **Remember:** Same task, different methods.

# 11. State Pattern [Less important]

## Definition

The State pattern changes an object's behavior based on its current state.

## Easy example: Order status

```js
const order = {
  status: "pending",

  cancel() {
    if (this.status === "pending") {
      this.status = "cancelled";
      console.log("Order cancelled");
      return;
    }

    console.log("Order cannot be cancelled");
  }
};

order.cancel(); // Order cancelled
order.cancel(); // Order cannot be cancelled
```

The result of `cancel()` depends on the current order state.

## Interview answer

> State pattern is used when an object's behavior changes according to its current state. Examples include orders, media players, forms, and workflow statuses.

> **Remember:** Different state, different behavior.

# How to Identify the Pattern

| Question | Pattern |
|---|---|
| Do I need one shared object? | Singleton |
| Do I create different objects based on a type? | Factory |
| Do I construct an object step by step? | Builder |
| Do I convert one format into another? | Adapter |
| Do I add behavior by wrapping something? | Decorator |
| Do I hide many operations behind one method? | Facade |
| Do I control access to another object? | Proxy |
| Do I store an action to run later? | Command |
| Do components communicate through a middleman? | Mediator |
| Does one change notify many subscribers? | Observer |
| Does behavior depend on current state? | State |
| Do I have different methods for the same task? | Strategy |

---

# Commonly Confused Patterns

## Adapter versus Facade

- **Adapter:** Converts one format or interface into another.
- **Facade:** Hides several operations behind one simple method.

## Decorator versus Proxy

- **Decorator:** Adds new behavior.
- **Proxy:** Controls access.

## State versus Strategy

- **State:** Behavior changes internally when state changes.
- **Strategy:** The caller selects which algorithm to use.

## Observer versus Mediator

- **Observer:** One subject notifies multiple subscribers.
- **Mediator:** Multiple components communicate through a central object.

## Factory versus Builder

- **Factory:** Selects and creates the correct object.
- **Builder:** Constructs one object step by step.
