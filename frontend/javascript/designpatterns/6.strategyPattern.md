# 4. Strategy Pattern ⭐⭐⭐⭐⭐

## What Problem Does It Solve?

Imagine you're building an e-commerce website.

Users can sort products by:

- Price
- Rating
- Name

A beginner usually writes something like this.

```javascript
function sortProducts(type, products) {
    if (type === "price") {
        return products.sort((a, b) => a.price - b.price);
    }

    if (type === "rating") {
        return products.sort((a, b) => b.rating - a.rating);
    }

    if (type === "name") {
        return products.sort((a, b) => a.name.localeCompare(b.name));
    }
}
```

Usage

```javascript
sortProducts("price", products);
```

Works.

But after a few months...

The product manager asks for:

- Newest First
- Best Seller
- Discount
- Popular
- Trending

Now your function becomes...

```javascript
function sortProducts(type, products) {

    if (type === "price") {
        ...
    }

    if (type === "rating") {
        ...
    }

    if (type === "name") {
        ...
    }

    if (type === "discount") {
        ...
    }

    if (type === "newest") {
        ...
    }

    if (type === "popular") {
        ...
    }

    if (type === "trending") {
        ...
    }
}
```

Problems

- Huge if/else blocks
- Hard to maintain
- Every new sorting method changes the same function
- Easy to introduce bugs

---

# Solution — Strategy Pattern

Instead of one giant function,

create one function for each strategy.

```javascript
const sortStrategies = {

    price(products) {
        return products.sort((a, b) => a.price - b.price);
    },

    rating(products) {
        return products.sort((a, b) => b.rating - a.rating);
    },

    name(products) {
        return products.sort((a, b) =>
            a.name.localeCompare(b.name)
        );
    }
};
```

Now selecting the strategy is simple.

```javascript
sortStrategies.price(products);

sortStrategies.rating(products);

sortStrategies.name(products);
```

Or even better

```javascript
const selectedSort = "rating";

sortStrategies[selectedSort](products);
```

Notice something important.

The calling code doesn't care **how** sorting works.

It only says

> "Sort by rating."

The selected strategy decides the algorithm.

---

# Why Is This Better?

Suppose tomorrow you need

```
Sort by Discount
```

You don't modify existing code.

Just add a new strategy.

```javascript
sortStrategies.discount = function (products) {
    return products.sort(
        (a, b) => b.discount - a.discount
    );
};
```

Done.

No existing code changes.

# Another Example You Use Every Day

Imagine login.

Users can login using

- Google
- GitHub
- Microsoft

Bad approach

```javascript
function login(type) {

    if (type === "google") {
        // Google Login
    }

    if (type === "github") {
        // GitHub Login
    }

    if (type === "microsoft") {
        // Microsoft Login
    }
}
```

Better

```javascript
const loginStrategies = {

    google() {
        console.log("Google Login");
    },

    github() {
        console.log("GitHub Login");
    },

    microsoft() {
        console.log("Microsoft Login");
    }
};

loginStrategies["google"]();
```

Need Facebook login?

Just add another strategy.

```javascript
loginStrategies.facebook = function () {
    console.log("Facebook Login");
};
```

No existing code changes.

# React Example

Suppose you're rendering products.

```jsx
const sortStrategies = {
    price,
    rating,
    newest
};

const sortedProducts =
    sortStrategies[selectedSort](products);
```

When the dropdown changes

```jsx
<select onChange={...}>
```

Only

```
selectedSort
```

changes.

The sorting algorithm automatically changes.

# Mental Model

Think of Strategy Pattern as:

```
Same Goal

↓

Different Ways

↓

Choose One
```

Example

```
Sort Products

        │

 ┌──────┼────────┐

 ▼      ▼        ▼

Price Rating   Name
```

Only one strategy runs at a time.

---

# When Should I Think About Strategy Pattern?

Ask yourself:

> **"Do I have multiple ways of doing the same thing?"**

Examples

- Sorting products
- Login providers
- Payment methods
- Form validation
- Search algorithms
- Discount calculation
- Shipping calculation

If the answer is **yes**, Strategy Pattern is usually a good fit.

---

# Interview Definition

**Strategy Pattern defines a family of algorithms, puts each algorithm into its own function or class, and lets the application choose one at runtime without changing the calling code.**
