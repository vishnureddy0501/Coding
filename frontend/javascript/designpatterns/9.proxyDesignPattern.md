## Proxy Design Pattern:
---------------------
# What is a Proxy?

Imagine you want to talk to the CEO of a company.

Can you directly call the CEO?

**No.**

Instead:

```text
You
 │
 ▼
Secretary
 │
 ▼
CEO
```

The **Secretary** is the **Proxy**.

The proxy decides:

- Can you talk to the CEO?
- Should I reject your request?
- Should I cache the response?
- Should I log the request?
- Should I delay it?
- Should I fetch additional information?

The proxy **controls access** to the real object.

---

# API Example

## Without Proxy
----------------
```javascript
const users = await fetch("/users");
```

Your code directly talks to the server.

```text
Component
   │
   ▼
Server
```

---

## With Proxy
-------------
```javascript
const users = await apiProxy.getUsers();
```

Internally, `apiProxy` decides what to do.

```text
Request
   │
   ▼
Check Cache
   │
   ├── Cache Exists?
   │        │
   │       Yes
   │        │
   │        ▼
   │   Return Cache
   │
   └── No
            │
            ▼
        Call Server
```

Your component doesn't know whether the data came from:

- Cache
- Server
- Local Storage

It simply calls:

```javascript
apiProxy.getUsers();
```

That's the **Proxy Pattern**.

---

# React Query Example

React Query is a great real-world example of the Proxy pattern.

Suppose a component requests users.

```javascript
const { data } = useQuery({
  queryKey: ["users"],
  queryFn: getUsers,
});
```

Internally, React Query decides what to do.

### First Request

```text
Component
   │
   ▼
React Query
   │
   ▼
Server
   │
   ▼
Cache
   │
   ▼
Component
```

---

### Second Request

```text
Component
   │
   ▼
React Query
   │
   ▼
Cache
```

The server isn't even called.

React Query intercepted the request and returned cached data.

Your component always talks to **React Query**, not directly to the server.

That's exactly what a Proxy does.

# Another Example — Permission Proxy

Imagine deleting a user.

## Without Proxy

```javascript
deleteUser();
```

Anyone can call it.

---

## With Proxy

```javascript
permissionProxy.deleteUser();
```

Internally:

```javascript
if (currentUser.isAdmin) {
    deleteUser();
} else {
    throw new Error("No Permission");
}
```

The proxy decides whether to forward the request.

# A Real Proxy Example

Suppose you create a service like this:

```javascript
const userService = {
    async getUsers() {
        if (cache.exists()) {
            return cache.get();
        }
        return fetch("/users");
    }
};
```

Now your component calls:

```javascript
const users = await userService.getUsers();
```

The component doesn't know whether the data came from:

- Cache
- Server
- Local Storage
- IndexedDB

`userService` decides.

That makes it a **Proxy**.
---

# Easy Rule

Ask yourself this question:

> **Is this object deciding whether to forward the request to the real object?**

If **Yes** →

## Proxy

Examples:

- React Query
- Browser Cache
- CDN
- Lazy Loader

---

# React Query Fits This Perfectly

Your component doesn't fetch data directly.

Instead:

```text
Component
      │
      ▼
 React Query
      │
      ├── Return Cached Data
      ├── Fetch Fresh Data
      ├── Retry Failed Request
      ├── Refetch in Background
      └── Return Final Result
```

React Query decides **how** the request should be handled before your component receives the data.

That's why **React Query is one of the best real-world examples of the Proxy Pattern in frontend development.**
