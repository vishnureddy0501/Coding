# 6. Facade Pattern
    Hide complexity behind a simple interface.

# Facade Pattern ⭐⭐⭐⭐

## Problem

Sometimes a component has to perform multiple related operations before it can complete a task.

For example, after a user logs in, you might need to:

- Authenticate the user
- Fetch the user profile
- Fetch permissions
- Fetch settings
- Fetch notifications

Without a Facade, every page that needs this functionality has to repeat the same code.

```javascript
await login();

await fetchProfile();

await fetchPermissions();

await fetchSettings();

await fetchNotifications();
```

Imagine having this code in 20 different pages.

Problems:

- Repeated code
- Hard to maintain
- If one step changes, every page must be updated

---

## Solution

Create **one simple function** that hides all the complexity.

```javascript
async function initializeUser() {
    await login();
    await fetchProfile();
    await fetchPermissions();
    await fetchSettings();
    await fetchNotifications();
}
```

Now every page only needs:

```javascript
await initializeUser();
```

The page doesn't know (or care) what happens inside.

This is the **Facade Pattern**.

---

## Frontend Example 2 — API Wrapper

Suppose every API request needs:

- Show loader
- Make API call
- Hide loader
- Handle errors

### Without Facade

```javascript
showLoader();

try {
    const response = await axios.get("/users");

    hideLoader();

    return response.data;

} catch (error) {

    hideLoader();

    showError(error);
}
```

You'll end up writing this everywhere.

### With Facade

```javascript
async function getUsers() {
    showLoader();

    try {
        const response = await axios.get("/users");
        return response.data;
    } finally {
        hideLoader();
    }
}
```

Now components simply do:

```javascript
const users = await getUsers();
```

The component doesn't know anything about loaders or error handling.

## Frontend Example 3 — API Service Layer

Instead of calling Axios directly everywhere:

```javascript
axios.get("/users");

axios.post("/users");

axios.delete("/users/1");

axios.put("/users/1");
```

Create a service layer.

```javascript
const api = {
    getUsers() {
        return axios.get("/users");
    },

    createUser(data) {
        return axios.post("/users", data);
    },

    deleteUser(id) {
        return axios.delete(`/users/${id}`);
    }
};
```

Usage:

```javascript
const users = await api.getUsers();
```

### Why is this useful?

Suppose your company switches from **Axios** to **Fetch API**.

Without a Facade:

❌ Hundreds of files need changes.

With a Facade:

✅ Only `api.js` changes.

Everything else continues working.

## Frontend Example 4 — React Query

React Query configuration can become repetitive.

### Without Facade

```javascript
useQuery({
    queryKey: ["users"],
    queryFn: getUsers,
    staleTime: 5000,
    retry: 3,
    refetchOnWindowFocus: false,
});
```

### With Facade

```javascript
function useUsers() {
    return useQuery({
        queryKey: ["users"],
        queryFn: getUsers,
        staleTime: 5000,
    });
}
```

Usage:

```javascript
const { data } = useUsers();
```

The custom hook hides the React Query configuration.

Ask yourself:

> **"Am I hiding several complicated steps behind one simple function?"**

➡️ **Facade Pattern**

# Facade vs Adapter (Interview Favorite)

These two patterns are often confused.

### Adapter

**Purpose:** Change the data format.

Backend returns:

```json
{
    "fname": "Vishnu"
}
```

Frontend expects:

```javascript
{
    firstName: "Vishnu"
}
```

Adapter converts one format into another.

---

### Facade

**Purpose:** Hide complexity.

Instead of:

```javascript
login();
fetchProfile();
fetchPermissions();
fetchSettings();
```

You provide:

```javascript
initializeUser();
```

Nothing is converted.

You're simply making the API easier to use.

## Interview Answer

**Q. Where have you used the Facade Pattern?**

A good answer:

> "We created service functions and custom hooks that wrapped multiple API calls, loading states, and error handling behind a single function. Components only called functions like `initializeUser()` or `useUsers()`, while the service layer handled all the underlying complexity."

This is one of the most common real-world uses of the **Facade Pattern** in React and Vue applications.
