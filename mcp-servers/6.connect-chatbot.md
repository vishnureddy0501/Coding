# 6. Connect it to the chatbot

## Local development

First test the MCP server with Inspector:

```text
Inspector -> MCP server -> MongoDB
```

After the three tools work, connect the same server to your chatbot backend:

```text
React/Vue chat UI
      -> FastAPI or Node chat backend (MCP host)
      -> LLM
      -> local MCP server over stdio
      -> MongoDB
```

## Chat backend responsibilities

The backend must:

1. receive the user's message;
2. send the message and available MCP tools to the LLM;
3. execute the tool selected by the LLM;
4. send the result back to the LLM;
5. return the final answer to the UI.

The frontend should only know about a chat endpoint such as:

```http
POST /api/chat
```

It should not know the MongoDB URI or MCP launch command.

## Suggested system instruction

```text
You answer questions only about Action Items Library templates.
Use MCP tools whenever the answer requires current MongoDB data.
Do not claim that library templates are live customer action items.
If no record is found, say so clearly.
Never invent IDs, priorities, or counts.
```

## Do we need REST APIs too?

Yes, keep the existing FastAPI REST endpoints for normal product screens. The chatbot uses MCP because tool discovery and structured tool calling are designed for an LLM.

```text
Normal UI CRUD -> existing REST API
Chat questions -> custom MCP tools
```
