# MCP Fundamentals

## What Problem Does MCP Solve?

Without MCP, every AI application needs a custom integration for every external service:

```text
AI application → custom GitHub integration
AI application → custom Slack integration
AI application → custom database integration
```

MCP provides a common interface:

```text
AI application → MCP protocol → GitHub MCP server
                              → Slack MCP server
                              → Database MCP server
```

This is similar to how a standard protocol lets different clients and servers communicate without sharing the same internal implementation.

## Main Participants

### MCP Host

The host is the user-facing AI application, such as an IDE assistant, desktop assistant, or custom agent application.

The host controls:

- The user experience
- Which servers may be connected
- Permissions and approvals
- How context reaches the model
- How tool results are shown

### MCP Client

The client is the protocol component inside the host that communicates with one MCP server.

A host can create multiple clients:

```text
AI Host
  ├── GitHub MCP client → GitHub MCP server
  ├── Slack MCP client  → Slack MCP server
  └── DB MCP client     → Database MCP server
```

### MCP Server

The server exposes capabilities and connects them to an external system.

Examples:

- Read GitHub pull requests
- Search internal documentation
- Query a database
- Create a ticket
- Send an approved message

The server is a protocol adapter. It should contain authentication, validation, authorization, and integration logic—not unrestricted access to the underlying system.

## Server Capabilities

### Tools

Tools are functions that the model can request.

```text
get_pull_request(repository, number)
search_documents(query)
create_issue(title, description)
```

Each tool normally has:

- Name
- Clear description
- Input schema
- Optional output schema
- Handler implementation

OpenAI's MCP guidance describes tool discovery as the client loading tool definitions, the model selecting a tool, and the server validating and executing it. [OpenAI MCP server concepts](https://developers.openai.com/plugins/concepts/mcp-server)

### Resources

Resources provide readable data or content:

```text
file contents
documentation pages
database schema
Git history
configuration
```

Resources are useful when the client chooses context for the model to read.

### Prompts

Prompts are reusable templates exposed by the server:

```text
Review this pull request
Summarize this incident
Create a customer briefing
```

Prompts guide interaction but do not perform the external operation themselves.

## Control Model

A useful interview distinction is:

| Primitive | Usually controlled by | Purpose |
| --- | --- | --- |
| Prompts | User | Reusable interaction templates |
| Resources | Application | Context supplied to the model |
| Tools | Model, within policy | Functions that retrieve data or take actions |

## MCP Is Not the Model

The MCP server does not usually contain an LLM. It exposes capabilities to an AI host.

```text
Model decides what it needs
        ↓
MCP client sends a structured request
        ↓
MCP server performs deterministic code
        ↓
Structured result returns to the model
```

## MCP Is Not a Database

MCP does not define how data is stored. A server can connect to PostgreSQL, GitHub, a REST API, files, or any other system.

## MCP Is Not an Agent Framework

MCP provides tools and context. An agent framework manages reasoning loops, sessions, delegation, memory, approvals, and model calls.

They are commonly used together:

```text
Agent framework → MCP client → MCP server → service
```
