# 1. The real requirement

## What Action Items Library means here

In the customer-success codebase, `cs_action_items_library` contains reusable action-item **templates**.

Real code used for this course:

- [Action Items Library module documentation](/Users/aviso/Desktop/customer-success/app/action_items_library/README.md)
- [MongoDB service functions](/Users/aviso/Desktop/customer-success/app/action_items_library/services/action_items_library.py)
- [Pydantic request and response models](/Users/aviso/Desktop/customer-success/app/action_items_library/models/action_items_library.py)

Example:

```text
"Schedule kickoff call" = reusable library template
```

It is different from `cs_action_items`, which contains actual work assigned for a customer.

| | Action Items Library | Action Items |
|---|---|---|
| Collection | `cs_action_items_library` | `cs_action_items` |
| Meaning | Reusable template | Actual assigned task |
| Used by this chatbot | Yes | No |

```javascript
  last_updated_at: "1791288000000",
  last_updated: ISODate("...")

```

The chatbot normally needs only the public fields. It does not need MongoDB `_id` or internal flattened audit fields.

## Scope of version 1

The chatbot can:

- search templates by action name;
- filter templates by priority;
- fetch one template by `action_library_id`;
- count templates by priority.

It cannot:

- inspect other MongoDB collections;
- execute arbitrary MongoDB queries;
- create, update, or delete data;
- answer questions about live customer action items.

Keeping this boundary small is the main advantage of a custom MCP server.
