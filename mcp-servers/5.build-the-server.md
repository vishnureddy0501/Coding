# 5. Build the custom MCP server

The runnable example is in [action-items-library-mcp](action-items-library-mcp/README.md).

## Project structure

```text
action-items-library-mcp/
├── app/
│   ├── config.py       # Environment settings
│   ├── database.py     # MongoDB connection and fixed collection
│   ├── repository.py   # Safe MongoDB queries
│   └── server.py       # MCP tool definitions
├── .env.example
└── pyproject.toml
```

## Responsibilities

```text
server.py     -> MCP names, descriptions, and input validation
repository.py -> MongoDB query details
database.py   -> connection and collection name
config.py     -> environment configuration
```

Keeping MongoDB queries out of `server.py` makes the code easier to test and prevents tool logic from becoming messy.

## Why the collection is fixed

```python
COLLECTION_NAME = "cs_action_items_library"
```

The model cannot choose another collection such as users, accounts, or live action items. This is both simpler and safer.

## Why tools return dictionaries

MCP sends structured results to the host. The LLM can understand:

```json
{
  "action_library_id": "...",
  "action_name": "Schedule kickoff call",
  "priority": "HIGH"
}
```

better than a formatted paragraph created inside the server. The LLM should handle presentation.
