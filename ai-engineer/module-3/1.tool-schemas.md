# Lesson 1: Tool schemas and arguments

A function tool tells the model which operation exists and which arguments it may propose.

## 1. Define argument models

```python
from pydantic import BaseModel, Field


class GetAccountArguments(BaseModel):
    account_id: str = Field(min_length=1, max_length=100)


class ListOpenTicketsArguments(BaseModel):
    account_id: str = Field(min_length=1, max_length=100)
    limit: int = Field(default=20, ge=1, le=50)


class GetAccountHealthArguments(BaseModel):
    account_id: str = Field(min_length=1, max_length=100)
```

Notice what is absent:

```text
tenant
user_id
role
allowed_account_ids
database filter
API URL
```

Those values must never be chosen by the model. The application supplies trusted `RequestContext` during execution.

## 2. Describe the tools

```python
TOOLS = [
    {
        "type": "function",
        "name": "get_account",
        "description": "Get one visible account by its account ID.",
        "parameters": {
            "type": "object",
            "properties": {
                "account_id": {
                    "type": "string",
                    "description": "Exact account ID supplied by the user.",
                }
            },
            "required": ["account_id"],
            "additionalProperties": False,
        },
        "strict": True,
    },
]
```

Important fields:

- `name` must match an approved application operation;
- `description` explains when the operation is appropriate;
- `parameters` describes the JSON arguments;
- `required` lists mandatory values;
- `additionalProperties: false` rejects undeclared arguments;
- `strict: true` asks the model to follow the schema exactly.

## 3. Schema validation is not authorization

This tool call has valid syntax:

```json
{"account_id": "account-900"}
```

But the user may not be allowed to see `account-900`. Pydantic validates the shape; Module 2's service still enforces tenant and record permissions.

```text
tool schema validation → are arguments shaped correctly?
authorization          → may this user access the record?
```

Both are required.

## 4. Do not create a generic query tool

Unsafe:

```json
{
  "name": "query_database",
  "parameters": {
    "collection": "string",
    "filter": "object"
  }
}
```

Safe tools represent reviewed business operations:

```text
get_account(account_id)
list_open_tickets(account_id, limit)
get_account_health(account_id)
```

## Remember

- Tool arguments contain only values the model is allowed to propose.
- Trusted authorization context is never a tool argument.
- Strict schemas reduce malformed calls but do not replace application validation.
- Every tool should correspond to one narrow read operation.
