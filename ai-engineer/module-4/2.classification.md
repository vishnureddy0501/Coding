# Lesson 2: Structured classification and routing

## Classification instruction

```python
SCOPE_INSTRUCTIONS = """
Classify the question. Do not answer it.

Approved intents:
- get_account: read basic data for one account
- list_open_tickets: read open tickets for one account
- get_account_health: read current health and score for one account

General knowledge, advice, write operations, arbitrary queries,
and unrelated topics are out of scope.
Never invent a missing account ID.
"""
```

## Parse into Pydantic

```python
response = await client.responses.parse(
    model=model_name,
    instructions=SCOPE_INSTRUCTIONS,
    input=question,
    text_format=ScopeClassification,
)

classification = response.output_parsed
```

Structured output avoids manually extracting JSON from text. Treat a missing parsed result as a temporary model failure.

## Route the decision

```python
if classification is None:
    return temporarily_unavailable_response()

if classification.outcome == "out_of_scope":
    return out_of_scope_response()

if classification.outcome == "needs_clarification":
    return clarification_response("Which account do you mean?")

if classification.intent not in SUPPORTED_INTENTS:
    return out_of_scope_response()

return await tool_orchestrator.answer(question, context)
```

The classifier cannot directly choose tenant, user permissions, query filters, URLs, or credentials.

## Unsupported write request

“Change account-101 to active” mentions an approved entity but requests an unsupported operation. Return `out_of_scope`; do not convert it into a read.
