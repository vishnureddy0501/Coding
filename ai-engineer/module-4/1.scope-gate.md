# Lesson 1: Build a layered scope gate

A system prompt saying “answer only project questions” is not enough. Use several small checks.

## 1. Intent allow-list

```python
SUPPORTED_INTENTS = {
    "get_account",
    "list_open_tickets",
    "get_account_health",
}
```

No other intent may reach the tool executor.

## 2. Structured classification

```python
from typing import Literal, Optional

from pydantic import BaseModel


class ScopeClassification(BaseModel):
    outcome: Literal[
        "supported",
        "needs_clarification",
        "out_of_scope",
    ]
    intent: Optional[Literal[
        "get_account",
        "list_open_tickets",
        "get_account_health",
    ]] = None
    account_id: Optional[str] = None
```

The classifier selects an intent. It does not answer, query data, or authorize an account.

## 3. Application checks

After classification, check:

- intent is allow-listed;
- required account ID exists;
- ID length and format are valid;
- requested operation is read-only;
- maximum question length is respected.

Authorization still occurs in Module 2. A valid account ID does not mean the current user can see it.

## 4. Fixed public responses

```python
OUT_OF_SCOPE_MESSAGE = (
    "I can only answer questions about this project's approved data."
)

NO_INFORMATION_MESSAGE = (
    "I could not find that information in the available project data."
)
```

Keep refusal text in application code. Do not let the model explain internal permissions, hidden records, or schemas.

## Important distinctions

```text
Who won the match?
→ out_of_scope

Show the health of account-101, but no visible record exists
→ no_information

Show the account health
→ needs_clarification
```
