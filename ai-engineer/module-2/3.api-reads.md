# Lesson 3: Safe internal API reads

Some project data already comes from an internal API. Wrap it behind an approved function instead of letting the model choose URLs or headers.

## 1. A small API client

```python
import httpx


class AccountHealthClient:
    def __init__(self, base_url: str, service_token: str):
        self.base_url = base_url.rstrip("/")
        self.service_token = service_token

    async def get_health(self, tenant: str, account_id: str) -> dict:
        async with httpx.AsyncClient(timeout=5.0) as client:
            response = await client.get(
                f"{self.base_url}/internal/accounts/{account_id}/health",
                headers={
                    "Authorization": f"Bearer {self.service_token}",
                    "X-Tenant": tenant,
                },
            )
            response.raise_for_status()
            return response.json()
```

The URL shape, HTTP method, timeout, and service credentials are fixed by application code. The model will never receive `service_token`.

## 2. Validate and filter the API response

```python
from typing import Literal


class AccountHealthData(BaseModel):
    account_id: str
    health: Literal["healthy", "watch", "at_risk"]
    score: int = Field(ge=0, le=100)
    updated_at: datetime
```

```python
async def get_account_health(
    client: AccountHealthClient,
    context: RequestContext,
    account_id: str,
) -> AccountHealthData | None:
    if context.role != "tenant_admin" and account_id not in context.allowed_account_ids:
        return None

    payload = await client.get_health(
        tenant=context.tenant,
        account_id=account_id,
    )
    return AccountHealthData.model_validate(payload)
```

Even though the API is internal, its response is validated. Only fields present in `AccountHealthData` continue to later chatbot layers.

## 3. Why the wrapper matters

Unsafe design:

```text
model chooses URL + method + headers → HTTP request
```

Safe design:

```text
approved operation name
→ application chooses fixed client method
→ trusted context supplies tenant
→ response is validated and filtered
```

## 4. API failures are not missing data

`404` can mean no visible record. A timeout or `500` means the source is temporarily unavailable. Do not convert every API error into `None`, because the chatbot would incorrectly say that information does not exist.

The next lesson creates explicit internal result states for this distinction.
