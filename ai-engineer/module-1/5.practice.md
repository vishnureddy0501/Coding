# Module 1 practice

Complete this module using your real project. Do not write LLM or vector-database code yet.

## Step 1: Select the first user role

Choose only one initial role, such as support agent or account manager.

Record:

- how the user authenticates;
- how tenant is determined;
- which records the role may access.

## Step 2: Inventory sources

List every candidate API, collection/table, and document set.

For each source, record:

- approved or forbidden;
- live or indexed;
- allowed fields;
- permission rule;
- maximum result size;
- expected freshness.

## Step 3: Select three intents

Recommended starting shape:

```text
one get-by-ID intent
one filtered-list intent
one documentation-search intent
```

Do not select write operations.

## Step 4: Create question examples

For each intent, write:

- five normal questions;
- two questions with missing required arguments;
- two questions using an unauthorized entity;
- two questions phrased unusually but still valid.

Also write:

- ten clearly unrelated questions;
- five unsupported project operations;
- five prompt-injection attempts.

Use [question-set-template.jsonl](question-set-template.jsonl).

## Step 5: Review every expected outcome

Label each question:

```text
answered
needs_clarification
no_information
out_of_scope
temporarily_unavailable
```

For `answered`, specify the required source or tool. For `no_information`, explain what evidence is absent.

## Step 6: Perform a manual security review

Answer these questions:

1. Can tenant be supplied through chat text?
2. Can the model choose an arbitrary database query?
3. Can forbidden fields reach the model?
4. Can one user retrieve another user's records?
5. Can an indexed document be returned without permission filters?
6. Does any refusal reveal that a forbidden record exists?

Every answer should be “no” before implementation continues.

## Completion checklist

- [ ] One initial user role is defined.
- [ ] Tenant and permission derivation are documented.
- [ ] Approved data sources are listed.
- [ ] Forbidden fields are listed.
- [ ] Exactly three initial intents are defined.
- [ ] Required and optional arguments are defined.
- [ ] Result limits are defined.
- [ ] Public response messages are defined.
- [ ] Normal, ambiguous, missing, unauthorized, unrelated, and injection questions exist.
- [ ] Each question has an expected outcome.

Once this contract is complete, Module 2 will implement the safe data-access functions behind the first intents.
