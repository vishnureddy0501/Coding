# Lesson 1: Understand the system boundary

## 1. What are we building?

The chatbot is a natural-language interface over approved project data.

It is not a general assistant.

```text
approved project question
        ↓
retrieve authorized project data
        ↓
answer using only that data
```

For an unrelated question:

```text
unrelated question
        ↓
scope check fails
        ↓
refuse without asking a data source or model for an answer
```

## 2. What does “only project data” mean?

An answer may use facts returned by:

- an approved project API;
- an approved read-only database operation;
- an approved indexed project document.

The model's pretrained knowledge is not an approved factual source.

The model may use language ability to summarize evidence, but it must not add facts that are absent from that evidence.

## 3. Three boundaries

### Domain boundary

Which business area may the chatbot discuss?

Example:

```text
Allowed: accounts, support tickets, invoices, product policies
Denied: sports, news, medical advice, general coding questions
```

### Data boundary

Which sources and fields may it read?

Example:

```text
Allowed: account name, status, owner, open-ticket count
Denied: password hashes, internal tokens, deleted records
```

### User boundary

Which records may the current user see?

Example:

```text
support agent → assigned accounts
manager       → accounts belonging to the manager's team
administrator → all accounts inside the current tenant
```

All three boundaries must pass before answering.

## 4. The LLM is not the security boundary

Do not rely on this alone:

```text
System prompt: Never reveal another tenant's data.
```

The database or API layer must enforce the tenant and user filter. If unauthorized data never reaches the model, the model cannot reveal it.

```python
document = collection.find_one(
    {
        "tenant": request_context.tenant,
        "account_id": account_id,
    }
)
```

`request_context.tenant` must come from trusted authentication—not from the user message or model output.

## 5. The answer must be traceable\


For every factual answer, the application should know:

- which operation ran;
- which document or records were used;
- which tenant/user permissions applied;
- whether the evidence was complete or truncated.

This does not mean returning private database details to the user. It means retaining enough source information to validate the answer.

## Important concept

The chatbot is a controlled interface over existing application capabilities. It does not replace authorization, data access, or business logic.
