# Core Concepts

## Agent

An agent is an AI model that can work toward a goal by repeatedly inspecting context, using tools, making changes, and verifying results.

```text
Understand the goal
        ↓
Inspect files and context
        ↓
Use tools and make changes
        ↓
Run tests or other checks
        ↓
Report the result
```

A normal chatbot mainly answers questions. A coding agent can:

- Search a repository
- Read and modify files
- Run terminal commands
- Execute tests
- Investigate failures
- Review a pull request
- Use connected external services

You are already using an agent when Codex or Claude can operate on your repository rather than merely returning a code snippet.

## MCP Server

MCP stands for **Model Context Protocol**. It provides a standard way for an agent to access external tools and data.

```text
Agent → MCP server → GitHub
                   → Slack
                   → Linear or Jira
                   → Database
                   → Documentation
```

An MCP server may provide tools such as:

```text
get_issue()
list_pull_requests()
search_slack()
read_database_schema()
create_linear_issue()
```

The MCP server controls live data, authentication, permissions, and actions. It does not define your complete working procedure.

## Skill

A skill is a reusable workflow for an agent.

Example:

```text
Skill: Review a backend pull request

1. Read the issue and acceptance criteria.
2. Inspect the changed files.
3. Check validation and authorization.
4. Review database changes.
5. Run relevant tests.
6. Report findings by severity.
```

A skill may contain instructions, scripts, templates, examples, and reference material.

The difference is:

```text
MCP   = tools and live data
Skill = procedure for using tools and completing work
```

OpenAI's documentation describes skills as reusable workflows that can teach an agent how to combine MCP tools. [Skills documentation](https://developers.openai.com/plugins/concepts/skills)

## Plugin

A plugin is an installable package that may combine:

- Skills
- MCP server configuration
- Commands
- Hooks
- Templates and assets
- External app connections

Use a plugin when a complete capability should be installed and shared as one package. [Plugins documentation](https://developers.openai.com/plugins)

## `AGENTS.md`

`AGENTS.md` is a repository instruction file for coding agents.

It can document:

- Architecture
- Project conventions
- Commands
- Testing expectations
- Files that should not be changed
- Definition of done

Example:

```md
# Project Instructions

## Architecture

- Frontend uses React and TypeScript.
- Backend uses Express and PostgreSQL.
- Controllers remain thin.
- Business logic belongs in services.

## Commands

- Tests: `npm test`
- API tests: `npm run test:api`
- Lint: `npm run lint`

## Rules

- Use ES modules.
- Add a regression test for every bug fix.
- Never modify production migrations.
```

Use nested `AGENTS.md` files when frontend and backend folders need different instructions.

## Automation

An automation performs a recurring workflow:

```text
Every weekday morning:
1. Check failed CI runs.
2. Group failures by repository.
3. Summarize likely causes.
4. Prepare an engineering report.
```

Automate a workflow only after it works reliably when performed manually by the agent.

## Subagent

A subagent handles a bounded part of a larger task.

Good parallel work:

```text
Agent 1 → inspect backend implementation
Agent 2 → inspect frontend usage
Agent 3 → inspect tests and CI
Primary agent → combine the findings
```

Avoid having several agents edit the same file or tightly coupled implementation simultaneously.
