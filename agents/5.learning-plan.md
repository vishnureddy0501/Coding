# Four-Week Learning Plan

## Week 1 — Use Agents Properly

Practice:

- Giving complete outcomes instead of asking only for snippets
- Separating read-only diagnosis from implementation
- Requiring tests and verification
- Reviewing every generated diff

Create an `AGENTS.md` file for one active repository.

Success criterion:

> The agent can inspect, implement, test, and report a small change without repeated reminders about project conventions.

## Week 2 — Master Development Workflows

Perform each workflow at least once:

1. Understand an unfamiliar feature
2. Implement a small feature
3. Fix a bug using a regression test
4. Review a pull request or local diff
5. Diagnose a failing test or CI job
6. Update documentation from actual code

After each task, note which instructions had to be repeated. Move stable project rules into `AGENTS.md`.

## Week 3 — Add One MCP Connection

Start with a read-only connection such as documentation or GitHub.

Practice one complete workflow:

```text
Read issue
    ↓
Inspect repository
    ↓
Implement change
    ↓
Run tests
    ↓
Review diff against acceptance criteria
```

Do not connect every workplace system at once. Add another connector only when it solves a specific repeated problem.

## Week 4 — Build a Reusable Workflow

Choose the task you repeat most often:

- API implementation
- PR review
- Bug investigation
- Migration review
- Release preparation

Write a skill describing its steps, safety rules, and expected output.

Run it on real work, note failures, and refine it.

## Monthly Review

Ask:

- Which tasks saved meaningful time?
- Which prompts required repeated clarification?
- Which repository rules belong in `AGENTS.md`?
- Which repeated workflow deserves a skill?
- Which manual recurring task is ready for automation?
- Which tool permissions are no longer necessary?

## Professional Safety Rules

- Never paste secrets into a prompt.
- Begin MCP connections with minimum permissions.
- Keep production database access read-only unless absolutely necessary.
- Require approval for deletion, deployment, migration, or external communication.
- Review generated code before committing.
- Require evidence: tests, logs, diffs, or source references.
- Do not let the agent silently expand the task scope.
- Keep human review for architectural and business decisions.

## Final Goal

Your workflow should evolve from:

```text
Ask AI for code → copy and paste → manually debug
```

into:

```text
Define outcome
    ↓
Agent investigates
    ↓
Agent implements
    ↓
Agent verifies
    ↓
You review evidence and make the final decision
```
