# MCP, Skills, Plugins, and Automations

## Which MCP Servers Are Useful?

### Documentation

Documentation MCP servers give agents current reference material instead of relying only on model memory.

OpenAI provides a read-only documentation MCP server for its developer documentation. [Docs MCP guide](https://developers.openai.com/learn/docs-mcp)

### GitHub

Useful for:

- Reading issues and pull requests
- Reviewing diffs
- Investigating failed CI
- Connecting requirements to code changes
- Preparing release notes

Start with read-only permissions.

### Linear or Jira

Useful for:

- Reading assigned work
- Extracting acceptance criteria
- Finding blocked dependencies
- Drafting progress updates
- Connecting tickets to pull requests

### Slack, Notion, or Google Drive

Useful when technical decisions and requirements are spread across workplace documents and conversations.

Example:

```text
Find the agreed payment retry policy, compare it with the current
implementation, and identify inconsistencies.
```

### Database

Start with read-only development or staging access.

Use it for:

- Schema inspection
- Query analysis
- Data-shape investigation
- Migration review
- ORM and constraint comparison

Do not begin with unrestricted production write access.

## MCP Security Checklist

Before connecting a server, check:

1. Who operates it?
2. What data can it read?
3. What actions can it perform?
4. Does it have production access?
5. Can permissions be restricted?
6. Are tool calls logged?
7. Can destructive actions require approval?

Treat an MCP server like installed software with access to professional systems.

## When to Create a Skill

Create a skill when a workflow is repeated and has recognizable steps.

Useful developer skills:

- Backend PR review
- Express endpoint implementation
- Production incident investigation
- Database migration review
- Accessibility review
- Release readiness check
- API documentation update

A skill should define:

```text
When it should activate
Required inputs
Procedure
Decision points
Safety checks
Expected output
Verification
```

## Example Skill Outline

```md
---
name: backend-pr-review
description: Review backend pull requests for correctness and risk.
---

# Backend PR Review

1. Read the issue and acceptance criteria.
2. Inspect the diff and affected call paths.
3. Check validation, authentication, and authorization.
4. Review data changes and transaction boundaries.
5. Check errors, retries, and idempotency.
6. Run relevant tests when possible.
7. Report only actionable findings by severity.
```

OpenAI recommends keeping skills focused on a recognizable user goal. [Building Skills](https://developers.openai.com/plugins/build/skills)

## When to Use a Plugin

Use a plugin when you want to distribute a complete capability containing skills, MCP configuration, and related resources.

For personal use, begin with `AGENTS.md`, one MCP connection, and one skill. Build a plugin after those pieces are proven useful.

## When to Create an Automation

Good automation candidates are:

- Repeated regularly
- Safe to execute unattended or with approvals
- Based on stable inputs
- Easy to verify
- Valuable even when no change is required

Examples:

```text
Daily CI failure summary
Weekly dependency-risk review
Release-readiness checklist
Stale pull-request report
Recurring documentation freshness check
```

Avoid automating an unclear workflow. First perform it manually with the agent several times and improve the instructions.

## When to Use Multiple Agents

Use multiple agents when work can be separated cleanly:

```text
Frontend review
Backend review
Test coverage review
Security review
```

One primary agent should combine the findings and resolve contradictions.

Avoid parallel edits to the same code area unless ownership boundaries are explicit.

## Recommended Adoption Order

```text
Clear prompts
    ↓
AGENTS.md
    ↓
One read-only MCP connection
    ↓
One reusable skill
    ↓
One recurring automation
    ↓
Multi-agent workflows for genuinely parallel work
```
