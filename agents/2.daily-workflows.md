# Daily Development Workflows

## 1. Understand an Existing Codebase

```text
Explain how an authenticated request flows from the Express route
to the database.

Show:
- Important files
- Middleware order
- Validation
- Authorization
- Database access
- Error handling

Do not modify anything.
```

Use this before making changes in unfamiliar code.

## 2. Start a Feature

```text
Inspect this repository and identify the files involved in adding
password-reset functionality.

Before editing:
1. Explain the current authentication flow.
2. Propose the smallest implementation plan.
3. Identify security risks and required tests.

Then implement the feature and run the relevant tests.
```

For large features, ask for a plan first. For small and obvious changes, let the agent inspect, implement, and verify in one workflow.

## 3. Fix a Bug

```text
Reproduce this bug before changing code.

Find the root cause, add a failing regression test, implement the
smallest safe fix, and run the relevant test suite.

Do not make unrelated refactors.
```

A good bug workflow is:

```text
Reproduce → Explain cause → Add failing test → Fix → Verify
```

## 4. Write API Tests

```text
Inspect POST /orders and the existing test conventions.

Add tests for:
- Successful creation
- Invalid input
- Missing authentication
- Insufficient inventory
- Duplicate idempotency key
- Database or dependency failure

Run only the relevant test suite first.
```

## 5. Review Your Changes

```text
Review my current diff as a senior backend engineer.

Look for:
- Incorrect behavior
- Security problems
- Missing validation
- Race conditions
- Database issues
- Missing tests

Report only actionable findings with file and line references.
```

Use a separate review prompt after implementation. A fresh review often catches assumptions made during coding.

## 6. Diagnose CI Failures

```text
Inspect the failing CI output and reproduce the failure locally.

Classify it as:
- Code defect
- Flaky test
- Environment problem
- Dependency problem

Do not change code until you can explain the likely root cause.
```

## 7. Refactor Safely

```text
Refactor this module without changing observable behavior.

Before editing:
- Identify its public API.
- Identify existing test coverage.
- List behavior that must remain unchanged.

After editing:
- Run relevant tests.
- Compare the public API.
- Summarize every behavioral risk.
```

## 8. Database Work

Useful agent tasks include:

- Explaining schemas and relationships
- Finding missing indexes
- Reviewing query plans
- Drafting migrations
- Comparing ORM models with constraints
- Generating rollback considerations

Require human review before executing destructive migrations or production writes.

## 9. Documentation

```text
Read the implementation and update the API documentation.

Include:
- Request schema
- Successful response
- Error responses
- Authentication requirements
- One realistic example

Do not document behavior that the code does not implement.
```

## 10. Learning

Use the repository itself as a teacher:

```text
Teach me how this caching layer works.

Start with the high-level request flow, then explain one important
file at a time. Ask me a short question after each section before
moving to the next concept.
```

## Daily Routine

### Beginning of the Day

- Ask the agent to summarize your assigned issue.
- Identify affected systems and unknowns.
- Create a short implementation and verification plan.

### During Development

- Let the agent search and explain unfamiliar code.
- Ask it to handle mechanical changes.
- Keep architectural decisions and acceptance criteria explicit.

### Before Committing

- Run focused tests.
- Review the diff.
- Check for secrets, debug output, and unrelated changes.
- Ask for an independent risk review.

### Before Opening a Pull Request

- Summarize the change.
- List testing evidence.
- Note risks and rollout requirements.
- Generate a clear PR description from the actual diff.
