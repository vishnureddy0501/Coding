# Prompting and Repository Setup

## A Reliable Prompt Structure

Use five sections:

```text
Outcome
Scope
Constraints
Acceptance criteria
Verification
```

Example:

```text
Outcome:
Fix POST /users returning 500 for duplicate emails.

Scope:
- Inspect the Express route, validation, service, and repository.
- Keep the existing response format.

Constraints:
- Do not modify unrelated files.
- Preserve existing successful behavior.

Acceptance criteria:
- Duplicate email returns 409.
- Valid creation returns 201.
- Unexpected errors return 500 without leaking details.

Verification:
- Add a regression test.
- Run the relevant API tests.
```

## Do Not Over-Specify the Implementation

Describe the expected outcome and important boundaries. Let the agent inspect the code before deciding implementation details.

Overly specific instructions can force an incorrect solution when the repository uses a different architecture.

## Separate Read-Only and Editing Tasks

Use clear verbs:

```text
Explain / review / diagnose → inspect without modifying
Implement / fix / refactor → modify and verify
```

Example:

```text
Diagnose why this endpoint is slow. Do not implement a fix yet.
```

## Supply Evidence

Useful inputs include:

- Error messages
- Failing commands
- Request and response examples
- Relevant issue links
- Acceptance criteria
- Screenshots
- Expected behavior

Do not make the agent rediscover information you already possess.

## Ask for Verification

Include verification in the original prompt:

```text
Run the smallest relevant test suite first. If it passes, run linting
and any broader tests affected by the change.
```

For UI work:

```text
Verify loading, empty, error, mobile, and desktop states.
```

## Recommended `AGENTS.md` Structure

```md
# Repository Guide

## Architecture

Explain the major components and ownership boundaries.

## Commands

- Install dependencies:
- Run development server:
- Run unit tests:
- Run integration tests:
- Run linting:
- Run type checking:

## Code Conventions

- Language and module style
- Naming conventions
- Error-handling approach
- Validation approach
- Test conventions

## Safety

- Files that must not be modified
- Destructive commands that require approval
- Rules for migrations and generated files

## Definition of Done

- Required tests
- Required documentation
- Expected final report
```

Keep repository instructions concise. Store detailed workflows in skills instead of putting every possible procedure in `AGENTS.md`.

## Common Prompting Mistakes

### Vague Goal

```text
Make this better.
```

State what “better” means: faster, simpler, safer, accessible, or easier to maintain.

### Missing Scope

Without boundaries, the agent may refactor unrelated code. Mention the relevant feature, folder, or API.

### No Verification

Generated code is not finished work. Require tests, linting, type checking, or visual inspection.

### Too Many Tasks at Once

Split unrelated work into separate tasks. Keep related implementation and verification together.

### Blind Acceptance

Inspect the diff and testing evidence before committing or deploying.
