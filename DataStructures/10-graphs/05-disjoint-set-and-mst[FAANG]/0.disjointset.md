## What is DSU?

Disjoint Set Union answers one main question:

> Are these two elements in the same group?

It is also called **Union-Find** because it has two important operations:

- `find(x)`: find the representative or root of `x`'s group;
- `unite(a, b)`: merge the groups containing `a` and `b`.

## Simple example

Initially, five people are in separate groups:

```text
{1} {2} {3} {4} {5}
```

After:

```text
unite(1, 2)
```

the groups become:

```text
{1, 2} {3} {4} {5}
```

After:

```text
unite(2, 3)
```

they become:

```text
{1, 2, 3} {4} {5}
```

Now:

```cpp
find(1) == find(3)  // true: same group
find(1) == find(5)  // false: different groups
```

The root is simply the representative of a group. Two nodes are connected when they have the same root.

## How do we store the groups?

Use a parent array:

```cpp
parent[i]
```

It tells us the current parent of node `i`.

Initially, every node is its own parent:

```cpp
parent[1] = 1;
parent[2] = 2;
parent[3] = 3;
```

```text
1    2    3
↑    ↑    ↑
self self self
```

Therefore, every node initially represents a separate group.

## Basic `find`

```cpp
int find(int node) {
    if (parent[node] == node)
        return node;

    return find(parent[node]);
}
```

Read it as:

1. If I am my own parent, I am the root.
2. Otherwise, ask my parent for the root.

For this tree:

```text
1
|
2
|
3
```

`find(3)` follows:

```text
3 → 2 → 1
```

and returns `1`.

## Basic union

Always join roots, not the original nodes:

```cpp
void unite(int a, int b) {
    int rootA = find(a);
    int rootB = find(b);

    if (rootA != rootB)
        parent[rootB] = rootA;
}
```

Steps:

1. Find the root of `a`.
2. Find the root of `b`.
3. If the roots differ, connect one root to the other.

If the roots are already equal, both nodes already belong to the same group.

## Optimization 1: path compression

Consider a tall tree:

```text
1
|
2
|
3
|
4
|
5
```

The first `find(5)` follows:

```text
5 → 4 → 3 → 2 → 1
```

Path compression makes every visited node point directly to the root:

```text
    1
 / / \ \
2 3  4  5
```

Only one assignment is added:

```cpp
int find(int node) {
    if (parent[node] == node)
        return node;

    return parent[node] = find(parent[node]);
}
```

The important line is:

```cpp
parent[node] = find(parent[node]);
```

It means:

> Find my root and make that root my direct parent.

Future `find` operations become much faster.

## Optimization 2: union by size

Randomly joining roots can create tall trees. Union by size attaches the smaller group under the larger group.

Maintain:

```cpp
size[root]
```

Initially every group contains one node:

```cpp
size[i] = 1;
```

During union:

```cpp
if (size[rootA] < size[rootB])
    swap(rootA, rootB);

parent[rootB] = rootA;
size[rootA] += size[rootB];
```

After the swap, `rootA` represents the larger group. Therefore the smaller root, `rootB`, is attached below it.

## Interview-ready implementation

For interviews, union by size is usually the easiest version to remember and explain:

```cpp
#include <bits/stdc++.h>
using namespace std;

class DSU {
    vector<int> parent;
    vector<int> size;

public:
    DSU(int n) {
        parent.resize(n);
        size.resize(n, 1);

        for (int i = 0; i < n; i++) {
            parent[i] = i;
        }
    }

    int find(int node) {
        if (parent[node] == node)
            return node;

        return parent[node] = find(parent[node]);
    }

    bool unite(int a, int b) {
        int rootA = find(a);
        int rootB = find(b);

        if (rootA == rootB)
            return false;

        if (size[rootA] < size[rootB])
            swap(rootA, rootB);

        parent[rootB] = rootA;
        size[rootA] += size[rootB];
        return true;
    }

    bool connected(int a, int b) {
        return find(a) == find(b);
    }

    int componentSize(int node) {
        return size[find(node)];
    }
};
```

Returning `false` from `unite` means the nodes were already connected. This is useful for detecting an extra edge or a cycle.

## Union by rank

Rank represents the approximate height of a tree.

Initially:

```cpp
rank[i] = 0;
```

When joining two roots:

- smaller rank goes below larger rank;
- if ranks are equal, attach either root below the other and increase the new root's rank by one.

```cpp
void uniteByRank(int a, int b) {
    int rootA = find(a);
    int rootB = find(b);

    if (rootA == rootB)
        return;

    if (rank[rootA] < rank[rootB]) {
        parent[rootA] = rootB;
    }
    else if (rank[rootA] > rank[rootB]) {
        parent[rootB] = rootA;
    }
    else {
        parent[rootB] = rootA;
        rank[rootA]++;
    }
}
```

### Why increase rank only when ranks are equal?

Suppose a tree of rank `1` absorbs a single node of rank `0`:

```text
    1              1
   / \     +      /|\
  2   3    4     2 3 4
```

The tree's height does not increase, so its rank remains `1`.

If two trees of the same rank are joined, one complete tree goes below the other. The resulting height can increase by one, so the new root's rank is incremented.

## Rank versus size

Both optimizations keep trees shallow and have the same practical time complexity.

| Union by size | Union by rank |
|---|---|
| Tracks number of nodes | Tracks approximate tree height |
| Easier to visualize | Common in textbook explanations |
| Directly gives component size | Rank is not component size |

For interviews, learn both ideas but memorize one implementation. Union by size is often simpler.

Do not combine the decision rules in one union operation. Choose either size or rank.

## Time complexity

With both path compression and union by size/rank:

```text
find:  O(α(n)) amortized
union: O(α(n)) amortized
```

`α(n)` is the inverse Ackermann function. It grows so slowly that DSU operations are treated as almost constant time in practice.

Space complexity is:

```text
O(n)
```

for the parent and size/rank arrays.

## When should you think of DSU?

Think of DSU when:

> There are initially separate groups, operations keep merging them, and we repeatedly need to know whether two elements belong to the same group.

Common patterns:

- connected components;
- cycle detection in an undirected graph;
- redundant/extra edge;
- dynamic connectivity as edges are added;
- merging accounts or similar groups;
- Kruskal's minimum spanning tree;
- determining the size or number of components.

For a static graph where you only need to traverse components once, ordinary DFS or BFS may be simpler. DSU is especially useful when connections are processed one by one.

## Common interview observations

### Are two nodes connected?

```cpp
find(a) == find(b)
```

### Does an edge create a cycle?

Before adding edge `(a, b)`:

```cpp
if (find(a) == find(b)) {
    // a and b are already connected;
    // this edge creates a cycle
}
```

### How many components remain?

Start with:

```cpp
components = n;
```

Decrease the count only when `unite` successfully joins two different roots:

```cpp
if (dsu.unite(a, b))
    components--;
```

## Common mistakes

- Joining `a` and `b` directly instead of joining their roots.
- Forgetting the path-compression assignment in `find`.
- Updating `size` or `rank` on a node that is no longer the root.
- Increasing rank when the two ranks are different.
- Confusing rank with the exact number of nodes.
- Forgetting to check whether both nodes already have the same root.
- Mixing 0-based and 1-based indexing.
- Applying DSU to directed-cycle detection; use directed-graph algorithms there.

## What to remember

```text
DSU = groups + find + union

find(x)       → return x's group representative
unite(a, b)   → merge two groups
same root     → connected
path compression + size/rank → shallow trees
```

Interview definition:

> Disjoint Set Union maintains separate components under repeated merge operations. `find` returns a component's representative, and `union` joins two components. Path compression and union by size or rank keep operations almost constant time.
